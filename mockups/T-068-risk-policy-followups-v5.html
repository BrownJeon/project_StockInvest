v3 대비 바뀐 곳 (5곳)

"현재" = 지금 운영 중인 화면(T-066 배포본) 문구, "제안" = 이번 v5. 아래 미리보기 위의 비교 보기를 "현재"로 바꾸면 같은 화면에서 전후를 볼 수 있다.

v4 → v5 정정 (②만 바뀜): v4 는 분할 행에 "집행 중 한도 4회 (같은 종목 24시간 내 자동 매수 시그널)"라고 썼다. 코드로 다시 보니 이 한도는 국내 룰 엔진의 자동 매수만 막고, 세는 것도 시그널이 아니라 24시간 내 체결·접수된 매수 주문이다. 미국 자동 매수와 시나리오 확정은 거치지 않는다. 그래서 "분할 4회가 모든 경로에서 지켜진다"로 읽히지 않게 실제 집행 범위 두 가지(확정 1회당 조각 상한 · 국내 자동 매수 한도)와 아직 없는 것(여러 번 나눠 확정하는 누적 횟수 제한)을 따로 적었다. 나머지(①③④⑤)는 v4 와 같다.

  1. ① 정책표 — 현금 행 (리스크 정책 화면 · 그 밖의 정책)
    현재현금 하한 · § 문서 정책 · 총자산의 10% · ! 미달 — 3.0%
    제안현금 비중 (정보 표시, 하한 없음) · ✓ 사용자 확정 · 3.0% (경고 없음)
  2. ② 정책표 — 분할 매수 행
    현재최대 3회 · 40 / 30 / 30 (비율은 제안) · 신규 진입 때 적용
    제안최대 4회 · ✓ 사용자 확정 · 비율 표기 없음 · 현재 상태 = 집행 중인 제한 2가지 — ⓘ 확정 1회당 조각 최대 4개(시장 무관) · ⓘ 국내 자동 매수 24시간 내 같은 종목 4건(국내 룰 엔진만) · "여러 번에 나눠 확정하는 누적 횟수는 아직 제한이 없습니다(후속 결정)."
  3. ③ 배지 (리스크 정책 화면 머리 + 안전장치 영역 요약 행)
    현재◌ 표시·위험 계산 전용
    제안◌ 표시·위험 계산·알림 (주문·매도 없음)
  4. ④ 안내 문구 (저장 바 · 저장 완료 · 상단 띠 · 엔진 안내)
    현재저장해도 매도 주문·알림은 만들지 않습니다.
    제안저장해도 매도 주문은 만들지 않습니다. 예상 손절가에 닿으면 텔레그램으로 알림만 보냅니다. 엔진 안내에 "알림은 엔진과 별개라 엔진이 꺼져 있어도 옵니다" 한 줄 추가.
  5. ⑤ 새 영역 — 손절가 도달 알림 안내 + 메시지 미리보기 (손절 합 결과 바로 아래)
    현재없음
    제안알림 규칙 4줄 · 지금 손절가 아래 종목 수로 "처음 켜질 때 요약 몇 건" · 텔레그램 말풍선 예시 2개(도달 알림 · 처음 요약)

정정할 사실: 작업 지시의 "정책과 다른 현재 상태 목록"과 요약 행의 "확인 필요 n건"은 v3 데모와 운영 화면 어디에도 없다(v1·v2 데모에만 있었고 v3 에서 빠졌다). 그래서 지울 목록이나 줄일 건수는 없다. 현금 경고가 나오던 곳은 정책표 한 칸뿐이고, 그 칸의 "! 미달"을 없앤다. 그 결과 정책표의 경고(!)는 합성 예시 기준 2건 → 1건(심볼당 최대 비중 초과만 남음)이 된다.
참고: v3 데모의 분할 행은 "최대 2회 60/40"이지만, 운영 배포본은 사용자 승인 수정으로 "최대 3회 40/30/30"이다. 위 "현재"는 운영 배포본 기준이다.

D3. 알림 켜짐·꺼짐을 화면에 보일까 — 토글은 이번 범위 밖

A. 이번에는 안내만 (켜짐·꺼짐 표시 없음) ✓ 권장(이번 범위)

알림은 설정이 없으면 켜져 있다. 끄는 화면이 없으므로 이번에는 규칙 안내와 미리보기만 둔다. 화면·API 추가가 없다.
한계: 운영 DB 에서 알림을 꺼 두면 화면은 여전히 "보냅니다"라고 말한다(사실과 어긋남).

B. 읽기 전용 상태 줄 "알림: ● 켜짐 / ○ 꺼짐" 추가

안내 제목 옆에 지금 상태를 글자+기호로 보인다. 조회 API 응답에 필드 1개(켜짐 여부)가 늘어난다.
한계: 끄고 켜는 버튼이 없으니 "꺼짐"을 보고도 화면에서 할 일이 없다. 토글을 넣는 후속 task 와 함께 하는 편이 낫다.

D1(구조 A)·D2(평균단가 기준)는 v3 에서 결정됐다. 이번 데모에서 다시 묻지 않는다.

③ 설계 메모

  • 현금 비중은 규칙이 아니라 정보다. 그래서 경고 기호·"미달"·초록 "✓" 모두 쓰지 않고 숫자만 중립 글자로 보인다(✓ 를 쓰면 "기준을 통과했다"로 읽힌다).
  • 분할 비율 표기를 뺐다. 코드를 읽어 보니 시나리오 확정은 화면에서 넣은 구간별 수량(manualSlices)을 그대로 쓰고, 자동 분할 함수 calcSplitSlices 는 가격 구간만 같은 폭으로 나누며 금액은 넘겨받지 않는다(금액 인자 없음). "각 구간에 같은 금액"은 실제 동작이 아니므로 적지 않는다.
  • 집행 중인 제한은 정책 값과 같은 칸에 두되 초록 "● 집행 중" 배지는 쓰지 않는다. 그 배지는 안전장치 카드(실제 주문에 적용) 전용 표식이라, 여기서 쓰면 "리스크 정책이 주문을 막는다"로 오해된다. 대신 ⓘ 글자로 실제 집행 범위를 경로별로 쓴다 — 확정 1회당 조각 상한(시장 무관)과 국내 룰 엔진의 자동 매수 한도. 둘 중 하나라도 4가 아니면 그 줄만 "! 정책과 다름"으로 바꾼다.
  • 없는 제한은 없다고 쓴다. 여러 번에 나눠 확정하는 누적 횟수를 세는 장치는 아직 없다. 규칙처럼 보이지 않게 기호·색 없이 작은 글자 한 줄로 사실만 적는다(후속 결정 D17).
  • 배지 문구가 길어져 412·360px 에서 한 줄에 안 들어간다. 머리·요약 행에서 배지가 다음 줄로 내려가도록 줄바꿈을 허용했다(가로 넘침 0).
  • 알림 안내는 결과 영역(손절 합) 바로 아래에 둔다. "이미 손절가 아래 n종목" 경고와 손절 합을 본 직후에 "그래서 언제 알림이 오나"를 읽게 하는 순서다. 알림에는 주문·매도가 없다는 문장을 안내와 메시지 양쪽에 둔다.
  • 위험·초과·오류는 amber + 기호 + 글자. 빨강·파랑은 이 앱에서 상승·하락 뜻이라 쓰지 않는다(메시지 제목의 🔻 는 텔레그램 본문 그대로 보여 주는 예시).
