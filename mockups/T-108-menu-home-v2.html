D. 결정 필요 — 7건 (초록 테두리가 권고)

메뉴명·아이콘(홈 stone · 거래 handshake · 분석 scan-search · 비서 brain · 설정 settings)과 지표 결정 D1~D14 는 확정이라 다시 묻지 않습니다. 아래 7건은 「권고대로」라고만 답하셔도 됩니다.

① 하단 탭 순서

A. 홈 · 거래 · 분석 · 비서 · 설정권고

인계서 기본안. 비서는 T-113 배포 전에는 칸을 빼고 4칸(홈·거래·분석·설정)으로 두고, 배포 때 4번째에 끼웁니다.

B. 홈 · 분석 · 거래 · 비서 · 설정

「판단을 보고 → 행동」 순서. 관찰 기간에 자주 여는 분석이 엄지 가까이 옵니다.

근거 [가능성 높음]: 홈 「확인 필요」 줄의 대부분(승인 대기·진입 감시·DRY_RUN 청산·주문 오류)이 거래로 이어집니다. B 는 관찰 기간엔 편하지만 실거래 전환 뒤 다시 바꾸면 손에 익은 위치가 깨집니다.

② 홈 섹션 순서 · 지표 배치

A. 띠 → 확인 필요 → 운용현황 → 청산 로직 → 오늘의 분석 → 최근 활동권고

지표는 2×2 칸, 칸 안에 국내·해외 두 줄(시장별 세션일 표기).

B. 띠 → 운용현황 → 오늘의 분석 → 청산 로직 → 확인 필요 → 최근 활동

숫자 먼저. 지표는 시장별 블록(국내 4칸 · 해외 4칸).

근거: 확인할 것이 없으면 A 의 「확인 필요」는 한 줄로 줄어 숫자가 바로 올라옵니다. 이상이 있는 날은 숫자보다 먼저 보여야 합니다(J6 — 수집·가동 이상은 홈 「확인 필요」). B 의 시장별 블록은 412px 에서 운용현황만 두 화면 높이가 됩니다.

③ 분석 탭 3분류

A. 오늘 분석 · 검증·성과 · 데이터 상태권고

11-23 감사 증거 3종(후보·제외 사유 / 사후 성과 / 가동률)과 하나씩 맞습니다. 리서치·주도주·관심 종목 관리는 「오늘 분석」 아래 「종목별」로. 청산 로직 관찰은 「검증·성과」.

B. 종목분석 · 추이·검증 · 성과 (인계서 안)

종목 탐색이 첫 칸. 「성과」는 실거래 전엔 표본 0(executions 0행)이라 빈 칸으로 남습니다.

근거: 홈 「데이터 이상」 줄을 누르면 갈 자리가 필요한데 B 에는 없습니다. A 는 「성과」를 검증과 합쳐 실거래 전에도 빈 탭이 생기지 않습니다.

④ 거래 하위 구조

A. 운용 현황 · 보유·주문 · 운영 기록 (3칸 세그먼트)권고

승인 대기 → 진입 감시 → 보유 → 최근 주문 순, 기록은 「전체 보기」 상세 화면.

근거: B 는 실거래 단계에서 보유가 늘면 승인 대기 아래가 길어져 주문 오류가 밀려납니다. A 의 세그먼트는 딥링크(?tab=) 호환을 그대로 이어받기 쉽습니다.

⑤ 비서 1차 조회 범위 (노출은 T-113 대화 소유권 배포 뒤)

A. 운영 기록만 — 분석 실행·후보·제외 사유·데이터 상태·사후 성과·청산 판정. 계좌 보유는 「종목 수」까지권고

답마다 기준 시각·조회 기간·근거·상세 링크. 없는 데이터는 「모름」.

B. A + 계좌 보유 상세(종목·수량·평단·손익)

「종목 A 지금 얼마 손해야?」에 바로 답합니다.

근거 [확실]: chat_threads 에 소유자 열이 없고(계약 §0-8) 외부 LLM 으로 보낼 범위가 아직 정해지지 않았습니다. 두 안 모두 주문·승인·취소·스위치·설정 변경은 하지 않고 해당 화면으로 안내만 합니다.

⑥ 홈 「청산 로직」 3줄의 위치

A. 운용현황 바로 아래 독립 영역 — 0 이어도 항상 보임권고

B. 「확인 필요」 안에 흡수 — 조건 충족·발화가 있을 때만

홈이 짧아집니다.

근거: 감사 대상이 청산 로직이라 「해당 없음 0종목」 자체가 증거입니다. B 는 조용한 날 청산 엔진이 돌았는지(X1) 홈에서 알 수 없습니다.

⑦ 장중 룰 평가 깔때기의 국내/해외 토글 위치

A. 거래 › 운영 기록 카드 머리의 국내/해외 세그먼트권고

기본 = 마지막 세션이 더 최근인 시장. 세그먼트 글자에 세션일과 이상 건수(「해외 · ET 10-29 · 이상 1」)를 붙여 숨은 시장의 이상도 보입니다.

B. 국내·해외 두 카드를 위아래로 둘 다 펼침 (토글 없음)

숨는 것이 없습니다.

근거: 게이트 9단계 × 2시장은 412px 에서 두 화면 높이입니다. 홈 「오늘의 분석」 표는 장마감 AI 분석이라 토글 없이 두 열을 그대로 둡니다(D1 — 장중 깔때기는 홈에서 뺍니다, E 절 확인 요청 2).

계약과 다르게 해석했거나 계약이 말하지 않아 정한 곳 — Leader 확인 요청

  1. 청산 상세 위치: 계약 §11.2·D14 는 상세를 「분석 › 보유」로 적었으나 보유는 거래로 옮깁니다(인계서 §8). 그래서 판정 관찰(X1·X3·X4·X6)은 분석 › 검증·성과, 종목별 임계 거리(X5)·평가 대상(X2)은 거래 › 보유·주문에 두었습니다.
  2. 장중 룰 깔때기를 홈에서 뺐습니다(D1 = 홈 분석은 장마감 AI 만). 10-28 사용자 결정 ③의 「깔때기 시장 토글」은 거래 › 운영 기록에서 충족합니다.
  3. 「중지(킬스위치)」 띠 라벨: 계약 §10.3-6 은 킬스위치 켜짐을 관찰 단계에 넣습니다. 데모는 관찰 지표(A)를 그대로 쓰고 띠 라벨만 「중지 — 모든 주문 차단」으로 구분했습니다.
  4. 혼합 단계의 손익 기준: D5 는 「실거래 전환일 첫 스냅샷」. 혼합(DRY_RUN 꺼짐·매수 차단)을 전환으로 볼지 계약에 없어 B4 를 「◌ 기준 미설정」으로 두었습니다. 혼합 단계 지표는 B 세트에 매수 관련(B1·B7)만 「차단」.
  5. 하드손절 OFF 조건 충족을 「확인 필요」에도 넣었습니다(계약은 홈 청산 3줄만). 위험 신호라 두 곳에 보입니다 — 중복이 싫으면 확인 필요에서 뺍니다.
  6. 홈 「최근 활동」의 원천(job_run_log · orders · signals 합치기)은 계약에 없습니다 — 첫 배포에서는 orders·signals 만으로 채우고 「분석 완료」 줄은 T-112 뒤.
  7. 하단 탭 글자 10px → 11px: 현재 BottomTabs 는 10px 로 11px 미만 금지 규칙에 걸립니다. 아이콘 22px·선택 탭 위 막대(색 외 모양 단서)를 더했습니다.
  8. 비서 보류 기간: 데모는 목표 구조 비교를 위해 5칸에 「보류」 표지를 그렸지만, 권고(①A)는 배포 전 4칸입니다.

접근성·구현 메모

  • 하단 바 nav + 현재 탭 aria-current="page", 세그먼트는 aria-pressed, 상태는 글자 + 테두리 모양(점선·점·실선)으로 — 색만 쓰지 않습니다. 시트는 role="dialog"·aria-modal, 열면 제목에 포커스, Esc 닫기(처리 중 제외), 닫으면 연 버튼으로 복귀.
  • 아이콘은 지난번에 정한 Lucide 5종의 원본 SVG 경로 그대로입니다(워크스페이스의 lucide-react 1.24.0, ISC 라이선스에서 추출 — 직접 그린 도형 없음). 현재 StockInvest package.json 에는 lucide-react 가 없어 도입 방식(의존성 추가 vs 인라인 SVG)은 구현 가이드에서 정합니다.
  • 색 대비: 파랑·빨강 글자는 --bg·--bg2 위에만(≈4.5:1), 회색 칩 바탕 위의 경고 글자는 밝은 톤(#fca5a5·#86efac)을 씁니다.
  • 경로는 기존 재사용 권고(/·/recommend·/analytics·/ai·/settings) — 새 URL·리다이렉트는 구현 가이드에서. HIDDEN_PATHS(로그인 등 하단 바 숨김)는 그대로.
