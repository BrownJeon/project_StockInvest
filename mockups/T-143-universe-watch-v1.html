종목마다 출처가 보입니다 — 4가지가 섞이기 때문입니다. 「자동 n위」는 시가총액 순위, 「보유 n주」는 그 종목이 목록에서 빠져도 분석된다는 표시입니다. 즐겨찾기·보유는 여기서 바꾸지 않습니다(각자 원래 화면에서).

12월 정기 재구성 — 목록 한 번에 바꾸기

목록에서 빼기

세 가지 행동만 있습니다. 「빼기」·「넣기」·「코드 바꾸기」가 제안을 처리하고, 「보류」는 다음 월간 산출까지 숨기며, 「무시」는 같은 근거로 다시 제안하지 않습니다. 「삭제」라는 말은 쓰지 않습니다 — 데이터를 지우는 게 아니라 분석 목록에서 빼는 것이라서입니다.

색으로 넣기·빼기를 구분하지 않습니다. 이 앱의 빨강·파랑은 상승·하락이라 목록 추가에 빨강을 쓰면 「오른다」로 읽힙니다. 기호(+·−)와 글자(「넣기」·「빼기」)로 구분하고, 강조가 필요한 쪽만 --accent 를 씁니다.

수동 목록을 바꿀까요?

저장 결과 (데모 전용)

안전장치와의 관계: 이 화면은 주문을 보내지 않으므로 실거래여부·모든거래차단과 무관합니다(차단 상태에서도 목록은 바꿀 수 있습니다). 이미 만들어진 시그널과 보유 종목에도 영향이 없습니다 — 목록은 다음 「해외 장마감 분석」부터 쓰입니다. 확인 대화에 이 문장을 그대로 넣었습니다.

결정 필요 6건

Q1·Q3 과, 데모를 만들며 새로 드러난 4건입니다. 초록 테두리가 권고안이고, 전부 권고대로 가도 모순이 없습니다. D1 만 다른 선택을 하면 D2~D4 가 함께 바뀝니다(불편한 사실 1번).

D1 (= Q1) 수동 목록을 어디에 두나

데모 §1 에서 세 칸으로 나란히 봤습니다. Q2·Q4 는 화면과 무관해 이 데모에 없습니다.

A · DB + 설정 화면권고

화면에서 바꾸고 변경 이력이 남는다. 재배포·재시작 없음. 저장 전 형식 검사·대조 화면이 있다.

B · 환경변수 OVERSEAS_UNIVERSE_SYMBOLS

지금 구조 그대로. 화면은 읽기 전용. 바꿀 때마다 .env 편집 + pm2 재시작, 이력 없음.

권고 이유: 알림을 만드는 목적이 「사용자가 눌러서 끝내기」인데, B 는 누를 자리가 없어 알림이 할 일 목록으로 바뀝니다.

D2 (= Q3) 알림 경로

홈 줄은 어느 쪽이든 넣습니다. 실제 선택은 텔레그램을 보낼지입니다.

A · 텔레그램 + 홈 둘 다권고

제안이 새로 생길 때만 1회. 설정 › 알람에 토글 1개.

B · 홈만

알림 비용 0. 홈을 열어야 안다.

권고 이유: 상장폐지는 날짜를 예고하지 않고, 놓치면 매일 KIS 조회가 실패해 「데이터 이상」만 쌓입니다. 빈도가 연 5~10건이라 소음 위험이 낮습니다.

D3 (새로 드러남) 텔레그램에서 바로 처리할 수 있게 할까

기존 주문 승인 메시지에는 [승인]·[거절] 버튼이 있습니다. 같은 모양을 쓸지가 문제입니다.

A · 「앱에서 확인」 링크만권고

텔레그램은 알리기만. 결정은 근거를 볼 수 있는 화면에서.

B · [빼기]·[보류] 버튼도

한 번에 끝난다. 구현은 기존 승인 버튼 구조를 재사용.

권고 이유: 주문 승인은 만료가 있어 즉답이 필요하지만 목록 변경은 급하지 않습니다. 반대로 오조작 비용은 더 깁니다 — 분석 대상이 조용히 틀어지고, 다음 분석 결과를 봐야 알아차립니다.

D4 (새로 드러남) 「보류」는 얼마나 숨기나

A · 다음 월간 산출까지 (약 30일)권고

인수 거래가 끝나거나 공시가 갱신되면 그때 다시 올라온다.

B · 7일

자주 되올라온다. 진행 중인 인수는 7일마다 같은 제안이 반복될 수 있다.

권고 이유: 인수·합병은 몇 달 걸립니다. 7일이면 같은 제안이 10번 넘게 올라와 T-125 와 같은 소음이 됩니다.

D5 (새로 드러남) 변경 확인은 얼마나 자주 도나

WP-A 의 NYSE 상위 50 산출은 월 1회(Q2)입니다. 변경 확인은 별개 작업으로 둘 수 있습니다.

A · 매일 1회 (미국 공시 수집 뒤)권고

이미 받아 둔 공시·뉴스를 읽기만 — 외부 호출 0, 비용 거의 없음. 상장폐지를 하루 안에 안다.

B · 월 1회 (상위 50 산출과 함께)

작업 1개로 끝난다. 상장폐지를 최대 한 달 뒤에 안다.

권고 이유: 거래소 이동·상장 말소는 월간 산출에서만 드러나지만, 인수·상장폐지 공시는 매일 들어옵니다. 늦게 아는 비용이 돌리는 비용보다 큽니다.

작업 이름 후보(사전 reason-dictionary.ts 말투에 맞춤 — 「해외 장마감 분석」·「미국 공시 수집」·「보유 종목 개장 전 공시 확인」과 같은 꼴):
· 월 1회 산출(WP-A) → overseas-universe-refresh = 「해외 분석 대상 갱신」
· 매일 변경 확인(WP-B) → universe-change-watch = 「해외 분석 대상 변경 확인」
B 를 고르면 작업은 「해외 분석 대상 갱신」 하나뿐입니다.

D6 (새로 드러남) 기존 「동적 종목 선별 (Universe)」 행을 같이 손볼까

그 행의 설명이 코인 시절 문구입니다(불편한 사실 5번). 새 행을 바로 위에 붙이면 나란히 보입니다.

A · 문구만 이번에 함께 고친다권고

이 스위치가 실제로 무엇을 켜는지 확인한 뒤 한국어 설명을 바로잡는다. 동작은 건드리지 않는다.

B · 그대로 두고 별도 개선 항목으로

이번 범위를 작게 유지. 모순된 두 설명이 당분간 함께 보인다.

권고 이유: 같은 섹션에 새 행을 넣는 작업이라 추가 비용이 거의 없습니다. 단 그 스위치가 지금 해외 분석에서 무슨 일을 하는지 확인되지 않았습니다 — 확인 결과 동작까지 바꿔야 하면 별 task 로 빼야 합니다[추측].

설계 메모 · 이 데모가 다루지 않은 범위

지키거나 새로 정한 말

  • 기존 말 그대로: 「시그널」 · 「실거래여부」 · 「모든거래차단」 · 「장마감 전 손절」 · 「건수 적음」 · 「AI 매수 판단」 · 「손실한도 손절」 — 이 화면에 나오는 것은 그중 실거래여부·모든거래차단뿐이고, 둘 다 이 화면과 무관하다는 설명으로만 씁니다.
  • 새로 정한 말과 이유:
    · 「해외 분석 대상」 — 코드의 universe. 「유니버스」는 뜻이 안 보이고 기존 「동적 종목 선별 (Universe)」와 겹칩니다.
    · 「수동 — 나스닥100」 / 「자동 — NYSE 상위 50」 — 출처가 4가지라 종목마다 어디서 왔는지 보여야 합니다.
    · 「변경 제안」 — 「알림」은 보낸 것, 「제안」은 아직 처리 안 된 것. 홈 줄·텔레그램·탭 이름을 한 말로 맞췄습니다.
    · 「목록에서 빼기」 / 「넣기」 / 「코드 바꾸기」 — 「삭제」는 데이터를 지우는 것으로 읽힙니다.
    · 「보류」 / 「무시」 — 보류는 다시 올라오고, 무시는 안 올라옵니다.
  • 나사닥 ↔ 나스닥: 지시문에 「나사닥100」이라 적혀 있었지만 task 이력서 본문과 일반 표기가 「나스닥」이라 그쪽으로 썼습니다. 다른 뜻이면 알려 주세요.

모바일 확인

  • 412px(대표)·360px(경계)에서 가로 스크롤·잘림 0건. 유일한 가로 스크롤은 목록 탭의 출처 걸러보기 칩 줄이고, 의도한 것입니다.
  • 누르는 것은 전부 44px 이상(목록·설정 행 56px). 제안 카드 버튼은 360px 에서 「빼기」가 한 줄 전체를 쓰고 「보류/무시」가 반씩 나눠 씁니다.
  • 글자: 본문 13px · 숫자 14~18px · 레이블 11~12px. 11px 미만 없음.
  • 세로 스크롤은 화면당 1곳. 시트는 내용이 길어지면 시트 안에서만 스크롤합니다(max-height:100%).
  • ≥900px 에서 시트가 가운데 모달로 바뀝니다(기존 데모와 같은 @container fr 방식). 1280px 에서는 폭 720px 중앙 고정 — 데스크톱 전용 2열 레이아웃은 만들지 않습니다(연 5~10건 쓰는 화면).
  • env(safe-area-inset-bottom) 을 시트 하단 여백에 반영.

접근성

  • 탭은 role="tablist"/tab/tabpanel + aria-selected, 출처 걸러보기는 aria-pressed, 시트는 role="dialog" aria-modal="true" aria-labelledby.
  • 상태를 색만으로 말하지 않습니다 — 출처 칩은 글자(수동·자동·즐겨찾기·보유)를, 대조 목록은 기호(+·−)와 글자를 함께 씁니다.
  • 저장 결과는 role="status"(성공) / role="alert"(실패)로 읽히게 합니다.
  • 포커스 링은 브라우저 기본 :focus-visible 을 지우지 않습니다. 시트는 열릴 때 첫 버튼으로 포커스를 옮기고, Esc 로 닫히며, 닫으면 원래 버튼으로 포커스를 돌려줍니다 — 이 데모에서 실제로 동작합니다. 배경 가두기(focus trap)는 데모에 없습니다 — 구현 때 시트 밖 요소를 inert 로 두는 것을 가이드에 적습니다.
  • prefers-reduced-motion 에서 뼈대 깜빡임을 끕니다.

일부러 다루지 않은 것

  • WP-A(NYSE 상위 50 자동 산출)에는 화면이 없습니다. 이 데모에 나오는 「자동 50」은 결과를 보여 주기만 합니다. SEC 목록 읽기·tomv 단위 확인·ETP 제외·정렬은 서버 작업이라 데모 대상이 아닙니다.
  • Q2(산출 주기 월 1회 vs 분기)·Q4(상위 50 개수) — 화면에 영향이 없어 이 데모에서 묻지 않습니다. 화면은 숫자를 받아 그릴 뿐입니다(「자동 — NYSE 상위 50」의 50과 「산출 12-01」 날짜만 바뀝니다).
  • WP-C(시간 예산 실측) — 목록을 ~150개로 넓히기 전 관문이고 화면이 없습니다. 이 데모의 「150종목」은 WP-C 통과를 전제한 숫자입니다.
