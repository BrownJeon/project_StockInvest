T-088 데모 v1 — 앱 "주식캐기" 로그인 화면에서 Google 로그인 (Chrome 창 → 앱 복귀)

judge: delta (DM-user-required)대표 폭 412px · 경계 360px1280px 데스크톱: 바뀌는 것 없음매매·안전장치 동작 변경 없음

Google 은 앱 안(WebView) 로그인을 막는다. 그래서 앱에서 [Google로 계속하기]를 누르면 Chrome 창(Custom Tab)이 앱 위에 열리고, 거기서 로그인을 마치면 앱으로 자동으로 돌아와 로그인이 마무리된다. 이 데모는 그 왕복 동안 앱 로그인 화면이 보이는 모습(기본·여는 중·대기·마무리 중·오류)과, T-084 에서 앱 전용으로 바꿨던 oauth_account 문구를 웹과 같은 문구로 되돌리는 변경을 보인다. 웹 로그인 화면은 바뀌지 않는다.

이 데모는 화면 모양만 보인다. 이메일 칸의 you@example.com 은 입력란 안내 글자(placeholder)이고, 로그인 과정의 코드·검증값·토큰은 어느 화면에도 그리지 않는다(구현도 같다).

A. 기본 화면 — 웹(그대로) · 앱 현재 v1.0.0 · 앱 제안 v1.0.1

구조는 지금의 src/app/login/page.tsx + AuthShell + OAuthButtons 그대로다. 앱에서는 Google 버튼과 "또는 이메일로" 구분선이 다시 보이고, GitHub 버튼은 계속 숨긴다(Leader 방침 1). 이메일·비밀번호·회원가입·가입 요청·30일 안내는 웹과 같다. 앱에서만 맨 아래 안내에 한 줄을 더한다(Chrome 창이 열린다는 예고).

웹 브라우저 — 현재 그대로 (변경 없음)

앱 — 현재 v1.0.0 (T-084: 소셜 버튼 없음)

앱 — 제안 v1.0.1 (Google 만)

"초대코드가 없으신가요? 가입 요청" 줄은 지금처럼 서버에 메일 발송 설정이 있을 때만 보인다(웹·앱 같음). 앱 화면의 Google 버튼도 지금처럼 서버가 Google 을 "설정됨"으로 알려 줄 때만 그린다 — 목록을 받기 전에는 아무것도 그리지 않으므로 깜빡임이 없다.

데스크톱(1280px): 로그인은 가운데 카드(최대 380px)라 넓은 화면에서도 같은 모양이다 — 바뀌는 것 없음. 아래 B·C 의 상태는 앱(WebView)에서만 생기므로 데스크톱 웹에는 나타나지 않는다.

B. 앱 Google 로그인 흐름 — 여는 중 · 대기 카드 · 마무리 중 (앱에서만)

새 컴포넌트 AppLoginArea 가 Google 버튼 자리 하나를 차지하고 상태에 따라 바꿔 그린다. 구분선 아래 이메일 폼은 어느 상태에서도 잠그지 않는다(다른 방법으로 로그인할 길을 막지 않는다). 아래 라디오로 상태를 고르거나, 미리보기 안 버튼과 "데모 사건" 버튼으로 흐름을 따라가 볼 수 있다.

C. 오류 상태 — 앱으로 돌아왔는데 로그인이 안 된 경우

오류는 지금처럼 로그인 화면 주소에 고정 코드(?oauth_error=)를 붙여 다시 띄우고, 카드 맨 위 안내 상자(기존 authStyles.note / noteDanger)에 보인다. 다시 시도하는 행동은 바로 아래 [Google로 계속하기] 하나다 — 따로 "다시 시도" 버튼을 만들지 않는다(같은 일을 하는 버튼 두 개). 앱에서는 오류 상자에 포커스를 둔다(이메일 칸에 두면 키보드가 올라와 안내를 가린다).

D. 이메일 로그인에서 "소셜로 가입된 계정"(oauth_account) 문구 — T-084 앱 문구를 웹 문구로 되돌림

T-084 는 앱에 Google 버튼이 없어서 서버 문구("아래 Google로 계속하기를 눌러…")가 막다른 말이 되자 앱 전용 문구로 바꿨다(appOauthAccountText). 이제 앱에도 그 버튼이 있으므로 앱 분기를 없애고 웹과 같은 서버 문구를 그대로 보인다. 포커스·오류 줄 동작은 지금 그대로다(오류 줄은 role="alert" 로 읽히고, 문구가 가리키는 Google 버튼은 같은 카드 위쪽에 이미 보인다).

앱 — 현재 v1.0.0 (T-084 앱 문구)

앱 — 제안 v1.0.1 (웹과 같은 문구)

GitHub 로 가입한 계정이 앱에서 이메일 로그인을 시도하면 서버 문구는 "GitHub로 가입된 계정입니다. 아래 GitHub로 계속하기를…"인데 앱에는 GitHub 버튼이 없다 — 이 경우만 T-084 앱 문구를 GitHub 에 한해 남긴다(지금 사용자 계정은 Google 이라 해당 없음, 구현 가이드 참조).

결정 필요

D1. 대기 카드에 [취소] 버튼을 둘까

A. 둔다✓ 권장

누르면 검증값을 지우고 대기를 풀고 Chrome 창 닫기를 시도한 뒤 "Google 로그인을 취소했습니다." 한 줄. Chrome 창이 앱 위 탭(Custom Tab)이 아니라 별도 브라우저 앱으로 열리는 기기에서는 "창이 닫혔다"는 신호가 오지 않아 대기 카드에 남을 수 있다(추측 — 실기기에서 확인 필요). 그때 빠져나갈 길이 된다.

B. 두지 않는다 (TheKaiwa)

창을 닫으면 자동으로 풀리고, 이메일 폼은 계속 쓸 수 있어 갇히지는 않는다. 카드가 단순하다. 위 경우에는 10분 만료(D3 A)까지 대기 카드가 남는다.

D2. Chrome 창을 그냥 닫고 앱으로 돌아왔을 때

A. 1.5초 기다린 뒤 대기를 풀고 한 줄 안내✓ 권장

"로그인 창이 닫혔습니다. 다시 눌러 주세요." + 기본 버튼. 로그인을 끝낸 직후에도 창이 닫히므로 1.5초 안에 결과가 오면 무시한다. TheKaiwa 에서 실기기로 써 온 방식이다.

B. 대기 카드를 그대로 둔다

[다시 열기]·[취소] 중 고르게 한다. 사용자가 이미 그만두려고 닫은 경우에도 "로그인하는 중입니다"가 남아 상태를 잘못 말한다.

D3. 오래 걸릴 때(10분)

A. 카드에 10분 안내를 미리 적고, 10분이 지나면 대기를 자동으로 푼다✓ 권장

서버 로그인 요청과 검증값이 둘 다 10분이라 그 뒤의 [다시 열기]는 반드시 실패한다. 한 줄 "로그인 요청 시간(10분)이 지났습니다. 다시 눌러 주세요."

B. 시간 제한 없음 (TheKaiwa)

2단계 인증 등으로 오래 걸려도 카드가 남는다. 10분 뒤 Chrome 창에서 끝내면 "로그인 요청이 만료되었거나…"(invalid_state)로 돌아온다 — 결국 다시 눌러야 한다.

D4. 가입되지 않은 Google 계정(signup_requires_web) 안내

B. 문구 + [Chrome에서 가입 화면 열기]✓ 권장

앱 안에서는 가입할 수 없으니 Chrome 창으로 /signup 을 연다(앱 업데이트 받기와 같은 "외부 열기" 경로). 문구만 두면 이번 작업이 없애려는 "앱에서 할 수 있는 게 없는 막다른 안내"가 다시 생긴다.

A. 문구만

범위가 가장 작다. 사용자가 브라우저를 직접 열어 주소를 입력해야 한다. 초대제라 이 경우를 만날 사람은 적다.

D5. 앱이 도중에 다시 시작되어 검증값을 잃은 경우

A. 따로 안내한다✓ 권장

앱이 서버에 묻기 전에 스스로 아는 사실이라 구분해서 말해도 서버 쪽 정보가 새지 않는다. "앱이 다시 시작됐거나 시간이 오래 지나…" — 사용자가 같은 일을 반복하지 않게 원인을 짐작하게 한다.

B. ① 마무리 실패와 같은 문구 (TheKaiwa)

문구가 하나 줄어든다. 사용자는 왜 실패했는지 알 수 없다.

D6. 새 문구의 말투

A. 합니다체✓ 권장

이 화면의 기존 문구("계속하려면 로그인하세요", "세션은 30일간 유지됩니다")와 서버 문구가 모두 합니다체다. 한 카드 안에서 말투가 섞이지 않는다.

B. 해요체 (TheKaiwa·Leader 지시문 예시)

"Chrome 창에서 로그인하고 있어요"처럼 부드럽다. 기존 문구까지 바꾸지 않으면 한 화면에 두 말투가 섞인다.

설계 메모

  • 값을 그리지 않는다: 코드·검증값·세션은 화면·콘솔·주소 표시 어디에도 나오지 않는다. 오류 코드(app_code_invalid 등)는 고정 문자열이라 주소에 붙어도 된다.
  • 거짓 안심 금지: "안전하게 로그인됩니다" 같은 말을 쓰지 않는다. 대기 카드는 무슨 일이 일어나는지와 다음 행동만 말한다.
  • 로그인 전 화면이라 DRY_RUN·KILL 표시와 업데이트 띠는 이번 범위 밖이다(로그인 전에는 띠가 안 보임 — T-084 그대로).
  • 색만으로 구분하지 않기: 대기 = 회전 표시 + 제목 문장, 닫힘·만료·취소 = "!"/"i" 기호 + 문장, 오류 = 상자 + 굵은 첫 문장. 빨강 막대는 기존대로 email_unverified 하나뿐.
  • 터치: Google·다시 열기 48px, 취소·가입 화면 열기 44px. 360px: 카드 안 문장은 줄바꿈(word-break: keep-all), 가로 스크롤 0.
  • 앱 판별은 표시 전용: isNativeApp() 은 버튼·대기 카드 표시에만 쓴다. 서버는 서명된 state 안의 platform=app 으로만 분기한다(설계 ③). 웹에서는 이 절의 요소가 DOM 에 0개.
  • 움직임 줄이기: prefers-reduced-motion 이면 회전 표시를 멈춘다(문장이 상태를 말하므로 정보는 그대로).
