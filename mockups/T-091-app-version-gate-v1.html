B. 옛 앱 로그인 화면 — 현재 vs 제안 (권고 A · 대안 B)

현재는 옛 앱에도 Google 버튼이 보이지만 눌러도 아무 반응이 없습니다(옛 앱은 Chrome 창에서 앱으로 돌아오는 연결을 받지 못함 — T-088 사용자 확인). 제안은 그 자리에서 이유와 해결 방법을 함께 보입니다. 아래 토글로 권고 A 와 대안 B 를 바꿔 보세요.

제안 화면에 보일 안

현재 — 옛 앱 v1.0.0 (문제)

제안 — 권고 A

A 를 권하는 이유
  1. 막힌 기능이 있던 바로 그 자리에서 이유와 해결(새 버전 받기)을 함께 보여, "눌러도 무반응" 혼란을 거기서 끝냅니다.
  2. B 의 비활성 버튼은 여전히 "안 눌리는 버튼"이고, 포커스·읽기 장치에서 빠져 이유가 전달되지 않습니다(대비도 3:1 안팎으로 떨어짐).
  3. 바뀌는 곳이 Google 버튼 자리 한 곳뿐이라 제목·이메일 폼 위치가 그대로이고, B 처럼 화면 위·버튼 두 곳에 같은 말을 나눠 두지 않습니다.

C. [새 버전 받기]를 누른 뒤 — 흐름 한 바퀴

새 화면은 만들지 않습니다. 버튼은 업데이트 띠의 [받기]와 같은 방식으로 Chrome 창(Custom Tab)에서 /app/download/latest.apk 를 엽니다(같은 출처 공개 경로). 2·3단계는 안드로이드·Chrome 시스템 화면이라 우리가 그리지 않습니다 — 그래서 안내 상자의 "업데이트 설치 방법"이 그 단계를 미리 알려 줍니다(기존 설정 › 앱 섹션 문구 재사용).

단계

  1. 로그인 화면 — [새 버전 받기]를 누릅니다. 안내 상자의 "업데이트 설치 방법"이 저절로 펼쳐집니다.
  2. Chrome 창 (시스템) — "유해할 수 있는 파일입니다" 확인에서 [다운로드]. 플레이스토어 밖에서 받는 앱이라 매번 뜨는 확인입니다(설정 › 앱 문구와 같음).
  3. 설치 화면 (시스템) — 받은 파일을 열면 [업데이트]. 같은 서명 키라 지금 앱 위에 덮어 설치됩니다. 이 기기는 1.0.0 을 Chrome 으로 설치했으므로 "출처를 알 수 없는 앱" 허용은 대개 이미 되어 있습니다 [가능성 높음].
  4. 앱을 다시 열면 — build 2 로 읽혀 안내 상자 대신 Google 버튼이 보입니다(② 와 같은 화면).

Chrome 창을 그냥 닫고 돌아오면 1단계 화면(설치 방법 펼친 채)으로 돌아옵니다 — 별도 상태 없음. 다운로드 진행률은 앱이 알 수 없어 표시하지 않습니다(Chrome·알림이 보여 줌).

Chrome 창을 열지 못하면(Browser 플러그인 없음 등) 업데이트 띠와 같은 폴백: 같은 화면에서 일반 이동 → 앱(MainActivity)의 다운로드 처리. 새 오류 문구는 만들지 않습니다.

D1. 안내의 위치·강도

A. Google 버튼 자리를 안내 상자로 대체 ✓ 권장

제목 + 이유 한두 문장 + [새 버전 받기] + 설치 방법(접힘) + "이메일 로그인은 이 버전에서도 그대로". 이메일 폼은 아래 그대로.
한계: 안내 상자가 Google 버튼(48px)보다 높아(설치 방법 접힌 상태 412px 에서 약 283px, 360px 에서 약 303px) 이메일 폼이 그만큼 아래로 내려갑니다 — 데모 틀(높이 760px) 기준 412px 에서 [로그인] 버튼 아래끝이 약 724px 로 첫 화면 안, 360px 에서는 약간 스크롤(실기기 높이는 확인 전).

B. 화면 위 경고 띠 + Google 버튼 비활성

업데이트 띠(필수 업데이트 모양)를 로그인 화면 맨 위에 두고, Google 버튼은 회색으로 잠급니다.
한계: 안 눌리는 버튼이 남아 이유가 버튼에서 떨어져 있고, 비활성 요소는 포커스·읽기 장치에서 빠집니다. 띠는 지금 로그인 전 화면에 쓰지 않는 요소라 새 경우가 하나 늘어납니다.

D2. 옛 앱에서 첫 포커스

A. 옛 앱이면 이메일 칸 자동 포커스 안 함 ✓ 권장

키보드가 올라오지 않아 안내 상자가 온전히 보입니다. 이메일 로그인을 하려면 칸을 한 번 누르면 됩니다. 웹·새 앱·버전 모름은 지금처럼 이메일 칸 포커스.
한계: 앱에서는 버전을 읽은 뒤(수 ms) 포커스를 정하므로 지금보다 아주 조금 늦게 포커스가 갑니다.
