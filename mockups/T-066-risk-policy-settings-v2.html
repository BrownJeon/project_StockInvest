사용자 지시 ① "손절가입력은 해당 작업에서 함께 작업하며 설정은 설정화면에서 안전장치 항목에 추가해줘" ② "손절가는 안전장치가 아닌 추가되는 리스크정책에서 변경하게 해주고 그에 따른 변경도 실시간으로 반영되도록해줘". 그래서 안전장치 영역에 '리스크 정책' 항목을 추가하고, 손절가 편집은 그 리스크 정책 안에서만 한다. 기존 안전장치 컨트롤과 저장 바는 그대로 두고 손절가와 섞지 않는다. 손절가는 사용량 계산에만 쓰고 자동 매도·알림과 연결하지 않는다.

숫자는 전부 합성 예시값이다(총자산 20,000,000원 · 종목 AAA~EEE · 수량·가격·환율 1,250원/USD · 시각). 실제 계좌 값이 아니다. 정책 값(2%·10종목·미국 → 국내·0.25%·15%·10%·-3%·-5%·-15%·분할 2회)만 실제 정책이다.

③ 결정 필요

D1. 구조 — 리스크 정책을 안전장치 영역에 어떻게 넣을까

A. 안전장치 영역에 '리스크 정책' 행 + 별도 화면에서 편집 ✓ 권장

설정 화면에는 요약(2% 한도·사용량·손절가 n/5·확인 필요)만 실시간으로 보이고, 손절가 입력은 눌러 들어간 리스크 정책 화면에서만 한다.
· 한 화면에 저장 바가 하나뿐이다(설정 = 기존 저장 바, 리스크 정책 = 자체 저장 바). 킬스위치·주문 한도 옆에서 손절가를 고치다 잘못 저장할 일이 없다.
· 설정 페이지 길이와 킬스위치 위치가 거의 그대로다(요약 행 약 150px).
단점: 입력하려면 한 번 더 누른다.

B. 안전장치 안 접힌 카드에서 바로 편집

누를 필요 없이 설정 화면에서 바로 입력한다.
단점: 한 페이지에 저장 바가 둘이 된다(맨 위 일괄 저장 + 카드 안 손절가 저장). 무엇이 저장되는지 헷갈리고, 펼치면 412px 에서 약 1,600px 가 늘어나 아래 섹션이 멀어진다. 사용자가 말한 "안전장치가 아닌 리스크 정책에서 변경"과의 경계도 A 보다 흐리다.

④ 설계 메모

  • 집행 중 vs 표시·위험 계산 전용: 기존 안전장치 카드 맨 위에 초록 실선 띠 "● 집행 중", 리스크 정책은 회색 점선 테두리 + "◌ 표시·위험 계산 전용". 모양과 글자로도 구분된다.
  • 손절폭은 현재가 기준(평균단가 기준 아님). 위험 금액 = (현재가 − 손절가) × 수량, 미국 종목은 환율로 원화 환산.
  • 검증: 비어 있음 = 미설정 · 숫자 아님/0 이하 = 오류 · 현재가 이상 = 오류(저장 불가) · -50% 보다 멀리 = 경고 · 스냅샷 오래됨 = 경고. 저장한 뒤 현재가가 손절가 아래로 내려가면 "손절가 하회"(오류 아님, 사용량에서는 계산 불가로 셈).
  • 실시간: 손절가 입력 즉시 클라이언트에서 계산(저장 전 값 표시) → 저장 시 낙관적 반영 → 서버 확정값으로 보정 / 실패면 되돌리고 입력값 유지 / 409 면 서버 최신값을 받고 다시 확인.
  • 현재가 기준(사용자 확정): 포트폴리오 스냅샷(약 1시간마다). 기준 시각을 항상 보인다. 화면을 열 때 1회 + 60초마다 재조회하며, 재조회는 DB 의 최신 스냅샷만 읽고 증권사 시세 API 를 부르지 않는다. 기준 시각이 바뀌면 값을 갱신하고 "갱신됨"을 표시한다. 3시간 넘은 스냅샷은 "오래됨" 경고.
  • 자동 매도 아님을 세 곳에서 말한다: 상단 띠, 입력 목록 위, 저장 바 아래 줄.
