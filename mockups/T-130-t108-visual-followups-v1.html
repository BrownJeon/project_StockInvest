3. 홈 「확인 필요」 머리 숫자 — 무엇을 세는지 한 가지로

지금 머리 숫자(「4건」)는 화면에 그린 줄 수입니다. 데이터 이상은 3줄까지만 그리고 마지막 줄을 「외 4건」으로 바꾸므로, 머리 「4건」 · 「외 4건」 · 아래 운용현황 「데이터 이상·분석 실패 6건」이 같은 날 함께 보입니다. 단위가 모두 「건」인데 세는 것이 다릅니다. 아래에서 상황을 바꿔 보세요.

D3. 「확인 필요」 머리 숫자는 무엇을 셀까

A. 항목 수 합계 — 「확인 필요 7건」

줄마다의 건수를 더함(승인 대기 3건 = 3). 데이터 이상은 지금처럼 3줄 + 「데이터 이상 외 n건」.

B. 묶음 수 — 「확인 필요 · 2가지」 + 데이터 이상을 한 줄로권고

데이터 이상·분석 실패는 한 줄「데이터 이상·분석 실패 6건」(부제에 앞 2개 이름 + 「외 4건」) — 운용현황 칸과 같은 이름·같은 숫자. 머리 단위는 「건」 대신 「가지」.

C. 머리 숫자 없음

머리는 「확인 필요」만, 줄마다 자기 숫자. 데이터 이상은 A 처럼 3줄.

근거: A 는 승인 대기(시그널)·주문 거부(주문)·데이터 원천을 한 숫자로 더해 뜻이 없고, 승인 대기가 늘면 다른 줄이 없어도 숫자가 커집니다. C 는 홈 맨 위에서 「몇 가지를 봐야 하나」를 한눈에 볼 수 없습니다. B 는 머리 단위(가지)와 줄 안의 단위(건)가 달라 섞이지 않고, 같은 날 「6건」이 두 곳에서 같은 숫자로 보입니다. 데이터 이상의 개별 이름은 줄을 누르면 가는 분석 › 데이터 상태에 모두 있습니다.

4. 영문 사유 코드 → 한국어 문구 (승인 용어 §12 만 사용)

5. 「차단」 표기 규칙 3개 (+ 차단이 아닌 것 2개)

「차단」 한 낱말이 스위치·시그널·주문 세 곳에 쓰여 무엇이 막혔는지 문장마다 달랐습니다. 규칙은 「차단」 옆에 항상 누가 막았는지를 붙인다입니다.

규칙 1 · 스위치

이름은 「모든거래차단」 한 낱말(띄어 쓰지 않음) + ON/OFF. 「차단」만으로 스위치를 부르지 않습니다. 이 스위치에 막힌 것은 사유를 「모든거래차단 ON」으로.모든거래차단 ON — 모든 주문 차단 · 주문 차단 · 모든거래차단 ON

규칙 2 · 시그널

시그널 차단에는 막은 관문을 붙입니다 — 지금 화면에 나오는 시그널 차단은 모두 「검증 관문」. 칩 모양은 「⊘ 차단 · 검증 관문」, 셀 때는 「검증 관문 차단 n건」.⊘ 차단 · 검증 관문 · 검증 관문 차단 2건

규칙 3 · 주문

「주문 차단 — {종목} {매수|매도}」 + 사유 + 「송신 안 됨」. 사유를 모르면 「사유 기록 없음」. 목록 칸은 「차단 · {사유}」.주문 차단 — 종목 C 매수 · 변동폭 가드 · 차단 임계 · 송신 안 됨

「실거래 차단」은 실거래여부 OFF 상태 이름에만 씁니다(v3 승인). 그때 남은 주문은 「가상 주문」 — 「주문 차단」이라 하지 않습니다.실거래여부 OFF · 실거래 차단 / 가상 주문 기록

  • 다른 화면: 로그인·가입·프로필·자산 기록·리스크 정책·시나리오 편집·옛 분석 탭 8개의 레이아웃은 건드리지 않습니다(주문 상세의 차단 사유 한 줄만 4-6 사전으로).
