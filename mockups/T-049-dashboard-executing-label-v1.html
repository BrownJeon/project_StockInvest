3. 결정 필요

① 문구안

A안 권고10분 미만 "주문 처리 중"
10분 이상 "주문 여부 확인 필요"
B안10분 미만 "주문 확인 중"
10분 이상 "주문 확인 필요"

A안은 "주문이 나갔는지 모른다"를 "여부"로 직접 말합니다. B안 "확인 중"은 시스템이 무언가를 확인하는 것처럼 읽히지만 실제로는 주문 응답을 기다리는 중입니다.

② 주문 번호가 있을 때

D1 권고주문 기록 상태로 접수·결과 불명·모의를 나눔. 시그널 API 에 주문 상태 필드 추가가 필요(Leader 판단)
D2API 그대로, "주문 #N 기록됨"만. 결과 불명 주문이 정상처럼 보이는 위험이 남음

결과 불명 주문에 "접수됨"을 쓰면 이번 작업이 막으려는 오해를 그대로 만듭니다. D2 는 "실행됨"보다는 정직하지만 확인 필요를 알리지 못합니다.

③ 확인 필요 안내 줄

항상 표시 권고카드 안 한 줄. 누르지 않아도 할 일이 보임
눌러서 펼침카드 높이 유지, 설명은 길게 가능. 한 번 눌러야 보임

드물고 위험한 상태라 한 줄 늘어나는 비용보다 놓치는 비용이 큽니다.
