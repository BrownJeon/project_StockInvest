| 항목 | 확인된 내용 | 비고 |

### 1.2 현행 분석 시 확인할 항목

클로드 코드에서 프로젝트를 열었을 때 아래 항목들을 우선적으로 파악해야 합니다:

```
확인 순서:
1. package.json → 의존성 패키지, 프레임워크 버전 확인
2. src/App.js (또는 App.tsx) → 라우팅 구조, 전체 페이지 구성 파악
3. src/pages/ 또는 src/views/ → 각 페이지 컴포넌트 목록
4. src/components/ → 공용 컴포넌트 현황
5. src/api/ 또는 src/services/ → API 연동 구조
6. src/styles/ 또는 CSS 파일 → 스타일링 방식 (CSS Modules, Styled-components, Tailwind 등)
7. src/store/ 또는 src/context/ → 상태 관리 방식
8. public/index.html → 메타 설정, 외부 스크립트
```

## 2. UI/UX 개선 영역 도출

### 2.1 시각 디자인 (Visual Design)

#### A. 컬러 시스템 정비

```
[작업] 컬러 토큰 시스템 구축
├── 시맨틱 컬러 정의 (success/danger/warning/info)
│   ├── 수익: green 계열 (#10B981 또는 커스텀)
│   ├── 손실: red 계열 (#EF4444 또는 커스텀)
│   ├── 보합: gray 계열
│   └── 강조: brand 컬러
├── 다크/라이트 테마 대응
│   ├── CSS Custom Properties 기반 테마 변수
│   ├── prefers-color-scheme 미디어쿼리
│   └── 사용자 선택 테마 localStorage 저장
└── 접근성 대비율 확보 (WCAG AA 기준 4.5:1 이상)
```

#### B. 타이포그래피 체계

```
[작업] 타이포그래피 스케일 정립
├── 본문: Pretendard 또는 Noto Sans KR (가독성 최우선)
├── 숫자: Tabular Figures 지원 폰트 (금액 정렬용)
│   └── font-variant-numeric: tabular-nums;
├── 크기 스케일: 12 / 14 / 16 / 20 / 24 / 32 / 40px
├── 행간: 본문 1.6, 제목 1.3, 숫자 1.4
└── 금액 표시: 천단위 콤마, 부호 컬러 적용
```

#### C. 레이아웃 시스템

```
[작업] 반응형 그리드 시스템
├── 모바일: 1컬럼 (< 640px)
├── 태블릿: 2컬럼 (640px ~ 1024px)
├── 데스크탑: 사이드바 + 메인 (> 1024px)
├── 와이드: 사이드바 + 메인 + 보조 패널 (> 1440px)
└── 간격 스케일: 4 / 8 / 12 / 16 / 24 / 32 / 48px
```

### 2.2 인터랙션 & 사용성 (Interaction & Usability)

#### A. 네비게이션 개선

```
[개선 포인트]
1. 사이드바 네비게이션
   - 아이콘 + 텍스트 조합
   - 현재 페이지 하이라이트 (active state)
   - 접힌 상태 / 펼친 상태 토글
   - 키보드 단축키 (G+D: 대시보드, G+P: 포트폴리오 등)

2. 브레드크럼 추가
   - 현재 위치 명확히 표시
   - 상위 페이지로 빠른 이동

3. 글로벌 검색
   - Cmd/Ctrl + K 단축키
   - 종목명, 종목코드, 메뉴 통합 검색
   - 최근 검색 히스토리
```

#### B. 데이터 테이블 개선

```
[개선 포인트]
1. 정렬 기능
   - 컬럼 헤더 클릭 정렬 (ASC/DESC 토글)
   - 다중 컬럼 정렬 지원

2. 필터링
   - 날짜 범위 (오늘/1주/1달/3달/6달/1년/커스텀)
   - 종목별, 매매 유형별 (매수/매도)
   - 수익/손실 필터

3. 페이지네이션
   - 무한 스크롤 또는 페이지 번호
   - 페이지당 행 수 선택 (10/25/50/100)

4. 인라인 편집
   - 메모 수정 (클릭하여 바로 편집)
   - 벌크 선택 및 일괄 작업

5. 데이터 내보내기
   - CSV / Excel 다운로드
   - 기간 선택 후 내보내기
```

#### C. 폼 UX 개선

```
[개선 포인트]
1. 매매 기록 입력 폼
   - 종목 검색 자동완성 (Autocomplete)
   - 수량 × 단가 = 총액 실시간 계산
   - 수수료 자동 계산 (설정된 수수료율 기반)
   - 입력 유효성 실시간 검증
   - 직전 입력값 기억 (매매 유형, 계좌 등)

2. 에러 핸들링
   - 인라인 에러 메시지 (필드 하단)
   - 성공/실패 토스트 알림
   - 네트워크 에러 재시도 UI
```

#### D. 로딩 & 피드백

```
[개선 포인트]
1. 스켈레톤 로딩
   - 테이블, 카드, 차트별 맞춤 스켈레톤
   - 콘텐츠 레이아웃 시프트(CLS) 방지

2. 트랜지션
   - 페이지 전환 애니메이션 (fade, slide)
   - 데이터 업데이트 시 숫자 카운팅 애니메이션
   - 수익률 변동 시 색상 flash 효과

3. 빈 상태 (Empty State)
   - 매매 기록 없을 때 안내 + CTA
   - 검색 결과 없을 때 제안
```

### 2.3 모바일 반응형 (Mobile Responsiveness)

```
[개선 포인트]
1. 모바일 네비게이션
   - 하단 탭바 (5개 이하 주요 메뉴)
   - 햄버거 메뉴 → 풀스크린 오버레이

2. 터치 최적화
   - 최소 터치 타겟: 44px × 44px
   - 스와이프 제스처 (목록 항목 삭제/편집)
   - 풀다운 리프레시

3. 모바일 테이블 대안
   - 카드형 레이아웃 전환
   - 가로 스크롤 with 고정 컬럼
   - 요약 → 상세 확장 패턴
```

## 4. 작업 우선순위 매트릭스

### Impact × Effort 매트릭스

```
                        낮은 노력 (1~3일)        중간 노력 (3~7일)       높은 노력 (7일+)
```

### 6.1 작업 시작 전 설정

```bash
# 프로젝트 열기 후 첫 번째 프롬프트:

"이 프로젝트를 분석하고 CLAUDE.md 파일을 생성해줘.
내용에 포함할 것:
- 프로젝트 개요 (기술 스택, 구조)
- 코딩 컨벤션 (네이밍, 파일 구조 규칙)
- 디자인 토큰 위치 및 사용법
- 커밋 메시지 규칙 (conventional commits)
- 주요 명령어 (빌드, 테스트, 린트)"
```

### 6.2 커밋 전략

```
# Conventional Commits 형식:
feat: 새 기능 추가
fix: 버그 수정
style: UI/스타일 변경 (기능 변경 없음)
refactor: 코드 리팩토링
chore: 빌드/설정 변경
docs: 문서 변경

# 예시:
feat(dashboard): 포트폴리오 도넛 차트 추가
fix(table): 모바일에서 테이블 가로 스크롤 안 되는 문제 수정
style(tokens): 컬러 토큰 시스템 도입 및 하드코딩 값 교체
refactor(components): Button 컴포넌트 variant prop 추가
```

### 6.3 브랜치 전략

```
main ─── 프로덕션 배포 브랜치
 │
 ├── develop ─── 개발 통합 브랜치
 │    │
 │    ├── feature/design-tokens ─── 디자인 토큰 정비
 │    ├── feature/dashboard-renewal ─── 대시보드 리뉴얼
 │    ├── feature/data-table ─── 데이터 테이블 개선
 │    ├── feature/mobile-responsive ─── 모바일 반응형
 │    ├── feature/global-search ─── 글로벌 검색
 │    ├── feature/notifications ─── 알림 시스템
 │    ├── feature/trading-journal ─── 매매 일지
 │    └── feature/tax-calculator ─── 세금 계산기
 │
 └── hotfix/xxx ─── 긴급 수정
```

## 7. 테스트 및 검증 체크리스트

### 7.1 UI/UX 검증

```
□ 모든 페이지에서 다크/라이트 테마 정상 작동
□ 모바일(375px), 태블릿(768px), 데스크탑(1280px) 레이아웃 확인
□ 로딩 상태: 스켈레톤 또는 스피너 표시 확인
□ 빈 상태: 모든 데이터 없음 화면에 안내 문구 표시
□ 에러 상태: API 실패 시 사용자 친화적 에러 메시지
□ 수익/손실 색상 일관성 (green/red) 전 페이지 확인
□ 금액 표시 포맷 일관성 (천단위 콤마, %, 부호)
□ 폼 유효성 검증 동작 확인
□ 키보드 네비게이션 (Tab, Enter, Esc) 정상 작동
□ 터치 제스처 (모바일 스와이프 등) 정상 작동
```

### 7.2 기능 검증

```
□ 매매 기록 CRUD (생성/조회/수정/삭제) 정상 작동
□ 필터/정렬 조합 테스트 (날짜 + 종목 + 유형)
□ 검색 기능: 한글 입력, 초성 검색, 빈 결과 처리
□ 차트 데이터: 매매 기록과 차트 수치 일치 확인
□ 수익률 계산 정확성 검증
□ 수수료/세금 계산 정확성 검증
□ CSV 내보내기: 필터 적용 범위 + 한글 인코딩
□ 알림 발송/수신/읽음 처리
□ 브라우저 호환성: Chrome, Safari, Firefox, Edge
□ 성능: 대량 데이터(1000건+) 로딩 속도 확인
```

### 7.3 접근성 검증

```
□ 색상 대비율: WCAG AA 기준 (4.5:1) 충족
□ alt 텍스트: 모든 이미지/아이콘에 적절한 대체 텍스트
□ aria-label: 인터랙티브 요소에 스크린리더 레이블
□ focus 표시: 키보드 포커스 시각적으로 명확
□ 시맨틱 HTML: 적절한 heading 계층 구조
□ 폼 라벨: 모든 입력 필드에 label 연결
```
