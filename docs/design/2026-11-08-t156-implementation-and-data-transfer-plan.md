# T-156 구현·운영 자료 이관·테스트 이력 저장 실행안

2026-11-08 KST. 사용자는 구현 착수, 시뮬레이션 수집 자료의 운영 DB 이관, 테스트 데이터의 DB 이력 보존을 승인했다. 이전 분석 전용 제약은 이 범위에서 해제됐다. 이 문서는 구현·이관을 위한 사전 점검과 계약이며, 코드 구현·운영 DDL/적재·배포 완료 기록이 아니다.

설계 정본은 [T-156](../../agent-vault/10-Flow/tasks/T-156-us-stock-entry-exit-forecast-design.md)의 F01~F11이다. 단계별 판단 권한과 자료의 불확실성은 유지한다. 기본 전략 구현 승인과 거래 전략의 검증 상태 승격, 실거래 활성화는 서로 다르다.

## 3. 자료 이관 원칙과 대상

운영에 자료를 보관하고 분석에서 조회할 수 있도록 연결하되, 연구 자료의 불확실성을 제거한 것처럼 표시하지 않는다. 신규 이관판은 준비→적재→검산→조회 게시 상태를 가진다. 검산이 끝나기 전 운영 분석의 기본 원천으로 선택하지 않는다.

|---|---|---|
| 가격 | 기존 연구 308티커 원주 이력1,855,428행과 새125종목 정규장 원주858,628행, 시뮬레이션에 실제 사용된 조정 입력판 | 출처·원주/분할 조정/배당 포함 조정을 분리. 최신 검증 가격의 선택 기준을 구현하고 변환/단위 확인 전 기존 KIS 조정 일봉 대체 금지 |

| 구성·기업 신원 | 실제 구성판·효력/관측 이력·공식 공지·재구성 근거, 현재 종목 매핑 | 실제 공식 PIT 구성과 재구성/고정 참조판을 다른 등급으로 유지. NYSE24개를 검증된50개로 승격 금지 |

가격은 연구용 원주·운영용 조정 가격·주문용 원주 가격을 분리해야 한다. M40의 비교 기준인 분할 조정만 반영한 일관된 가격판을 확보·대조하고 사용한다. 원주 이력의 확보만으로 모멘텀·총수익 분석 준비를 완료 처리하지 않는다.

새 이관의 기본 형태는 운영 스키마의 출처/판본별 전용 표다. 기존 `daily_bars`, `us_filings`, `ci_raw_item`, `orders`, `signals`, `position_state`의 원본 행을 먼저 덮거나 연구 결과를 실거래 기록으로 적재하지 않는다. 검증된 최신 사실을 기존 조회 경로로 연결하는 작업은 판본별 원천 선택과 필수 조건을 거친다.

## 5. 테스트 이력으로 남길 실제 자료

현재 로컬 `docs/research-data/T-156*`에서 PNG를 제외한 **28개 파일·57,339,111바이트**의 이름·크기·SHA256을 읽어 목록화했다. 이 수치는 독립 실험28개 또는 거래28개라는 뜻이 아니다. 24개 JSON에는 실험과 수집 감사·원장도 섞여 있다. NPZ 입력2개와 JSONL gzip2개는 실제 입력/관측 아카이브로 분류한다.

M40 5년·10년 각100개 설정, E3/R02 비교, 패턴 반복/계좌 비교, 비용 민감도, 시점 제한 재생과 원래 결과를 각자의 판본으로 저장한다. 같은 입력의100회 반복을100개 독립 표본으로 재분류하지 않는다. 설정×기간별 계좌 결과와 고정 응답 재생/새 에이전트 응답 검증을 구분한다.

연구 DB의 기존 `replay_run`, `closed_trade`, `daily_analysis`, `daily_context`, `price_decision` 등도 해당 테스트 실행과 연결한다. 현재 SSH 재접속이 실패해 이 표들의 새 전체 export/행수 확정은 아직 하지 않았다. 파일 원본과 별개로 DB 행 이관의 근거를 확보해야 한다.

## 6. 구현 순서와 재사용 지점

1. **자료판·이력 기반** — 신규 DDL과 타입/저장 모듈, 읽기/쓰기를 분리한 리포지터리, 가용 시점·가격 조정·정식 거래일 필터를 먼저 구현한다. 누락을0/빈 후보 목록으로 바꾸지 않는다.
2. **일회성 이관 도구** — 기본은 dry-run/계획 출력. 운영 대상 확인, 파일/DB 해시 manifest, 배치·중단/재개·충돌 격리·읽기 검산·게시/철회를 구현한다. 코드 import만으로 DDL/적재하지 않는다.
3. **테스트 보관** — 28개 아카이브의 원본과 메타를 저장하고 해시로 복원 확인한다. 실제 있는 거래/NAV/판단만 색인화하고 원본을 정본으로 유지한다. 새 테스트도 같은 저장 계약을 사용한다.
4. **전체 후보 수집** — `us-data-db.ts`, 일봉 수집기·SEC 클라이언트·뉴스 최초 관측·작업 기록을 확장/재사용한다. 기존 KIS 우선 유량·실패 격리·가격 단위·원본 판본 규칙을 유지한다. 백필과 운영 증분은 별도 예산으로 처리한다.
5. **M40 기본안** — 단일 종목 규칙 레지스트리에 다종목 순위를 억지로 넣지 않고, 자료판을 읽는 순수 계좌/후보 선택 함수와 실행 조율 모듈로 분리한다. 매일 계산·20세션 교체·D−1 시장 조건·불완전 주간 제외·재시작 중복 방지를 구현한다.
6. **참고·판단** — 기존 `runLlm`과 판단 기록의 재사용 지점을 검토한다. 출처/시각을 코드가 먼저 검증하고 조건에 맞는 단계만 호출한다. 에이전트의 임의 거래 변경은 shadow 상태에만 보존한다.
7. **분석→시그널 연결** — 해외 장마감 경로를 통합하고 신규 M40 전략판을 명시한다. 초안은 별도 저장, 승인 가능한 발행은 기존 공통 서비스와 검증 관문을 거친다. 보호 청산 우선·현재 잔량/미체결 대사·USD/KRW 변환을 유지한다.
8. **운영 적용** — 독립 검토와 적절한 격리 검증 뒤 DDL·staging 적재·해시 대조·조회 게시를 순서대로 수행한다. 기존 설정과 일반/보호 거래의 회귀를 확인하고 배포 결과를 별도 기록한다.

핵심 재사용 경로는 `src/lib/profit-engine/daily-bars-*`, `src/lib/data/us-edgar/*`, `src/lib/corp-intel/*`, `src/lib/strategy/post-market-overseas.ts`, `records/judgment-*`, `src/lib/signals/service.ts`, `src/lib/safety/validation-gate.ts`다. `/api/analyst/run`의 국내 기본 경로를 미국 전략 진입점으로 대체하지 않는다.

## 7. 적용 전 검증·복구

| 검증 | 확인할 실패/경계 |
|---|---|
| 이관 재현 | 같은 import 재실행·절반 종료/재개·중복 키·기존 파일 hash drift·DB 목표 오류·본문 압축 해시/바이트·패킷 분할·문자셋/시간대 |
| 입력 의미 | 원주/조정 혼합, 분할이 급락으로 집계됨, ticker/종류주 중복, 핵심 자료 partial, 시장 false/unknown, 공개일만 있는 문서·접수/배포·정정 후행 자료 |
| M40 일치 | 고정 입력의 과거 기본안과 같은 순위/시점/일반 매도, 직전 완료 시장 조건,126일 유효 간격·SMA200·동률·공통 기준일·20세션 주기·재시작 |
| 계좌·주문 | entry debit15%·슬롯5·수수료 양쪽25bp·정수 주·가용 결제 현금·보유 비중 상승을 자동 리밸런싱하지 않음·기존/다른 전략 보유 보호 |
| 에이전트 | 없는 근거·미래 문서·허용하지 않은 종목/행위·schema 실패·timeout·재호출 중복. 선택적 실패 때 M40 기본안 불변, 원문 지시는 명령이 아닌 데이터 |
| 시그널 회귀 | 미등록/미검증 새 전략은 활성 매수 우회 없음. 매도 검증 면제만으로 일반 매도 허용하지 않음. 모의 결과가 `orders`/실제 포지션·알림을 만들지 않음 |
| 이력 복원 | 원본28개 파일의 복원 SHA 일치, 실제 사례/기간/통화/수수료와 요약 일치. 과거 결과의 사후 최적화·실제 당시 실행을 구분 |
| 운영 스모크 | 게시한 자료판을 실제 조회/분석한 증거, 대상·신선도·부분 완료 보고, 기존 DRY_RUN/킬스위치/승인 모드 불변, 계좌/주문 회귀 |

DDL은 트랜잭션 rollback만으로 되돌릴 수 있다고 가정하지 않는다. 신규 표 추가와 입력 staging을 우선하고 기존 표 변환은 최소화한다. 이관 전 실제 영향 표의 스키마/기존 상태와 선택 데이터 백업·격리 복원 근거를 확보해야 한다. 현재 안전한 전량 export/복원 리허설과 운영 적용은 미실행이다.

철회는 새 자료판의 조회 게시를 취소하고 이전 검증 자료판 선택을 복원하는 방식이 우선이다. 이미 운영 분석/새 이력이 연결된 표를 일괄 DROP하거나 기존 데이터를 삭제하지 않는다. 새 소스·배치 ID를 기준으로 중단·재개/격리할 수 있어야 하며, 적용 후 다른 쓰기가 있는 경우 원시 백업을 통째로 덮어 복원하지 않는다.

공통 교체 기준일(T0), 개장 집행 가격/만료·늦은 분석 처리, 허용 위험·기존 보유분 이관의 미결 항목은 F09와 연결한다. 정책값이 없으면 이유를 기록하며 활성 거래 판단을 임의로 통과시키지 않는다. 분석/초안 구현과 기존 안전 관문의 검증은 먼저 진행할 수 있다.

## 8. 담당·실행 상태

사용자는 담당 확인에 **“이번 T-156은 Codex가 구현·DB 이관까지 직접 진행”**이라고 답했다. 따라서 이번 T-156의 큰 구현·검증·이관은 Codex가 직접 맡는다. 이전 담당 확인 대기는 해소됐으며, 원본 보존·안전 관문·운영 적용 검증은 유지한다. 읽기 전용 Claude 검토 브로커를 구현 실행기로 사용하지 않는다.

이 문서는 구현 또는 DB 이관 완료 증거가 아니다. 실제 인수·작성·검토·검사·DDL·적재·배포 각각의 결과를 T-156 이력에 추가해야 한다.
