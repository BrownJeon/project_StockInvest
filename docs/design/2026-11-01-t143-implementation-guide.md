## 0. 머리말

### 0.1 먼저 — 불편한 사실 7개

데모의 「불편한 사실 5가지」 중 4개는 그대로 유효하고, 가이드를 쓰며 3개가 더 드러났다.

1. **[확실] 화면만 만들면 아무 일도 일어나지 않는다.** 지금 해외 수동 목록을 읽는 함수는 `getStaticOverseasUniverse()`(`src/lib/strategy/universe-overseas-static.ts:21`) 하나이고, **환경변수 `OVERSEAS_UNIVERSE_SYMBOLS`(폴백 `ALLOWED_SYMBOLS_OVERSEAS`)만 읽고 비어 있으면 하드코딩 `SP500_TOP50` 을 돌려준다.** 호출자는 3곳 — `universe.ts:221`·`us-data-db.ts:56`·`app/api/ticker/all/route.ts:99`. 화면이 DB 에 저장해도 **이 함수가 DB 를 읽도록 바뀌기 전에는 분석 대상이 하나도 안 바뀐다.** 그런데 데모의 성공 문구는 「다음 「해외 장마감 분석」부터 반영됩니다」라고 **단정**한다 → **읽기 쪽 연결과 화면은 같은 릴리스에 함께 나가야 한다**(§8.1 WP-B0, §8.4 완료 기준 ①). 따로 배포하면 화면이 거짓말을 한다.
2. **[확실] 그 읽기 쪽 파일은 커밋 훅 감시 대상이다.** `SAFETY_PATHS` 에 `^src/lib/strategy/` 가 있다 → `universe-overseas-static.ts`·`universe.ts`·`records/job-slots.ts` 를 건드리는 커밋은 **Reviewer 판정 줄(scope 포함) 없이는 커밋되지 않는다.** `^scripts/migrations/`(DDL)·`^src/app/api/settings/safety/`(알람 토글)도 같다. 화면 파일(`src/app/settings/**`·`src/components/**`)과 `src/lib/ops/**`·`src/app/api/settings/overseas-universe/**` 는 감시 밖이다 → **커밋을 섞지 말고 §8.1 의 패키지 경계대로 쪼갠다.**
3. **[확실] 목록에서 빼도 보유 중이면 계속 분석된다.** 해외 수집 대상 = 보유(`position_state` market='overseas') ∪ 즐겨찾기(`stock_favorites` 중 해외 형식) ∪ 수동·자동 목록 — `src/lib/data/us-data-db.ts:41` 주석과 44~57행 구현 [확실]. 데모가 이 사실을 **4곳**에 글로 적어 둔 이유다(§2.4). 이 문구를 빼면 「뺐으니 끝」으로 오해한다.
4. **[가능성 높음] 알림은 12월 정기 재구성을 못 잡는다.** 인수·합병·상장폐지는 공시로 드러나지만 「시가총액 순위가 떨어져서」 하는 교체는 공시에 없다 → **알림이 조용한 것은 목록이 맞다는 뜻이 아니다.** 데모가 「마지막 수동 갱신 N일 전」과 「12-19 에 목록을 직접 확인하세요」를 **3곳**에 둔 이유다(§2.7).
5. **[확실] 기존 「동적 종목 선별 (Universe)」 스위치는 아무 동작도 바꾸지 않는다.** D6 확인 결과다 — 근거·정정 문구는 §6. 데모는 이 행의 설명을 「D6 에서 결정합니다」라는 **자리표시자**로만 그렸으므로, **정정 문구 자체는 승인 데모에 없다**(§11 L-2).
6. **[확실] 홈 「확인 필요」는 입력이 하나라도 실패하면 목록 대신 통째로 오류다**(`src/lib/ops/metrics/home.ts` 머리 주석 3번 + 123~136행). 빈 목록이 「지금 확인할 것 없음」으로 읽히는 것을 막는 fail-closed 규칙이다. 그래서 **제안 건수 조회를 그 입력에 그냥 더하면, 새로 들어온 가장 덜 급한 값 하나가 「모든거래차단 ON」 줄까지 가린다.** 처리 방법은 §3.4 — 새 입력을 fail-closed 집합에 넣지 않는다.
7. **[확실] 일괄 교체의 형식 검사는 앱의 기존 검사보다 엄격하다.** 앱 `isOverseasSymbol` 은 `/^[A-Z]{3}:[A-Z][A-Z0-9.]*$/` 로 **아무 3글자 거래소**를 통과시키지만, 실제로 KIS 로 변환되는 거래소는 `NAS`·`NYS`·`AMS` 3개뿐이다(`OverseasExchange` 타입 + `OVRS_EXCG_CD` 표, `kis-symbols.ts:12·46~50`). 데모의 검사 `/^(NAS|NYS|AMS):[A-Z][A-Z0-9.]{0,6}$/` 가 **더 맞다** → 데모 쪽을 쓴다(§2.6.2). 기존 함수는 바꾸지 않는다.

### 1.1 새 라우트 2개 — 기존 설정 서브 화면과 같은 자리

### 2.1 설정 요약 행 (데모 §0 「설정 › 전략 설정 — 들어가는 행」 오른쪽 칸)

- **삽입 위치**: `src/app/settings/SettingsPage.tsx` — `<SectionHeader title="전략 설정" />`(860행) 다음 카드 `div` 의 **첫 자식**. 즉 「동적 종목 선별 (Universe)」(863~882행) **바로 위**. 데모가 그린 순서와 같다.
- 모양: 56px 행, **행 전체가 누르는 영역**(T-130 교정 규칙), 끝에 `›`. `<Link href="/settings/overseas-universe">`.
  - 제목: `해외 분석 대상` + 제안이 1건 이상이면 칩 `변경 제안 N`(`StatusChip`, `--accent` 계열).
  - 부제: `150종목 · 수동 98 · 자동 50 · 수동 갱신 2025-12-19` — **값이 null 인 조각은 그 구절을 뺀다**(0 으로 채우지 않는다 — T-108 §2.3.2 규칙).

- 상태: 로딩(`SkelBar`) · 조회 실패(「눌러서 다시 확인」 — `CashLedgerSummaryRow` 문구 관습) · 마이그레이션 전(503 `not_migrated` → 중립 `◌ 준비 중 — 서버 준비 뒤 쓸 수 있습니다`, `CashLedgerSummaryRow` 선례와 같은 문구).

### 2.2 본 화면 틀 (데모 §3 `#f3`)

```
OverseasUniversePage                      ← 'use client', 자체 조회 1회(60초 재조회 없음 — 데모 §5 로딩 주석)
├─ 앱바  ‹ | 해외 분석 대상 | <조회 시각 MM-DD HH:mm>
├─ TileGrid                               ← 데모 .grid2 (2×2)
│   ├─ MetricTile 분석 대상   150종목  meta「보유 ∪ 즐겨찾기 ∪ 목록」
│   ├─ MetricTile 변경 제안     3건    meta「확인 필요」 / 0건이면 「지금 확인할 것 없음」
│   ├─ MetricTile 수동 — 나스닥100 98종목 meta「갱신 2025-12-19 · 349일 전」
│   └─ MetricTile 자동 — NYSE 상위 50 50종목 meta「산출 12-01 02:40 · 다음 01-01」
├─ SegmentControl  [변경 제안 N] [목록 M]   ← ?tab= 동기화
├─ 패널 proposals : ProposalCard × N  |  빈 상태(§2.7)  |  오류(§2.8)
├─ 패널 list      : 출처 칩 줄 + 종목 목록 + foot + 「12월 정기 재구성 — 목록 한 번에 바꾸기」
└─ Sheet (확인)                            ← 제안 처리 확인
```

- **「자동 — NYSE 상위 50」 칸의 제목에 50 을 박지 않는다.** Q4 가 `system_config` 로 조정되므로 라벨은 서버가 준 개수로 만든다 — `자동 — NYSE 상위 {n}`. 「다음 01-01」도 서버 값이다(Q2 주기가 바뀌면 따라간다). **화면에 50·월1회를 하드코딩하지 않는다.**
- **「349일 전」** = 서버가 준 `updatedAt` 과 조회 시각의 차. 350일이 넘든 말든 숫자를 그대로 쓰고, `updatedAt` 이 null 이면 그 조각을 뺀다(「갱신 기록 없음」).
- 숫자는 전부 `.num`(tabular-nums). 종목 코드는 **전각 금지·전체 코드 표기**(§2.5).

### 2.3 탭 — a11y 를 데모와 다르게 쓴다 (designer 판단, 선언)

- 데모는 `role="tablist"`/`tab`/`tabpanel` + `aria-selected` + `aria-controls` 로 그렸다.
- **구현은 기존 `SegmentControl`(`role="group"` + 버튼마다 `aria-pressed`)을 쓴다** [확실: 그 파일 11~27행].
- **이유**: 거래 3칸·분석 3분류가 전부 이 부품·이 규격이다. 눈에 같아 보이는 것을 화면마다 다른 ARIA 로 쓰면 읽기 도구 사용자에게 같은 것이 다르게 들린다. 둘 다 유효한 ARIA 이고 **보이는 모양·동작·URL 동기화는 데모와 같다.**
- 패널은 `hidden` 으로 바꿔 그린다(두 패널을 동시에 마운트하지 않는다 — 목록 150행을 숨겨 두지 않는다).
- 탭 라벨의 건수는 **처리하지 않은 제안 수**(`open`)다. 보류·무시한 것은 빠진다 — 그것이 보류·무시의 뜻이다(데모 `renderProposals` 주석 D4).

### 2.4 제안 카드 — `ProposalCard` (데모 §3, 행동 3종)

**카드 1개 = 제안 1건.** 구조(데모 `.pcard`):

```
ph   : <종목코드 전체>  <종류 칩>  [보유 n주 칩]
dl   : 근거  <원천 + 수집일>
       권고  <권고 한 줄>              ← rec 가 있으면 rec, 없으면 act
warn : (있으면) 보유 중 경고 한 줄
acts : [주 행동]  [보류]  [무시]        ← 상태 open 일 때만
```

#### 2.4.1 상태 5종 — 무엇을 그리나

| 상태 | 저장되나 | 그리는 것 | 문구(데모 그대로) |
|---|---|---|---|
| `open` | ○ | 버튼 3개 | 주 행동 = `목록에서 빼기` / `목록에 넣기` / `코드 바꾸기 NAS:AJJJ → NYS:AJJJ` |
| `held` | ○ + 해제 시각 | `role="status"` 줄 + `되돌리기` | `보류 — 다음 「해외 분석 대상 갱신」(01-01)까지 숨깁니다. 공시가 갱신되면 그때 다시 올라옵니다.` |
| `ignored` | ○ + 근거 지문 | `role="status"` 줄 + `되돌리기` | `무시 — 같은 근거로는 다시 제안하지 않습니다.` |
| `done` | ○ | `role="status"` 초록 줄, 버튼 없음 | `{행동 완료문} · 다음 「해외 장마감 분석」부터 반영됩니다. 이미 만든 시그널·보유 종목에는 영향 없습니다.` |
| `failed` | **✗ 화면 전용** | `role="alert"` 줄 + `다시 시도` | `저장하지 못했습니다 — 데이터베이스 오류. **목록은 바뀌지 않았습니다.** 잠시 뒤 다시 해 보세요.` |

- `failed` 는 **DB 상태가 아니다** — 저장 요청이 실패한 화면 상태다. 새로고침하면 `open` 으로 돌아온다. DB 에 `failed` 를 만들지 않는다.
- 취소: 시트에서 「취소」를 누르면 그 카드 밑에 `role="status"` 로 `취소했습니다 — 목록은 그대로입니다.` 를 **4초** 보이고 지운다(데모 `sh3no`).
- 행동 완료문(데모 `done`): 빼기 `목록에서 뺐습니다` / 보유 중이면 `목록에서 뺐습니다 (보유 중이라 분석은 계속)` / 코드 바꾸기 `코드를 바꿨습니다`.

#### 2.4.2 보유 중 경고 — **4곳 전부 남아야 한다** (불편한 사실 3)

| # | 자리 | 문구 |
|---|---|---|
| 1 | 카드 머리 칩 | `보유 2주` (`StatusChip`. `qty` 가 null 이면 **`보유`** — 0 으로 채우지 않는다) |
| 2 | 카드 경고 줄 | `보유 중입니다 — 목록에서 빼도 분석은 계속됩니다(분석 대상 = 보유 ∪ 즐겨찾기 ∪ 목록). 분석을 멈추려면 먼저 매도해야 합니다.` |
| 3 | 확인 시트 본문 | `수동 목록에서 빼면 98 → 97 종목. 보유 중이라 분석 대상 수는 150 그대로입니다.` + 위 경고 줄 |
| 4 | 일괄 교체 대조 목록 | 빼는 줄 뒤에 `· 보유 2주 — 빼도 분석은 계속` (§2.6.3) |

> 이 4곳은 **회귀 시험 대상**(§8.3 T-1)이다. 데모가 드러낸 사실이 화면에서 사라지면 결함이다.

#### 2.4.3 확인 시트 (데모 `sheet3`)

`Sheet` 를 쓴다. 제목 = 주 행동 이름, 확인 버튼 글자 = `빼기`/`넣기`/`바꾸기`, 취소 버튼 왼쪽. 본문 4줄:

1. `<종목코드 전체>` · `<종류>`
2. 효과 한 줄 — `수동 목록에서 빼면 98 → 97 종목, 분석 대상 150 → 149 종목.` (코드 바꾸기: `수동 목록의 코드만 바뀝니다(98 종목 그대로). 바꾸지 않으면 KIS 조회가 매일 실패해 「데이터 이상」으로 올라옵니다.`)
3. (보유 중이면) 경고 줄
4. **고정 꼬리말**(`--muted` 12px) — `주문이 아닙니다 — 실거래여부·모든거래차단과 무관하고, 이미 만든 시그널·보유 종목에도 영향이 없습니다. 다음 「해외 장마감 분석」부터 쓰입니다.`

- **보류·무시·되돌리기는 시트를 거치지 않는다**(데모: 즉시 적용, 되돌리기 버튼이 있다). 되돌릴 수 있고 목록을 바꾸지 않으므로 맞다.
- 시트의 숫자(98 → 97, 150 → 149)는 **서버가 준 효과 값**으로 만든다. 화면이 더하기·빼기를 해서 만들지 않는다(§4.2 응답 `effect`).

### 2.5 목록 탭 (데모 §3 `#panel-l`)

- **출처 칩 줄** — `전체 150` `수동 98` `자동 50` `즐겨찾기 7` `보유 4`, 버튼마다 `aria-pressed`, `role="group" aria-label="출처로 걸러보기"`. **가로 스크롤 허용**(화면의 유일한 가로 스크롤, 의도 — 데모 「모바일 확인」 1번). 한 번에 하나만 선택(데모 동작).
- **종목 줄** — 왼쪽 `NAS:AAAA` + 작게 종목 이름, 오른쪽 출처 칩 묶음(`수동`·`자동 n위`·`즐겨찾기`·`보유 n주`·`제안 있음`). 줄 높이 56px. **누르는 동작 없음**(데모에 링크가 없다 — 종목 상세로 보내지 않는다).
- **종목 코드는 전체로 보인다** — `formatSymbolShort` 를 **쓰지 않는다**. 그 함수는 `NAS:AAAA` → `AAAA` 로 거래소를 떼는데(`src/lib/symbols.ts:16~21` [확실]), 이 화면은 **거래소 이동 제안**(`NAS:AJJJ → NYS:AJJJ`)을 다루므로 접두사가 뜻을 가진다.
- 종목 이름이 없으면(= `stock_meta` 에 없음) 코드만 그린다. **이름 조회를 위해 외부/`/api/ticker/*` 를 부르지 않는다**(홈 규칙과 같다).
- foot 문구(데모 그대로): `종목마다 출처가 보입니다 — 4가지가 섞이기 때문입니다. 「자동 n위」는 시가총액 순위, 「보유 n주」는 그 종목이 목록에서 빠져도 분석된다는 표시입니다. 즐겨찾기·보유는 여기서 바꾸지 않습니다(각자 원래 화면에서).`
- 맨 아래 버튼 `12월 정기 재구성 — 목록 한 번에 바꾸기` → `/settings/overseas-universe/bulk`.

### 2.6 일괄 교체 서브 화면 (데모 §4) — **고위험 취급**

#### 2.6.1 틀

```
BulkReplacePage
├─ 앱바  ‹ | 수동 목록 한 번에 바꾸기
├─ label  새 나스닥100 목록 붙여넣기
├─ hint   한 줄에 한 종목. 형식은 NAS:AAAA(거래소:코드). 쉼표·공백·빈 줄은 알아서 정리합니다.
│         여기 내용이 수동 목록 전체를 대신합니다 — 즐겨찾기·보유는 건드리지 않습니다.
├─ textarea rows=9  spellcheck=false  aria-describedby
├─ [대조하기]
├─ ManualListDiff  (대조 결과 — 넣을 것·뺄 것·그대로 + 문제 줄 + dnote + [다시 대조][저장])
└─ Sheet (확인)
```

- 데모의 예시 버튼 3개(`정상`·`형식 오류 포함`·`빈 입력`)는 **데모 전용이라 옮기지 않는다.**
- 붙여넣은 내용은 **저장 실패 뒤에도 지우지 않는다**(데모 실패 문구: 「붙여넣은 내용은 그대로 두었으니 다시 저장해 보세요」).

#### 2.6.2 파싱·검사 규칙 — 데모 `parse()`/`buildDiff()` 를 그대로 (순수 함수로 뺀다)

`src/lib/universe/parse-manual-list.ts`(신규, 순수 함수 · 시험 대상):

1. `String(text).split(/[\n,]/)` → `trim()` → 빈 문자열 제거.
2. 형식 검사 `^(NAS|NYS|AMS):[A-Z][A-Z0-9.]{0,6}$` — **통과 못 하면 `bad`**. 소문자·거래소 없음(`AAPL`)·빈 코드(`NAS:`)·뒤에 글자가 붙은 것(`NAS:ANNN 삼성`) 전부 `bad`(데모 `bad` 예시가 이 5가지다).
3. 이미 나온 코드는 `dup`(첫 것만 남긴다).
4. 대조 — `add` = 통과한 것 중 현재 수동 목록에 없는 것 / `rm` = 현재 수동 목록 중 새 목록에 없는 것 / `same` = 둘 다 있는 것. **현재 수동 목록만 비교 대상이다**(즐겨찾기·보유는 비교에 넣지 않는다).
5. **`bad` 가 1건이라도 있으면 저장 버튼 `disabled`** — 일부만 반영되는 상태를 만들지 않는다.
6. `next.length === 0` 이면 저장을 막지 않되 **경고**하고 버튼 글자를 바꾼다(아래).

> 이 검사는 앱의 `isOverseasSymbol` 보다 엄격하다(불편한 사실 7). **기존 함수를 바꾸지 말고** 이 화면용 검사를 따로 둔다.

#### 2.6.3 대조 화면 `ManualListDiff` (데모 `.diff`)

- 머리 3칸: `넣을 것 N` · `뺄 것 N` · `그대로 N`.
- 줄 순서 — **문제를 먼저**: `bad` → `dup` → `add` → `rm`.
- 줄 모양: 기호 글리프(`aria-hidden`) + 코드 + 작은 설명.
  - `bad` → `!` + `형식 오류 — NAS:AAAA 꼴이어야 합니다`
  - `dup` → `=` + `중복 — 1번만 씁니다`
  - `add` → `+` + `넣기`
  - `rm` → `−` + `빼기` (+ 보유 중이면 `· 보유 2주 — 빼도 분석은 계속`)
- 아래 `dnote` 1줄 — 세 갈래:
  - `bad > 0` → `role="alert"` · `형식 오류 N건이 있어 저장할 수 없습니다. 일부만 반영되는 상태를 만들지 않습니다 — 고치고 다시 대조하세요.`
  - `next === 0` → `role="alert"` · `목록이 비어 있습니다. 이대로 저장하면 해외 분석은 보유·즐겨찾기만 남아 약 11종목으로 떨어집니다.`
  - 그 밖 → `저장하면 수동 목록이 {현재} → {새} 종목이 됩니다. 즐겨찾기·보유는 건드리지 않습니다.`
    > **「약 11종목」은 서버가 준 값으로 만든다**(보유 ∪ 즐겨찾기 의 실제 수). 데모의 11 은 합성값이라 **숫자를 박지 않는다**. 모르면 그 구절을 뺀다.
- 버튼 2개: `다시 대조` · 저장(`next === 0` 이면 글자 `목록 전부 비우기` + 위험 꼴, 아니면 `이 내용으로 바꾸기` + 주 꼴).

#### 2.6.4 확인 시트 (데모 `sheet4`) — 바뀌는 수를 글로

본문 순서:

1. `수동 목록을 {현재} → {새} 종목으로 바꿉니다.`
2. `넣을 것 N · 뺄 것 N · 그대로 N`
3. (`next === 0`) `목록이 비면 해외 분석은 보유·즐겨찾기만 남아 약 {n}종목이 됩니다. 정말 비울까요?`
4. (빼는 것 중 보유가 있으면) `빼는 종목 중 보유 중인 것이 있습니다 — 목록에서 빠져도 분석은 계속됩니다.`
5. **고정 꼬리말** — `주문이 아닙니다 — 실거래여부·모든거래차단과 무관하고, 이미 만든 시그널·보유 종목에도 영향이 없습니다. 다음 「해외 장마감 분석」부터 쓰입니다. 바꾼 뒤에도 변경 이력에서 직전 목록으로 되돌릴 수 있습니다.`

확인 버튼 글자 = `바꾸기` / (빈 목록) `전부 비우기`. 결과:

- 성공 `role="status"` — `바꿨습니다 — 수동 목록 {N}종목 (넣기 N · 빼기 N). 변경 이력에 남았습니다. 다음 「해외 장마감 분석」부터 반영됩니다.`
- 실패 `role="alert"` — `저장하지 못했습니다 — 데이터베이스 오류. 목록은 바뀌지 않았습니다(전부 반영되거나 전부 안 되거나 둘 중 하나입니다). 붙여넣은 내용은 그대로 두었으니 다시 저장해 보세요.`

> 꼬리말 5번이 「직전 목록으로 되돌릴 수 있다」고 **단정**한다 → DB 에 직전 목록이 남아야 한다(§5.1). 되돌리기 **화면**은 데모에 없다 → §11 L-4.

### 2.7 빈 상태 — 2변형, 「확인했다」를 거짓으로 쓰지 않는다 (데모 §5 가운데)

| 변형 | 조건 | 문구 |
|---|---|---|
| **3곳 모두 확인** | 마지막 확인에서 원천 3곳(미국 공시 · 해외 뉴스 · 상장 목록)을 **다 읽음** | `지금 확인할 변경 없음.` / `마지막 확인 12-02 02:10 — 미국 공시 · 해외 뉴스 · 상장 목록 3곳 모두 확인했습니다.` / `⚠ 12월 정기 재구성은 공시에 나오지 않습니다 — 12-19 에 목록을 직접 확인하세요.` |
| **일부만 확인** | 한 곳이라도 못 읽음 | §2.8 의 경고 줄로 바꾼다 — **빈 문구를 쓰지 않는다** |
| (모두 처리) | 제안이 있었고 전부 처리·보류·무시됨 | 첫 줄만 `확인할 변경을 모두 처리했습니다.` 로 바꾼다(데모 `pempty-lead`) |

- **「3곳 모두 확인」은 서버가 그렇게 말할 때만 쓴다.** 원천 수를 화면이 세지 않는다(§4.1 `coverage`). 홈 「확인 필요」의 같은 규칙(`checkCoverage`)과 한 말투다.
- **12월 안내는 빈 상태에도 남는다** — 제안이 0건이어도 목록이 맞다는 뜻이 아니다(불편한 사실 4). 이 줄과 「수동 갱신 N일 전」·텔레그램 꼬리말 **3곳**이 §8.3 T-2 회귀 시험 대상이다.

### 2.8 로딩·오류 (데모 §5 왼쪽·오른쪽)

- **로딩**: 숫자 4칸은 `SkeletonTile`(자리를 먼저 잡아 화면이 튀지 않게), 줄은 `SkeletonRows`. `aria-busy="true"`. **조회는 1회 — 주기 재조회 없음.**
- **섹션 단위 실패 격리** — 제안 조회와 목록 조회는 **따로 실패**한다(홈과 같은 방식). 한쪽이 죽어도 다른 쪽은 보인다.
  - 목록 실패: 패널에 `목록을 불러오지 못했습니다.` / `조회 실패 — 잠시 뒤 다시 해 보세요.` + `RetryButton`. 탭 라벨 건수는 `?`.
  - 제안 실패: 같은 모양으로 제안 패널만.
- **일부만 확인 경고 줄**(데모 오른쪽 칸) — `CheckRow severity="e"`:
  제목 `변경 확인이 일부만 끝났습니다` / 부제 `미국 공시 확인 실패 (12-02 02:10) — 인수·합병·상장폐지를 놓쳤을 수 있습니다`.
  읽은 제안은 **그대로 보인다**(일부만 확인했어도 찾은 것은 보여 준다).
- 인증 만료(401)·네트워크 끊김은 기존 화면 관습을 따른다(T-108 §2.3.1 과 같은 처리).

### 3.4 ⚠ fail-closed 규칙을 깨지 않는 방법 (불편한 사실 6)

`home.ts` 는 「확인 필요」 입력 중 하나라도 실패하면 **목록 대신 섹션 전체 오류**로 둔다. 제안 건수를 그 집합에 그냥 더하면, **가장 덜 급한 새 값 하나가 「모든거래차단 ON」까지 가린다.**

**규칙(설계 결정)**:

1. 제안 건수 조회는 **fail-closed 집합에 넣지 않는다.** `CheckInput` 에 `universeProposals: { open: number; first: string | null } | null` 로 넣고, **`null` 이면 그 줄을 그리지 않고 끝낸다**(섹션을 오류로 만들지 않는다).
2. 「모르는 상태」를 사용자에게 알리는 일은 **이미 있는 기계가 한다** — 매일 도는 「해외 분석 대상 변경 확인」(`universe-change-watch`)이 실패·누락이면 `job_run_log` 를 통해 **데이터 이상(`data_anomaly`, `source='job_run'`) 줄로 올라온다**(`anomalies.ts` 가 오늘의 `failed`·`missing`·`degraded` 잡을 읽는다 [확실: `types.ts` `ObserveSet.anomalies` 주석]).
3. 그러려면 **그 잡이 `JOB_SPECS` 와 `JOB_NAME_KO` 에 등록돼야 한다**(§8.1 WP-B4). 등록하지 않으면 화면이 「알 수 없는 작업 실패」로 읽힌다(`jobNameText` 의 모르는 잡 처리 [확실]).

> 바꿔 말하면: **제안이 몇 건인지 못 읽은 것은 조용히 넘기고, 변경 확인이 돌지 않은 것은 데이터 이상으로 크게 말한다.** 후자가 사용자가 실제로 알아야 하는 사실이다.

## 4. API 계약 3개

**공통 규칙** (기존 패턴 그대로 — `/api/settings/risk-policy` 선례 [확실]):

- 봉투 `{ ok: true, data }` / `{ ok: false, error }`. 400 은 `fieldErrors` 를 더 실을 수 있다.
- `export const dynamic = 'force-dynamic'`, 읽기 응답에 `Cache-Control: no-store`.
- 인증은 **전역 미들웨어**가 한다(§1.1) — 라우트 안에서 다시 세션을 검사하지 않는다. `window.Capacitor` 같은 앱 판별을 **권한 판단에 쓰지 않는다**(금기).
- **DB 만 읽고 쓴다** — KIS·SEC·외부 호출 0, 주문·시그널·알림 생성 0. 쓰는 곳은 T-143 전용 테이블뿐이다.
- 마이그레이션 전에는 `503 { ok:false, error:'not_migrated' }`(`CashLedgerSummaryRow` 선례와 같은 처리) → 화면은 중립 「준비 중」.

### 4.1 `GET /api/settings/overseas-universe` — 화면 1회 조회

```
GET /api/settings/overseas-universe
→ 200 { ok: true, data: UniverseScreenDTO }
```

| 섹션 | 모양 | 실패 시 |
|---|---|---|
| `summary` | `{ total, manual, auto, favorites, held, manualUpdatedAt, manualUpdatedDaysAgo, autoRefreshedAt, autoNextAt, autoTopN, heldOrFavoritesOnlyCount }` | `{ state:'error', error }` — 숫자 칸만 `—` |
| `watch` | `{ lastCheckedAt, coverage: { source: 'us_filings'\|'news_overseas'\|'listing', ok: boolean, failedAt }[], allChecked: boolean }` | 〃 — 빈 문구를 「3곳 모두 확인」으로 쓰지 않는다 |
| `proposals` | `{ state:'ok', data: Proposal[] }` | `{ state:'error', error }` — 제안 패널만 오류 |
| `list` | `{ state:'ok', data: UniverseRow[] }` | `{ state:'error', error }` — 목록 패널만 오류 |

- **섹션 단위 실패 격리** — 한 섹션 실패는 그 섹션만 `error` 이고 **HTTP 200**. 예기치 못한 전체 실패만 503(`/api/ops/home` 선례 [확실]).
- `Proposal` = `{ id, symbol, kind, kindLabel, basis, recommendation, action: { type:'remove'|'add'|'recode', label, verb, nextSymbol? }, effect: { manualFrom, manualTo, totalFrom, totalTo, heldKeepsAnalysis }, held: { qty } | null, state: 'open'|'held'|'ignored'|'done', heldUntil, warn }`.
  - **`effect` 와 `label`·`verb` 는 서버가 완성해 준다** — 화면이 숫자를 더하거나 문장을 조립하지 않는다(§2.4.3).
- `UniverseRow` = `{ symbol, name, sources: ('manual'|'auto'|'favorite'|'held')[], autoRank, heldQty, hasProposal }`.
- `heldOrFavoritesOnlyCount` = 「목록을 비우면 남는 수」(§2.6.3 의 「약 11종목」). 모르면 `null`.
- **Q2·Q4 는 응답에 담아 보낸다**(`autoTopN`·`autoNextAt`) — 화면이 50·월1회를 박지 않는다.

### 4.2 `POST /api/settings/overseas-universe/proposals/[id]` — 제안 1건 처리

```
POST  { do: 'act' | 'hold' | 'ignore' | 'reopen', baseState: 'open'|'held'|'ignored' }
→ 200 { ok: true, data: { proposal: Proposal, summary: Summary } }
→ 409 { ok: false, error: 'state_changed', data: { proposal: Proposal } }
→ 400 { ok: false, error: '…', fieldErrors? }
→ 500 { ok: false, error: '…' }
```

- **멱등성·충돌**: `baseState` 가 현재 상태와 다르면 **409** 이고 **아무것도 바꾸지 않는다** — 다른 기기·텔레그램에서 먼저 처리한 경우다. `risk-policy` 의 `baseVersion` → 409 와 같은 방식 [확실: 그 라우트 164~166행]. 화면은 409 를 받으면 서버가 돌려준 `proposal` 로 카드를 다시 그리고 `role="status"` 로 알린다(**실패 빨강으로 쓰지 않는다** — 이미 처리된 것은 오류가 아니다).
- 같은 `do` 를 두 번 보내면 두 번째는 409 다(상태가 이미 바뀌었으므로). **중복 클릭이 목록을 두 번 바꾸지 않는다.**
- `act` 는 **수동 목록을 바꾼다** → 응답에 새 `summary` 를 실어 머리 숫자 4칸을 함께 갱신한다(화면이 다시 전체 조회하지 않는다).
- `hold` 는 `heldUntil` 을 **다음 월간 산출 시각**으로 둔다(D4 — 날짜를 화면이 계산하지 않는다). `ignore` 는 **근거 지문**을 기록해 같은 근거 재제안을 막는다(§5.2).
- `reopen`(되돌리기)은 `held`·`ignored` 만 받는다. `done` 은 되돌리지 않는다(목록이 이미 바뀌었다 — 되돌리려면 §11 L-4 의 변경 이력이 필요하다).

### 4.3 `PUT /api/settings/overseas-universe/manual` — 일괄 교체, **전부 아니면 전무**

```
PUT   { symbols: string[], baseVersion: number }
→ 200 { ok: true, data: { summary: Summary, applied: { added: number, removed: number, kept: number }, version: number } }
→ 400 { ok: false, error: '형식이 잘못된 종목이 있습니다', fieldErrors: { symbols: string[] } }
→ 409 { ok: false, error: 'version_changed', data: { summary, version } }
→ 500 { ok: false, error: '…' }
```

- **전부 아니면 전무**: 한 트랜잭션에서 수동 목록을 통째로 바꾼다. 한 종목이라도 형식 검사에 걸리면 **400 이고 DB 는 그대로**다(부분 반영 없음). 실패 문구가 「전부 반영되거나 전부 안 되거나 둘 중 하나입니다」라고 **단정**하므로 이 보장이 깨지면 화면이 거짓말을 한다.
- **서버가 다시 검사한다** — 화면의 `parse-manual-list.ts` 와 **같은 규칙**(§2.6.2)을 서버도 적용한다. 화면 검사를 신뢰하지 않는다.
- **멱등성**: `baseVersion` 이 현재 버전과 다르면 409. 같은 본문을 두 번 보내면 두 번째는 409 다 → 같은 교체가 두 벌 이력에 남지 않는다.
- `symbols` 길이 상한을 둔다(권고 **500**) — 붙여넣기 사고로 수만 줄이 들어오는 것을 막는다. 넘으면 400.
- `symbols: []`(빈 목록)은 **허용**한다 — 화면이 확인 시트에서 그 결과를 말하고 버튼 글자를 바꾼 뒤 보낸 요청이다(D: 금지하지 않되 경고).
- **저장 전 직전 목록을 이력에 남긴다**(§5.1) — 꼬리말의 「되돌릴 수 있습니다」가 성립하려면 필수다.

## 6. D6 — 기존 「동적 종목 선별 (Universe)」 문구 정정

### 6.1 확인 결과 — **이 스위치는 아무 동작도 바꾸지 않는다** [확실]

Leader 조건대로 코드를 읽어 확인했다. 근거 4개:

1. **쓰는 곳이 둘뿐이다.** `strategy_universe_enabled`(그리고 폴백 env `UNIVERSE_ENABLED`)를 저장소 전체에서 찾으면 **`src/app/api/settings/safety/route.ts:66`(읽어서 화면에 돌려주기)와 `:195`(화면에서 저장하기)뿐**이다. `.env.example:109` 에 선언만 있다.
   ```
   $ grep -rn "UNIVERSE_ENABLED|strategy_universe_enabled" . (node_modules·.git·.next 제외)
   src/app/api/settings/safety/route.ts:66   ← 읽기(화면 표시용)
   src/app/api/settings/safety/route.ts:195  ← 쓰기(키 이름 표)
   .env.example:109                          ← 선언
   ```
   **전략·시그널·universe 산출 코드에 읽는 곳이 0건이다.**
2. **동적 선별은 스위치와 무관하게 늘 돈다.** `refreshUniverse(market, force)` 가 `runEngine` 안에서 **조건 없이** 호출된다(`src/lib/strategy/engine.ts:1353`). 앞에 있는 유일한 관문은 `engine_disabled`(분석가 스위치)다.
3. **숫자도 틀렸다.** 현재 문구는 「거래대금 상위 **20**개 중 전략별 최적 **3**종목」인데, 후보 풀은 `UNIVERSE_TOP_N = 150`(`universe.ts:15`)이고 전략별 선별 수는 **30·40·30**(`engine.ts:426~428`)이다.
4. **OFF 문구는 코인 시절 문장이다.** 「전략에 하드코딩된 종목 사용 (BTC, ETH)」 — 이 앱은 주식이고, OFF 로 해도 **아무 일도 일어나지 않는다**.

추가 사실(해외 쪽) — `universe.ts:219~226`: 해외는 KIS 시총 랭킹 API 가 없어 **`getStaticOverseasUniverse()` 를 받아 거래대금으로 정렬**한다. 즉 **해외의 「동적 선별」은 T-143 이 교체하려는 바로 그 목록을 정렬하는 일**이다.

### 6.2 정정 문구 — 토글·동작·저장 흐름은 그대로

`src/app/settings/SettingsPage.tsx` **866~869행**만 바꾼다.

| 자리 | 지금 | 정정 |
|---|---|---|
| 제목(866행) | `동적 종목 선별 (Universe)` | **그대로** |
| 설명(868행 ON) | `거래대금 상위 20개 중 전략별 최적 3종목 자동 선별` | **ON·OFF 같은 한 문구**로 바꾼다 ↓ |
| 설명(868행 OFF) | `전략에 하드코딩된 종목 사용 (BTC, ETH)` | 〃 |
| `ON`/`OFF` 글자(874~875행) · `Toggle`(877~881행) | — | **그대로** (값은 저장되고, 저장 흐름도 그대로) |

**정정 문구(권고)** — `safety?.universeEnabled` 삼항 분기를 없애고 한 문장을 둔다:

```
거래대금 상위에서 전략별로 자동 선별 — 이 스위치는 켜고 꺼도 동작이 바뀌지 않습니다
```

- **이 문구가 §6.1 의 동작과 맞는 이유**: 앞 절은 ②·③ 의 사실(선별은 늘 돌고, 숫자는 150→30/40/30)을 **숫자를 빼고** 말한다 — 숫자를 넣으면 그 숫자가 또 드리프트한다(지금 문구가 그래서 틀렸다). 뒷 절은 ① 의 사실을 그대로 말한다.
- **숫자를 쓰지 않는 이유**를 코드 주석으로 남긴다: 「150·30/40/30 은 `universe.ts`·`engine.ts` 상수라 여기 적으면 또 어긋난다」.
- 「(BTC, ETH)」·「상위 20개」·「최적 3종목」 — **세 문자열을 저장소에서 지운다.**

### 6.3 ⚠ 이 정정으로 **해결되지 않는 것** — Leader 판단 필요

문구를 사실대로 고치면 **「아무 동작도 바꾸지 않는다」고 스스로 말하는 토글**이 남는다. 그것은 문구 문제가 아니라 **그 조작이 거기 있다는 것 자체가 결함**이다. 데모는 이 행의 설명을 「D6 에서 결정합니다」라는 자리표시자로만 그렸으므로 **최종 모양이 승인 데모에 없다.**

- 이 가이드는 **승인 범위(문구만)**를 넘지 않는다 → 위 문구까지만 적용한다.
- 토글을 없애거나 읽기 전용 줄로 바꾸는 것은 **화면 구조 변경**이라 **v2 데모가 필요하다** → §11 **L-2**.

## 7. 텔레그램·알림 (D2·D3)

### 7.1 보내는 조건 — T-125 재발 방지

- **변경 제안이 새로 생겼을 때만 1회.** 보류·무시한 제안은 다시 알리지 않고, 「확인할 변경 없음」은 **아무 알림도 내지 않는다**(데모 §2 머리글). 분석일마다 「뉴스 0건」이 반복된 T-125 와 같은 소음을 만들지 않는다.
- 같은 제안이 두 번 알림을 내지 않으려면 **「알렸음」 표시가 제안에 남아야 한다**(§5.2 의 상태와 별개 — 발송 기록).

### 7.2 메시지 (데모 §2 A 말풍선 그대로)

머리 `📋 해외 분석 대상 — 변경 제안 N건` → 제안마다 번호 · 종목 · 종류 / `근거` / `권고` / (보유면) `⚠ 보유 중 N주` → 꼬리 3줄:

```
수동 98종목 · 다 반영하면 97
수동 갱신 2025-12-19 (349일 전)
⚠ 12월 정기 재구성은 공시에 안 나옵니다 — 12-19 에 목록을 직접 확인하세요
```

- **버튼은 링크 1개뿐**(D3=A). 기존 패턴을 그대로 쓴다 — `[{ text: '🔗 앱에서 자세히', url: appUrl }]` 이고 `app_public_url` 이 `/^https:\/\/[^\s]+$/i` 를 통과할 때만 붙인다(`src/lib/signals/approval-message.ts:183·285` [확실]). **url 은 제안 탭 주소**(`{app_public_url}/settings/overseas-universe?tab=proposals`).
- 데모 말풍선의 버튼 글자는 「🔗 앱에서 확인」인데 **코드의 기존 글자는 「🔗 앱에서 자세히」**다 → §11 **L-1**(기존 글자 권고).
- **조작 버튼(`[빼기]`·`[보류]`)을 만들지 않는다** — `telegram-poller` 의 콜백 처리에 이 제안을 넣지 않는다.
- HTML 이스케이프는 기존 `src/lib/notify/escape.ts` 를 쓴다(종목 이름·근거 원문이 들어간다).

### 7.3 알림 스위치

- 설정 › **알람** 섹션에 토글 1개 추가 — 기존 4개(`자동 제출 알람`·`승인 요청 알람`·`진입 감시 발동 알람`·`수동 시나리오 등록 알람`, `SettingsPage.tsx:937~969`)와 **같은 모양·같은 저장 흐름**(`notifySignal.*` 과 나란히). 이름: **`해외 분석 대상 변경 알림`**.
- ⚠ **이 토글은 `src/app/api/settings/safety/route.ts` 를 고쳐야 한다 — `SAFETY_PATHS` 대상이다.** Reviewer 판정 줄(`scope: src/app/api/settings/safety/`)이 필요하고, 화면 커밋과 **섞지 않는다**(§8.1 WP-B5).
- 꺼져 있으면 텔레그램만 멈춘다. **홈 「확인 필요」 줄은 토글과 무관하게 늘 나온다**(D2 — A 는 「텔레그램 *추가*」다).

## 9. 접근성·모바일 요구

### 9.1 모바일

- **360px·412px 에서 가로 스크롤·잘림 0건.** 유일한 가로 스크롤은 목록 탭 출처 칩 줄(의도 — `overflow-x: auto`, 양 끝 여백 16px).
- 누르는 것 전부 **44px↑**, 목록·설정 행 **56px**. 제안 카드 버튼은 360px 에서 주 행동이 **한 줄 전체**, 「보류/무시」가 반씩(데모 「모바일 확인」 2번).
- 글자: 본문 13px · 숫자 14~18px · 레이블 11~12px. **11px 미만 금지.**
- **세로 스크롤은 화면당 1곳.** 시트는 내용이 길어지면 시트 안에서만 스크롤(`max-height`). 일괄 교체를 서브 라우트로 둔 이유도 이것이다(§1.1).
- `env(safe-area-inset-bottom)` 을 시트 하단 여백에 반영. 이 화면에는 하단 탭이 없다(설정 서브 화면) — `--nav-h` 여백을 넣지 않는다.
- `@media (min-width: 900px)`: 시트가 가운데 대화상자(최대 520px — `Sheet` 가 이미 그렇게 한다). **1280px 에서 폭 720px 중앙 고정**, 데스크톱 전용 2열 레이아웃은 만들지 않는다.
- textarea 는 `font-size: 16px` 이상으로 둬 iOS 자동 확대를 막는다(모바일 폼 관습) — 모바일 글자 크기 규칙과 충돌하지 않는 유일한 예외다.

### 9.2 접근성

- 탭 = `SegmentControl`(`role="group"` + `aria-pressed`, §2.3 선언). 출처 걸러보기 = `aria-pressed`.
- 시트 = `Sheet`(`role="dialog"`·`aria-modal`·`aria-labelledby`·첫 포커스·Tab 가두기·**배경 `inert`**·Esc·포커스 복귀). **데모에 없던 `inert` 는 이 부품이 이미 한다** — 직접 구현하지 않는다(자체 점검 Minor 해소).
- 저장 결과: 성공 `role="status"`, 실패 `role="alert"`. **409(이미 처리됨)는 `role="status"`** — 오류가 아니다.
- 로딩 영역 `aria-busy="true"`. 뼈대는 `prefers-reduced-motion: reduce` 에서 **깜빡임을 끈다**.
- **색만으로 상태를 말하지 않는다** — 출처는 글자(수동·자동·즐겨찾기·보유), 대조는 기호(`+`·`−`·`!`·`=`) + 글자(넣기·빼기·형식 오류·중복). 기호 글리프는 `aria-hidden`(옆 글자가 뜻을 말한다 — `CheckRow` 규칙).
- 포커스 링은 브라우저 기본 `:focus-visible` 을 지우지 않는다.
- textarea 에 `aria-describedby` 로 형식 안내를 잇는다. 대조 결과가 갱신되면 그 영역이 `role="status"` 로 읽힌다.

### 9.3 색

- **`--up`(빨강)·`--down`(파랑)을 쓰지 않는다.** 이 앱의 빨강·파랑은 **상승·하락**이라 「목록에 넣기」에 빨강을 쓰면 「오른다」로 읽힌다(데모 §3 주의).
- 강조는 `--accent`, 위험·실패는 `--danger`, 성공은 `--ok`, 경고는 `--warn`. 다크 명암비 ≥ 4.5:1.

### B.3 ③-1 (medium-2) — 갈라진 두 경우의 문장

**규칙: 「목록은 바뀌지 않았습니다」는 쓰기 자체가 실패한 경우에만 쓴다.** 저장이 끝난 뒤 조회만 실패한 경우에 그 말을 쓰면 **화면이 거짓말을 하고, 사용자가 같은 저장을 다시 눌러** 409(또는 두 벌 이력)로 간다.

| 경우 | 트리거 | **최종 문장** | 표시 |
|---|---|---|---|
| **A. 저장 실패**(아무것도 안 바뀜) | 4xx·5xx 또는 `data.applied` 없음 | **지금 그대로** — `BULK_FAIL_TEXT` / `PROPOSAL_FAILED_TEXT` | `role="alert"` · 실패 꼴(`ops.e` / `.rl.bad`) |
| **B. 저장은 됐고 화면만 못 불러옴** — 일괄 교체 | `ok` + `data.applied` 있음 + **`data.summary == null`** | **`바꿨습니다 — 수동 목록 {새}종목 (넣기 {N} · 빼기 {N}). 저장은 끝났고 변경 이력에 남았습니다. 다만 바뀐 목록을 다시 불러오지 못했습니다 — 다시 저장하지 않아도 됩니다. 「해외 분석 대상」으로 돌아가 숫자를 확인하세요.`** | `role="status"` · **중립 꼴**(`ops.res` 만, `ops.ok`·`ops.e` 둘 다 안 붙인다) |
| **C. 저장은 됐고 화면만 못 불러옴** — 제안 1건 | 같은 조건 | 카드 결과 줄을 `{p.doneText} · ` + **`저장은 끝났습니다. 다만 바뀐 수를 다시 불러오지 못해 위 칸의 숫자는 아직 옛 값입니다 — 다시 누르지 않아도 됩니다. 화면을 새로 열면 최신 상태가 보입니다.`** | `role="status"` · **중립 꼴**(`.rl` 만, `.ok` 안 붙인다) |

- **「다시 저장을 눌러야 하는가」가 두 문장의 갈림길이다** — A 는 「잠시 뒤 다시 해 보세요」, B·C 는 「다시 하지 않아도 된다」. 이 한 마디가 서로 바뀌면 안 된다.
- **B 가 숫자를 말해도 되는 근거** [확실]: `diff.next`(보낸 목록)와 `data.applied`(서버가 확정한 넣기·빼기)는 **읽기 실패와 무관하게 사실**이다. 못 믿을 것은 **화면 위쪽 요약 숫자**뿐이므로 거기만 「옛 값」이라고 말한다. 일괄 교체 화면에는 머리 칸이 없어 **「해외 분석 대상으로 돌아가 확인」**으로, 제안 카드는 같은 화면에 칸이 있어 **「위 칸의 숫자」**로 가리킨다.

#### B.4.2 최종 문장 — **한 상수로 묶어 세 곳이 어긋나지 못하게**

> **`다음 차례에 도는 분석·수집 작업부터 쓰입니다 — 「해외 장마감 분석」은 다음 아침, 해외장이 열려 있으면 「장중 전략 평가」가 그보다 먼저일 수 있습니다.`**

- 작업 이름은 **앱이 이미 쓰는 말**이다(`JOB_NAME_KO` — 「해외 장마감 분석」·「장중 전략 평가」). 새 말을 만들지 않는다.
- 「분석·**수집** 작업」이라고 적는 이유: 공시·재무 수집도 같은 목록을 읽는다(B.4.1). 「분석부터」라고만 쓰면 **덜 말한 것**이 된다.
- 들어가는 곳 **3곳**(지금 「다음 「해외 장마감 분석」부터 쓰입니다/반영됩니다」가 박혀 있는 자리). **같은 상수를 참조**하게 해서 한 곳만 고쳐지는 일을 막는다:

| 상수 (`view.ts`) | 지금 끝부분 | 정정 |
|---|---|---|
| `SHEET_TAIL`(`:100`) | `… 다음 「해외 장마감 분석」부터 쓰입니다.` | `주문이 아닙니다 — 실거래여부·모든거래차단과 무관하고, 이미 만든 시그널·보유 종목에도 영향이 없습니다. ` + **위 문장** |
| `PROPOSAL_DONE_TAIL`(`:111`) | `다음 「해외 장마감 분석」부터 반영됩니다. 이미 만든 …` | **위 문장** + ` 이미 만든 시그널·보유 종목에는 영향 없습니다.` |
| `bulkSuccessText()`(`:194`) | `… 변경 이력에 남았습니다. 다음 「해외 장마감 분석」부터 반영됩니다.` | `바꿨습니다 — 수동 목록 {N}종목 (넣기 {N} · 빼기 {N}). 변경 이력에 남았습니다. ` + **위 문장** |

- `BULK_SHEET_TAIL`(`:107`)은 `SHEET_TAIL` 을 이어 쓰므로 **자동으로 따라간다** — 「직전 목록이 변경 이력에 남습니다」(L-4 로 낮춘 문구)는 **그대로 둔다.**
- **「반영됩니다」와 「쓰입니다」를 섞지 않는다** — 상수 하나이므로 동사도 하나(`쓰입니다`)다.
