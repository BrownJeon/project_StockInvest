# StockInvest 통합 작업절차서 — 수익 엔진·계좌 운용 개편

> **이 문서가 앞으로의 작업 순서·정책 충돌 해소·승급 조건의 단일 실행 정본이다.** T-064의 연구·검증 설계와 T-077의 최신 계좌 운용 개편안을 합쳤다. 기존 문서는 상세 근거와 변경 이력으로 보존한다. 두 문서의 Phase/A 단계를 따로 실행하지 않는다.
>
> 정책 근거: [사용자 인터뷰](../../agent-vault/10-Flow/handoffs/2026-10-23-project-direction-interview.md). 상세 설계: [T-064](../../agent-vault/10-Flow/tasks/T-064-profit-engine-design.md), [T-077 본문](2026-10-24-portfolio-restructure-plan.md). 통합 작업 이력: [T-078](../../agent-vault/10-Flow/tasks/T-078-integrated-execution-procedure.md).
>
> 이번 완료 범위는 문서 통합이다. 구현·운영 DB/설정·주문/취소·알림·커밋/push·배포를 실행하지 않았다. 새로운 수익성·매매 권한을 문서 통합만으로 승인하지 않는다.

## 1. 통합 목적과 정본 관리

목표는 **비용 후 실제 순손익과 자산 증가 가능성을 검증하고, 합의한 위험·권한 안에서 계좌를 관리하는 것**이다. 추천 수·분석 점수·승인율·거래 횟수를 수익의 대리 목표로 삼지 않는다.

- **T-064에서 유지:** 일봉/시점 데이터, 동일 신호 함수, 체결/비용 모델, 가설 사전 등록, 과적합 통제, OOS·전진 모의, 실패·중단 기준과 주간 원인 리포트.
- **T-077에서 유지:** 현재 자본·시장 구획, 기존 보유 관리, 공동 예산/슬롯·매도 수량 선점, 분석 점수, 월 손실 재평가, 3개월 연장 승인/재알림, 안전·권한 경계.
- **실행 순서:** 이 문서 S00~S09만 사용한다. 옛 Phase 0~4와 A0~A7은 §4 대응표로 참조한다.
- **진행 상황:** §6 실행 원장과 실제 구현 task를 갱신한다. T-064와 T-077의 옛 표를 별도 일정표로 운영하지 않는다.
- 최신 사용자 정책이 충돌하는 과거 제안을 대체한다. 기존 안전·검증·인증 장치를 최신 정책이라는 이름으로 해제하지 않는다.
- 구현 과정의 새 결정을 이 문서에 근거·날짜·적용 버전으로 기록한다. 승인된 정책과 연구용 가정을 구분하며 원본 인터뷰 발언을 소급 변경하지 않는다.

## 5. 두 경로와 통과 조건

**공통 기반:** S00 이후 S01(장부/자원 의미)과 S02(자료/품질)는 독립 범위를 병행할 수 있다. S03의 정책 계약을 먼저 만들고, 파일 소유가 겹치면 순차로 진행한다.

**신규 매수 경로 N:** S02→S03→S04의 과거/OOS 검증 후 S05/S06과 연결한 S08 전진 모의→신규 매수용 S09 통과 순서다. 과거 재현 불가능한 추가 분석 계층은 아래 관측 입장 조건에 따라 주문 없는 전진 관측부터 할 수 있지만 G-N 합격으로 취급하지 않는다. 연구의 최소 모의 allocator·보유 정책 함수는 S03에서 만들어 전체 정책을 시험하며, 복잡한 운영 저장/화면 전체를 먼저 완성할 필요는 없다.

**기존 보유 관리 경로 H:** S01/S02/S03의 보유 기준을 바탕으로 S05의 과매도 방지, S06의 보유 제어, 필요한 S07 화면, S08의 재생/섀도우와 운영 대사를 거쳐 보유 관리용 S09를 따로 판단할 수 있다. 신규 매수 알파 전략 합격이나 8주 매수 페이퍼를 기다려야만 기존 보유를 점검·관리할 수 있는 구조로 만들지 않는다.

| G-H 보유 관리 전환 | 승인된 보유 정책, 최신 수량/원가·분석, 점수/축소량 검증, 공통 매도 선점·취소/대사, 재생/섀도우, Reviewer/QA·운영 승인 | 매도는 T-072 매수 검증 대상이 아니라는 이유로 검토 생략, 신규 매수 허용, 임의 청산·기존 exit-engine 무조건 ON |
| G-N 신규 매수 전환 | 고정된 전체 정책 버전, S04 합격 근거, S08 전진/체결·비용 정합, T-072 전략 귀속/검증 상태와 별도 단계 승인, 자금/슬롯 계약 | 점수·사용자 일반 승인·기간 경과로 미검증 전략 매수, paper 상태명만으로 증거 생략 |

**주문 없는 S08 관측 입장과 G-N은 다르다.** 후향 재현 가능한 부분의 S04 판정/한계를 기록하고, 과거 검증 불가능한 계층·잠근 전체 버전·전진 가설/표본·합격/중단 기준을 등록하면 그 미검증 버전도 섀도우 관측에 넣을 수 있다. 이 경우 실제 주문 경로는 열리지 않는다. G-N은 최종 전체 정책에서 필요한 과거/전진 증거가 모두 충족된 범위만 통과하며 기반 기술전략의 합격을 추가 LLM/점수 계층 전체의 합격으로 확대하지 않는다.

H도 검증 없는 매도를 허용하지 않는다. 보유 분석·모의/제안·실제 자동 매도를 구분하고 승인된 범위 안에서만 전환한다. 어느 경로든 Kill Switch·기존 안전장치·인증·모든 주문의 `submitOrder()` 경유 원칙을 지킨다.

## 6. 실행 원장과 단계별 절차

현재 통합 절차의 **시작 상태는 S00 대기**다. 각 기존 task의 일부 구현은 존재하지만 통합 단계 전체가 완료된 것은 아니다. Claude는 아래 각 단계에 `실제 task ID / 담당·파일 소유 / 상태 / 근거 링크·버전 / 미해결 / 다음 작업`을 기록하고 실제 완료 기준을 채웠을 때만 완료로 바꾼다.

> **원장 위치 (2026-10-25, T-079):** 위 기록은 [단일 실행 원장](2026-10-24-execution-ledger.md) v1 에 있다. S00 기준선은 [S00 보고서](2026-10-24-s00-baseline-report.md). 진행 상태는 그 원장만 갱신한다. **S00 은 2026-10-25 에 완료(문서 범위)되었으므로 위 "시작 상태는 S00 대기" 문구는 낡았다 — 현재 상태는 원장 §1.**

### S00 — 최신 현황과 정책 기준 고정

- **입력:** 이 절차서, 최신 인터뷰, ACTIVE/board, 현재 HEAD/dirty diff, 관련 task.
- **수행:** 코드·배포·DB 스키마·안전/검증 설정과 최신 보유/시장 자금·미체결·원가/현금 의미를 허용된 읽기 전용 범위에서 대조한다. 해당 카드/매수 경로의 봉 주기(F03)·시장별 비용 가드(F05)·주문 정밀도(F12/D20)도 현재 구현으로 확인하며 과거 지적이 지금도 미수정이라고 단정하지 않는다. 권한이 필요하면 구체 범위를 제시한다. 과거5종목/다른 기록3종목을 현재 사실로 합치지 않는다.
- **산출물:** 정책/현재 구현/차이 표, 기존 task 완료 증거와 잔여 작업표, 최신 계좌 대사·미확정 항목, 파일 소유·작업 순서·결정 목록의 버전.
- **완료:** 현재 금액·구획·안전 상태의 근거/시점이 있거나 미확정으로 명시되어 있고 이미 구현한 것과 새 작업이 구분됨. 민감 상세는 git 제외 로컬 보고서에, 비밀·계좌번호는 문서에 쓰지 않음.
- **보류:** 불명 자금으로 새 예산 확정 금지. 미정 금액이 있다고 읽기/모의 설계 전체를 중단하지 않음.

### S01 — 측정·장부·자원 기반

- **입력:** S00 대사, T-071/T-074/T-076의 실제 잔여 범위.
- **수행:** 누적 실제 체결수량·체결가·USD/KRW·추정/실제 비용·이월원가·입출금/환전·외부 수동 보유를 분리한다. 부분체결·결과 불명·취소 요청/확정 상태를 유지한다.
- **산출물:** 계좌 원장과 앱 거래 원장 대사, 원가 미상 규칙, 비용/자금 필드 계약, 관련 회귀 시험. T-074 기준 정하기와 거래 원가 복구를 같은 완료로 세지 않음.
- **완료:** 매도대금 전체 이익화·입금 수익화·통화 혼용 없이 설명 가능하고 미확정은 가짜0이 아니라 상태로 표시됨. 부분체결/재시작/취소 대사에서 장부를 잃지 않음.
- **보류:** 잘못된 실제 손익으로 새 전략을 학습·합격시키지 않음. 격리된 일봉 연구/사후검증은 별도 진행 가능.

### S02 — 일봉·사건·후보군과 사후검증

- **입력:** T-070/059 등의 기존 수집기와 공식 원천, U05의 운용 범위.
- **수행:** 시장/통화·현지 거래일·확정봉·수정/원주가·공개/수집 시점을 보존한다. 누락·중복·역순·기업행위·조정 변경을 점검하고 의심행 재확인/재수집 후 복귀시킨다. 단순 제외로 승자/상폐 편향을 숨기지 않는다.
- **후보군:** 정적50은 파이프라인 시험용. 실제 후보는 확정한 Nasdaq100/코스닥100 등의 원천·효력일·편출/상폐 이력으로 버전 관리한다. NYSE50을 확정 편입으로 미리 세지 않는다. ≥150 연구안 때문에 매수 범위를 자동 확대하지 않는다.
- **실행:** 기존 KIS 스로틀·토큰 공유, 낮은 우선순위·재개 가능한 백필, 장 마감/확정 시점·DST·반일장 계약. 무거운 백필/백테스트로 진입·보유 감시를 지연시키지 않는다. 오프라인 러너와 공유 DB 부하 제한을 유지한다.
- **사후검증:** 과거 조건부 추천·미체결·만료·미배정도 원문/조건 충족·실행 가능 시각·비용·D+1/3/5/10 등의 고정 관측으로 평가한다. 추천 후3일 하락 기억은 근거를 찾으며 낙폭을 추정하지 않는다.
- **완료:** 품질/커버리지·시점 확보·편향 한계와 자료로 가능한 검증 범위가 보고됨. 기존 95% 커버리지 등 수치는 연구 등록 때 적용 범위를 확정한다. 과거 PIT를 복원 못한 구간은 합격 증거에서 한계를 명시.

### S03 — 순수 결정 함수와 실험 계약

- **입력:** 확정 정책·자료 계약·S01 비용, 최소 모의 보유/자원 상태.
- **수행:** 동일 순수 신호/정책 함수를 백테스트와 실제 판단 경로가 공유하도록 설계한다. 1h를1d로 바꾸면 별도 전략/검증 버전이다. 전체 정책의 후보군·자료 시점·신호·점수·배분·보유/매도·비용/체결 모델 해시를 남긴다.
- **분석:** 출처·공개 시점·사실/해석·가설·무효 조건·근거 충족도·다음 점검을 구조화한다. LLM은 사실/사건 해석을 보조하고 자금·승인·기간을 변경하지 못한다. 매수 우선순위/보유 매력도/축소 우선순위/자료 충족도를 분리한다.
- **연구:** H1 눌림목, H2 수축 돌파, H3 모멘텀 로테이션, H4 급등 후 수렴 대조군, H5 신고가 추세는 후보 묶음이다. 전부 구현을 의무화하지 않고 먼저 검증할 최소 가설과 대조군을 등록한다.
- **산출물:** 가설·파라미터 그리드·비용/체결·순위/배분·월/기한 관리·비교 기준·합격/중단 기준·종료일·전체 시행 기록의 사전 등록 파일, 동일 코드 경계와 순수 함수 시험.
- **완료:** 임의 AI 자신감을 승률/투자 비율로 쓰지 않고 과거 시점 자료로 재생 가능하며, 신호 TTL은3개월 보유와 분리됨. 아직 확정되지 않은 값은 모의 초안으로만 사용.

### S04 — 후향·표본 외 판정

- **입력:** S02의 시점/편향 범위와 잠근 S03 실험 계약.
- **수행:** §7의 체결/비용·과적합·벤치마크 계약을 적용한다. IS에서만 설계/고원 선택 후 잠근 OOS와 시간순 워크포워드를 평가한다. OOS를 보고 같은 구간으로 재튜닝·재합격시키지 않는다.
- **산출물:** 모든 시행/탈락·순기대값과 불확실성·일별 평가자산 낙폭·손익 집중·실행/미체결·비용 민감도·시장 구간·자료 한계 보고서, 합격/불합격/증거 부족 구분.
- **완료:** 등록한 판정 기준으로 결과를 재현할 수 있음. 현 시점 LLM 지식으로 과거 뉴스/재무를 만들어 낸 검증은 인정하지 않음. 과거 검증 불가능한 점수/사건 계층은 미검증 범위로 남기고 전진 증거를 별도로 확보함.
- **중단:** 후보 전부 실패하면 기술적 엣지 없음/이번 표본에서 증거 없음으로 보고. 현금·단순 보유·대체 방식은 비교/사용자 결정으로 제시하며 ETF 코어 매수로 자동 전환하지 않음. 연구 종료일에 실패/자료 부족을 보고하고 자동으로 기간만 늘리지 않음.

### S05 — 공동 자원과 실제 주문 경계

- **선행:** S01 자금 필드/수량 의미와 S03 자원 계약. H 경로는 신규 매수 S04 합격과 독립적으로 설계·구현/격리 검증 가능. 신규 매수 연결은 G-N을 충족하기 전 섀도우다.
- **수행:** §8.1의 모든 경로 공동 배분·예산/슬롯/매도 수량 예약, 송신 전 재확인, durable intent·결과 불명·부분체결/취소 정산을 구현한다. T-071/072의 보호를 재사용한다.
- **카드/매수 선결 시험:** 실제 입력 봉 주기와 전략 가설 일치, 시장별 비용·가격 단위/정밀도 일치, 목표 수익이 비용 이하인 후보의 거부를 확인한다. AI 점수/자신감이 비용 가드를 우회하지 못하게 한다. 비용/목표가 불명인 경우의 적격성도 명시해 시험한다.
- **완료:** 동시3개 전액 요청, 두 시장 마지막 슬롯, 수동/자동/시나리오/카드/분할, 동시 매도·재시작/응답 유실을 시험해 한도·수량·멱등성 보존. 브로커와 DB의 완전 원자성을 가정하지 않음.
- **산출물:** 관련 task·변경 scope·격리 시험 결과·대사/복구·롤백 계획. 주문 경로는 `submitOrder()`를 거치고 취소는 검증된 기존 경로를 보완한다.

### S06 — 보유·월 손실·기간과 승인 제어

- **선행:** S01·S03·S05 계약. 새 전략 알파 합격을 보유 분석의 선행 조건으로 삼지 않음.
- **수행:** §8.2의 월 손실 재평가·점수 축소·기한 보존·직접 연장 승인·미응답 재알림을 섀도우부터 구현한다. 전략 매수 판단과 보유 판단이 같은 최신 가설/정책 버전을 공유하게 한다.
- **완료:** 월 -5% 사건과 적격 신규 매수 공존, ETF 집중 노출, 축소 후 순위 갱신,3개월/말일/추가매수, 미응답/오래된 버튼/중복 승인/알림 실패/재시작에서 정책 보존. 자동승인·미응답 청산·과매도 없음.
- **산출물:** 보유 상태 전이·기산일/연장/재알림 정책안·권한/전달 이력·재생/섀도우 결과. 미정 투자 기준은 실제 운용 전에 결정.

### S07 — 최소 화면과 리포트

- **선행:** S03 정책/표시 계약. 필요한 데모는 다른 연구와 병행 가능하나 Designer→사용자 승인 후 구현.
- **수행:** T-073 등을 재사용해 시장별 가용/예약·오늘 행동/관망 근거·보유 만료/승인·실제/모의 성과와 불명 상태를 표시한다. 412px 모바일·900px 데스크톱·하단5탭·한국 색상·lightweight-charts 유지.
- **완료:** 화면 금액/상태가 원장·예약·승인/검증 상태와 맞고, 미검증 예측 확률이나 합성 성과를 실제 수익처럼 보이지 않음. 필요한 핵심 승인/조작 경로는 운영 전 검증.
- **주의:** 장식적 화면 완성을 OOS의 선행 조건으로 삼지 않는다. 정확한 지표 정의는 선행이고 대시보드 미관은 별도다.

### S08 — 전진 모의·결합 검증·주간 판단

- 월 지표는 실현/평가·원통화/환율·비용·외부 입출금과 경계를 명시한다. T-074 누적 성과를 월 지표로 이름만 바꾸지 않는다. 금액식 `E_now-E_start-외부순입금`과 수익률 분모/시점 방법을 대사하고 결측/분모 오류는 불명 상태로 표시한다.
- 유효 월 수익률 -5% 이하이면 재평가 사건을 남긴다. 조정 필요/지표 악화에 대응하되 월 손실만으로 신규 매수를 전면 차단하지 않는다. 기존24h Kill Switch는 별도 유지한다.
- 신규 최초 실제 체결일 기산, 달력3개월, 기존 보유의 편입 기준일은 검토할 전환안이다. 추가매수/일부매도로 최초 기한을 무한 리셋하지 않는다. 과거 취득일/처음 관측일/새 정책 편입일을 구분한다.
- 만료 시 재평가 후 필요한 매도·축소는 합의 범위 안에서 자동, 타당한 보유 연장은 분석 근거·제안 기간으로 직접 승인한다. 미응답은 보유/재알림 상태이며 기존 위험 점검·매도 기준을 계속 적용한다.
- 연장 요청은 주문 승인과 별도 유형이다. 계좌/계획·보유·평가/제안 버전·기간·인증/권한·CAS를 확인한다. 오래된 버튼이나 중복 클릭이 새 연장/주문을 만들지 않는다.
- 재알림 요청 상태·다음 시각·전달 이력은 영속화한다. 중요한 정보가 바뀌면 오래된 근거를 그대로 반복하지 않는다. 메모리 스로틀이나 deadline=NULL 단발 종료에만 의존하지 않는다. 횟수 초과를 자동승인/청산으로 바꾸지 않는다.
- 일반 종합 판단·긴급 안전 대응·전략 가격 청산의 충돌은 정책 적용 우선순위를 명시해 검토한다. 예전 청산 엔진을 켜는 것으로 새 관리 루프를 대체하지 않는다.

## 11. 각 작업의 완료·검토·보고 규칙

각 실제 구현 task에 다음을 남긴다.

1. 연결 S단계·H/N 적용 범위·목적과 수익/위험 경로·현재 정책 버전.
2. 기존 재사용·새 변경·파일 소유·비대상·선행 증거·미정 값·허용 권한.
3. Judge 접수 → 설계 C1 → Developer → 독립 Reviewer → Judge C2/필요 검토 → QA → 승인된 Deployer → 결과 보고. Codex 환경의 재귀 검토 예외는 기록하고 Claude에서 자동 면제로 쓰지 않음.
4. 실제 수용 시험·코드/데이터 해시·Reviewer의 해당 scope·확인 못 한 것·운영/롤백 조건.
5. 진행 원장 상태와 다음 한 작업. 과거 완료 문서의 Reviewer 판정을 새 안전 코드에 차용하지 않음.

새 환경/워크트리는 실제 `scripts/git-hooks/commit-msg`와 설치 절차를 확인한다. 안전 코드 독립 감사 없이 커밋하거나 에이전트가 `--no-verify`로 우회하지 않는다. 타 세션 변경을 보존하고 `git add -A`·reset/clean/stash 등 일괄 정리로 범위를 섞지 않는다.

이 문서의 **완료**는 통합 절차서 인수인계 완료다. 프로젝트 완료는 실제 계좌/장부·검증·자원/보유 정책·화면·승인된 운영 적용과 성과 측정까지 충족해야 한다. 합격 전략이 없다는 결론도 정직한 연구 결과이며, 수익률을 보장하지 않는다.
