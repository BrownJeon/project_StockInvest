## 1. SEC 원천 — NYSE 를 가려내는 방법과 규모

### 1.1 파일·필드 [확실]

- URL `https://www.sec.gov/files/company_tickers_exchange.json` — 이미 `SecClient`(`src/lib/data/us-edgar/sec-client.ts`) 가 쓰는 호스트. 선언 User-Agent(`SEC_USER_AGENT`, 연락 이메일 포함) 없으면 호출하지 않는다(클라이언트가 던진다). 간격 ≥250ms·429/403 쿨다운은 클라이언트가 맡는다.
- 모양 `{"fields":["cik","name","ticker","exchange"],"data":[[1045810,"NVIDIA CORP","NVDA","Nasdaq"],…]}`. **열 순서를 가정하지 말고 `fields` 의 이름으로 인덱스를 찾는다**(T-137 `parseSecResponse` 가 이미 그렇게 한다 — 그 함수 본문을 재사용).
- 2026-11-01 07:51Z 측정: **10,430행**. `exchange` 분포 `Nasdaq 4,357 · NYSE 3,269 · OTC 2,577 · CBOE 44 · TXSE 12 · null 171`. 같은 티커가 두 거래소에 중복 등재된 행 **0건**. 티커 문자는 전부 `[A-Z0-9-]`(점 0건).

### 1.2 NYSE 판정 규칙

```
nyse_rows = data.filter(row => row[exchange] === 'NYSE')          // 대소문자 그대로 정확 일치. 'NYSE American'·'NYSE Arca' 같은 별도 값은 존재하지 않는다(위 분포)
```

- `null`(171)·`OTC`·`CBOE`·`TXSE` 는 대상이 아니다. **TXSE 는 신규 거래소라 KIS 가 거래소 코드를 갖고 있지 않다**(`OverseasExchange = NAS|NYS|AMS`) — 예: `ET`(Energy Transfer) 가 TXSE 로 적혀 있다 [확실]. 수동 목록의 종목이 TXSE 로 바뀌면 §8 의 `otc_move`(거래 불가 이동) 와 같은 취급.
- **[확실] SEC 의 `NYSE` 값에는 NYSE Arca 상장 ETP 가 섞여 있다.** 예: BANK OF MONTREAL CIK 927971 아래 29개 티커(`FNGD`·`FNGU`·`BNKU`… ETN), UBS AG 12개(ETN), ProShares Trust II 12개(`AGQ`·`BOIL`… ETF), Teucrium 6개. 이름에 `FUND` 284 · `TRUST` 263 · `ACQUISITION`(SPAC) 118 · `ETF` 30. **그래서 SEC 만으로는 보통주를 가려낼 수 없고 §5 의 KIS 쪽 필터가 필수다.** [추측] NYSE American 종목도 `NYSE` 로 적혀 있을 수 있다(별도 값이 없다) — KIS 에는 `AMS` 라 `NYS` 로 조회하면 실패해 `kis_missing` 으로 센다(§5.4). 종목 마스터를 쓰면 이 구분이 정확해진다(§2.3).

### 1.3 사전 제거(KIS 호출 전) — 접미사 규칙 [확실, 2026-11-01 파일 기준 수치]

SEC 는 주식 종류를 하이픈 접미사로 적는다(`BRK-B`·`BAC-PL`·`KCAC-UN`). NYSE 3,269행 중 하이픈 530행, 접미사 분포 상위: `PA 73 · WT 60 · UN 50 · PB 46 · PC 42 · PD 32 · PE 25 · PF 19 · RI 18 · PG 17 · PH 17 · PK 14 · PL 13 · PI 13 · A 12 · PJ 11 · B 10 …`.

```
NONCOMMON_SUFFIX = /-(P[A-Z]?|WT[A-Z]?|UN|RI|WI|U|R|W|WS)$/     // 우선주·워런트·유닛·권리·when-issued
CLASS_SUFFIX     = /^[A-Z]{1,5}-[A-Z]$/                            // 보통주 클래스(A·B·C·V·K) — 유지
drop  = ticker matches NONCOMMON_SUFFIX                           → 506건 (exclusion='prefilter_noncommon', KIS 호출 안 함, 후보 표에 남겨 센다)
keep  = 하이픈 없음 2,739건 + CLASS_SUFFIX 24건                   → N = 2,763
```

클래스주 24건(전부 유지): `AGM-A AKO-A AKO-B BF-A BF-B BH-A BIO-B BRK-A BRK-B CIG-C CRD-A CRD-B GEF-B GTN-A HEI-A HVT-A LEN-B MKC-V MOG-A MOG-B PBR-A TAP-A UHAL-B WSO-B`. 사전 제거는 **보수적으로 접미사 2자 이상 `P`·`W`·`UN`·`RI` 계열만** 건다 — 한 글자 접미사는 전부 클래스주였다(`^[A-Z]{1,5}-[A-Z]$` 에 안 맞는 하이픈 티커 0건 [확실]). 이 규칙이 틀려 보통주를 떨어뜨리는 경우는 1회차 `counts_json.prefiltered_noncommon` 목록을 사람이 훑어 잡는다(506건, 접미사별 집계도 같이 저장).

### 1.4 같은 회사 여러 티커 — CIK 중복 [확실]

후보 2,763건의 CIK 는 2,572개, **86개 CIK 가 2개 이상의 후보**를 갖는다(초과 191행). 대부분 ETN 발행사(BMO·UBS)·베이비본드(`SOJC`·`DTW`·`AFGB`…)·클래스주(`BRK-A`/`BRK-B`, `BF-A`/`BF-B`). 처리는 §6.4 「CIK 당 1종목」.

## 2. 심볼 해석 — SEC 티커 → 내부 심볼 → KIS 요청 표기

### 2.1 내부 심볼 [확실]

- 내부 규약 `EXCD:TICKER`, 정규식 `/^[A-Z]{3}:[A-Z][A-Z0-9.]*$/`(`kis-symbols.ts:14`) — 클래스는 **점**(`NYS:BRK.B`). SEC `-` → 내부 `.` 변환은 이미 `toSecTicker`(`parse.ts:47~50`, 역방향 `.`/`/`→`-`)가 있으니 그 역을 쓴다: `internal = 'NYS:' + ticker.replace('-', '.')`.
- `symbol_cik_map` 도 같은 규약으로 쌓여 있다(`NYS:BRK.B` ↔ `sec_ticker BRK-B`, CIK 1067983) [확실 — 운영 SELECT].

### 2.2 KIS 요청 표기 — 점은 통하지 않는다

- **[확실]** `NYS:BRK.B` 는 11일 연속 KIS 현재가상세 실패(위 불편한 사실 1). `parseOverseas` 는 티커를 그대로 `SYMB` 에 넣는다(`kis-overseas.ts:getPriceDetail`).
- **[가능성 높음]** KIS 표기는 슬래시(`BRK/B`) — T-137 `selection.ts` 주석(「Nasdaq uses '/'」)과 KIS 샘플 저장소의 종목 마스터가 `symb` 열을 따로 둔 점으로 추론. **실측 없이는 단정하지 않는다.** 확정 방법 두 가지(둘 중 하나는 사용자 승인 뒤 developer 가 1회 실행):
  - (가) KIS 종목 마스터 `nysmst.cod` 의 `symb` 열에서 `BRK` 로 시작하는 행을 읽는다(§2.3 — API 호출 아님).
  - (나) `getPriceDetail('NYS:BRK/B')` 1회(실 KIS 호출 — 사용자 승인 사항, `withKisPriority('bulk')`).
- 설계 결정: **내부 심볼은 그대로 두고(`.`), KIS 요청 직전에만 표기를 바꾼다.** 바꾸는 곳은 어댑터(`kis-overseas.ts`/`kis-symbols.ts`, 🔴 `^src/lib/exchanges/` 가 `SAFETY_PATHS` 인지 훅 목록으로 확인할 것)가 아니라 **WP-A 모듈 안의 `kisSymbolFor(internal)`** 로 두고, 어댑터 수정은 별도 task 로 뺀다(기존 54종목 경로 영향 0). 후보 표에 `kis_symb` 를 저장해 요청에 쓴다.

### 2.3 KIS 종목 마스터 파일 — 표기·종류·DR 을 한 번에 [가능성 높음]

- 다운로드 `https://new.real.download.dws.co.kr/common/master/nysmst.cod.zip`(나스닥 `nasmst`, 아멕스 `amsmst`). **같은 호스트를 `src/lib/exchanges/kis-master.ts` 가 국내 마스터(`kospi_code.mst.zip`)에 이미 쓴다** [확실]. API 키·토큰·초당 한도와 무관한 정적 파일이다.
- 레이아웃 [가능성 높음 — KIS 샘플 `stocks_info/overseas_stock_code.py`·`해외종목코드정보(…).h` 를 2026-11-01 읽음, 파일 자체는 받지 않았다]: **탭 구분·cp949, 24열** — `ncod · exid · excd · exnm · symb(심볼) · rsym(실시간 심볼) · knam · enam · stis(1=Index·2=Stock·3=ETP·4=Warrant) · curr · zdiv · ztyp · base · bnit · anit · mstm · metm · isdr(DR 여부 Y/N) · drcd · icod · sjong · ttyp · etyp(001 ETF·002 ETN·003 ETC·004 Others·005 VIX ETF·006 VIX ETN) · ttyp_sb`. 헤더(.h)는 고정폭 char 배열로 선언돼 있어 **탭 구분인지 고정폭인지는 파일을 받아 확인해야 한다**(샘플 .py 는 `sep='\t'`).
- 용도: ① `symb` = KIS 요청 표기(§2.2 해결) ② `stis≠2`·`isdr=Y`·`etyp` 비어있지 않음 → 비보통주/DR 사전 제외(§5.2) ③ SEC NYSE 후보 중 KIS 가 **아예 취급하지 않는 종목**을 호출 전에 걸러 낭비 호출을 없앤다 ④ NYSE American 을 `amsmst` 로 구분.
- **v1 은 마스터 파일을 필수로 둔다**(없으면 run `failed`, 추측으로 요청하지 않는다). 이유: BRK.B 하나로도 상위 50 의 정확성이 깨지고, 마스터 없이는 2,763건 중 KIS 미취급 종목이 몇 건인지 알 수 없다. 마스터 파일 수집 모듈은 `kis-master.ts` 의 zip 해제·파싱 틀을 본떠 **새 파일**(`src/lib/universe/kis-overseas-master.ts`)로 둔다(기존 파일 수정 0).
- 선행 검증(developer, 코드 작성 전): zip 1회 다운로드 → 행 수·열 수 24·`symb` 에 `BRK/B`(또는 다른 표기) 존재·`stis` 분포·`isdr=Y` 건수·`etyp` 분포를 task 문서에 기록. **파일 다운로드는 사용자 승인 뒤**(외부 파일 수신 규칙).

## 3. 산출 파이프라인 — 단계·상태·재진입

한 달에 run 1개(`run_key = 'YYYY-MM'`, UNIQUE). 러너는 창 안에서 **매 틱** 라우트를 부르고, 라우트는 **한 번에 한 단계만, 100초 예산 안에서** 처리하고 돌아온다(`daily-bars` 의 `remaining` 이어받기와 같은 방식 [확실 — `daily-bars/route.ts` 머리 주석]).

```
phase:  listing ──→ scan ──(cursor = total)──→ retry ──→ finalize ──→ complete
                     ↑  (청크마다 cursor 전진, 유량 실패면 그 자리에서 멈추고 다음 틱)
         어느 단계든 치명 오류 → failed (last_error) · 창이 끝나도 complete 가 아니면 다음 주 일요일 창에서 이어감 · 다음 달 창 시작 전까지 못 끝내면 expired
```

### 3.1 공통 관문 (매 호출, 순서대로 — 앞이 막히면 뒤는 실행 안 함)

1. `checkCronAuth`(x-cron-secret, fail-closed) [확실 — 기존 함수].
2. 스위치 `system_config.overseas_universe_refresh.enabled === true` — **키 없음·해석 불가 = 꺼짐**(새 기능 = 꺼짐 규칙, `post_market_overseas_enabled` 와 같은 방향 [확실]). 꺼져 있으면 `{ ok:true, status:'disabled', final:true }` (외부 호출 0).
3. 표 존재(`overseas_universe_run`·`_candidate`·`_auto`) — 없으면 `{ ok:true, status:'tables_missing', final:true }`.
4. **휴장 관문**: `isUsRegularSessionOpen(now, closed) === false` **그리고** KST 요일이 설정의 `weekday`(기본 0=일) — `loadUsClosedDaysStrict` 는 표에 연도가 없으면 던지므로 **던지면 이 관문은 「열려 있을지 모름」으로 보고 호출을 거부**한다(`status:'calendar_unknown'`, final 아님). `market_holidays` 는 2025~2030 해외 행이 있다 [확실].
5. 창(`windowStart ≤ HH:MM < windowEnd`) 밖이면 `outside_window`(final 아님).
6. 프로세스 단일 실행(`running` 플래그 — `kis-fundamentals-snapshot.ts` 패턴) + **이달 run 이 `complete`/`failed`/`expired` 면 `skipped_month_done`(final:true)**.

### 3.2 `listing` 단계 (1회, 예상 5~20초)

```
sec   = SecClient.getJson(SEC_URL)                 // 200 아니면 run failed('sec_http_<code>')   (SEC 1회)
master= fetchNysMaster()                           // zip → rows; 실패면 run failed('master_unavailable')  (정적 파일 1회)
rows  = parseSecResponse(sec.json) where exchange==='NYSE'
INSERT run(run_key, phase='listing', top_n=cfg.topN, sec_sha256, sec_rows, master_sha256, started_at)
for (ord, row) in rows (SEC 순서 고정):
   internal = 'NYS:' + ticker.replace('-', '.')
   if NONCOMMON_SUFFIX.test(ticker)        → status 'excluded', exclusion 'prefilter_noncommon'
   else m = master.bySymbol(ticker 의 KIS 표기 후보들)   // 후보: ticker, ticker.replace('-', '/'), ticker.replace('-', '.')  — 마스터에 있는 것 하나
        if !m                                → 'excluded','master_missing'
        elif m.stis !== '2'                  → 'excluded','master_type'   (값 기록)
        elif m.isdr === 'Y' && cfg.excludeDr → 'excluded','master_dr'
        elif m.etyp                          → 'excluded','master_etp'    (값 기록)
        else                                 → 'pending', kis_symb=m.symb, kis_stis/isdr/etyp 저장
   INSERT candidate(run_id, ord, symbol=internal, sec_ticker, cik, sec_name, kis_*, status, exclusion)
UPDATE run phase='scan', cursor_pos=0
```

- 후보 INSERT 는 **한 트랜잭션**(2,763행, 수 초). 실패하면 run 을 만들지 않는다(다음 틱에 다시 `listing`).
- SEC·마스터 응답 본문은 저장하지 않는다(해시·행 수만). 1회차 검증용으로 서버 `~/.node-local/stockinvest/universe/<run_key>/` 에 원문 2개를 파일로 남긴다(선택 — 저장소·DB 아님).

### 3.3 `scan` 단계 (청크 반복)

```
budgetMs = 100_000; t0 = now
for cand in candidates WHERE status='pending' ORDER BY ord, 동시성 2 (bounded-fetch 재사용):
   if now - t0 ≥ budgetMs → break (cursor 저장, status 'scan_partial', final:false)
   try  d = withKisPriority('bulk', () => getPriceDetailBySymb(cand.kis_symb))     // §2.2 — 내부 심볼 아닌 KIS 표기로
        UPDATE candidate SET status='ok', tomv, shar, last_price, curr, etyp_nm, rsym=raw.rsym, fetched_at, attempts+1
   catch PriceDetailUnavailableError(판정 불가·빈 응답)   → status='kis_missing', error, attempts+1
   catch isKisThrottleFailure                             → attempts+1 그대로 'pending', **즉시 break**(증폭 방지 — snapshot 패턴), 응답 status 'throttled'
   catch 그 밖(네트워크·토큰)                             → status='kis_error', attempts+1 (retry 단계에서 1회 더)
cursor_pos = 처리한 마지막 ord
if 남은 pending == 0 → phase='retry'
```

- 동시성 2 로도 5 req/s 를 넘지 않는다(`kis-throttle` 가 전역 버킷이다 [확실]). 2 를 고른 근거: 직렬 실측 0.46~0.93 초/건은 KIS 왕복 지연이 지배하므로 2 병렬이면 ≈2배, 4 이상은 5 req/s 벽에 닿아 이득이 없다.
- 호출당 KIS 응답에서 **`tomv·shar·last·curr·etyp_nm·rsym` 원값만** 저장한다(`raw` 전체는 저장하지 않는다 — 2,700행 × JSON 은 불필요).
- `rsym` 은 참고용: `D` + `NYS` + 표기(T-137 `kis-validation` 의 기대 형식) 와 다르면 `cap_flag` 와 별개로 `rsym_mismatch` 를 센다. **run 을 실패시키지 않는다**(T-137 은 전부 일치 아니면 실패였다 — 월간 산출에서는 종목 단위 격리가 맞다).

### 3.4 `retry` 단계 (1회, ≤100초)

`kis_error` 이고 `attempts < 2` 인 것만 한 번 더. 끝나면 `finalize`.

### 3.5 `finalize` 단계 (1회, ≤20초, DB 트랜잭션 1개)

```
cands = status='ok' AND curr='USD' 인 후보
각 후보: (cap_used, cap_source, cap_ratio, cap_flag) = §6 규칙 ; etyp_nm 비NULL → excluded 'etp' ; cap_used NULL → excluded 'tomv_null' ; cap_used ≤ 0 or ≥ 2e13 → excluded 'implausible'
CIK 당 1종목: 같은 cik 중 cap_used 최대 1건만 남기고 나머지 excluded 'cik_dup' (§6.4)
정렬: cap_used DESC, symbol ASC  → rank_no 1..N (N = run.top_n)
prev = 직전 complete run 의 rank_no IS NOT NULL 집합 (없으면 ∅ — 1회차)
added = top − prev ; removed = prev − top
BEGIN
  DELETE FROM overseas_universe_auto; INSERT 상위 N (symbol, rank_no, market_cap=cap_used, computed_at=now, [run_id, cap_source])
  UPDATE candidate SET rank_no …
  UPDATE run SET phase='complete', counts_json, added_symbols, removed_symbols, finished_at
COMMIT
§8 제안 생성 → §9 알림(제안 ≥1 또는 added∪removed ≠ ∅ 일 때만) → run.notified_at
```

- `overseas_universe_auto` 는 **한 트랜잭션에서 통째로 바꾼다**(화면·B0 가 반쪽 목록을 읽지 않게). `computed_at` 은 N행 모두 같은 값(developer `buildSummary` 가 MAX 를 쓴다 [확실]).
- **상위 N 이 `top_n` 보다 적으면**(후보 부족) run `failed('insufficient_candidates')` 로 두고 자동 목록을 바꾸지 않는다 — 50도 못 채우는 상태는 원천이 깨진 것이다.

### 3.6 응답 계약

`{ ok, status, final, runId, runKey, phase, progress:{ pending, ok, excluded, failed, total }, elapsedMs, lastError? }` — `final:true` 는 「이달 더 부르지 마라」(complete·failed·expired·disabled·tables_missing·skipped_month_done). 러너는 `final` 만 본다(§4.3).

### 4.3 실행 시각 — 매월 첫째 일요일 01:10~05:50 KST (권고)

근거:

1. **거래일 아님(둘 다)**: 미국 정규장은 KST 23:30~06:00(EST)/22:30~05:00(EDT) — 평일 야간은 전부 미국 장중이다. **일요일 KST = 토요일 ET** 라 미국·국내 모두 닫혀 있고, 서머타임과 무관하다.
2. **가격 단면이 하나**: 청크가 30~75분에 걸쳐도 모든 종목의 `last`·`tomv` 가 금요일 종가다. 평일 야간이면 01시 종목과 05시 종목이 다른 가격으로 순위를 다툰다 — 시총 순위에서 받아들일 수 없는 비일관이다.
3. **KIS 유량 여유**: 장중이면 `normal` lane(entry-watcher·strategy-eval)이 `bulk` 를 밀어낸다(올바른 동작이지만 산출이 늘어진다). 일요일 01~06시의 KIS 호출은 매 분 잡의 보유 종목 몇 건 + 정시 portfolio-snapshot 뿐이다.
4. **08시 틱·06/07시 무거운 틱과 분리**: 창을 05:50 에 닫아 06:00 뉴스·07:00 edgar/research·07:20·07:40·08:00 블록과 겹치지 않는다. 03:00 `export-llm-trainset`(bash, KIS 0, 1~5초) 과 :00 peek(40초) 는 같은 틱에 와도 위 240초 안이다.
5. **KIS 가 주말에도 현재가상세를 준다** [확실 — 10-25(토)·10-26(일)·11-01(일) 스냅샷 `written=52`].
6. 00:00~01:00 를 피한 이유: [추측] KIS 토큰·점검 시간대 가능성. 01:10 시작이면 무관.

## 5. 비보통주 제외 규칙과 1회차 집계

### 5.1 관측된 것 [확실]

### 5.2 3겹 규칙

## 6. `tomv` 비일관 판정 규칙

### 6.1 관측 [확실]

운영 624행 전부 `market_cap ÷ (shares × last_price) = 1.000000`(min=max, `n_off(>0.1%) = 0`). `tomv` 는 USD 원값이고 **KIS 가 `shar × last` 로 계산한 값**이다. 함의: **클래스 단위**다 — `NAS:GOOGL` 1.64조(5.868B주)·`NAS:GOOG` 1.54조(5.527B주)로 Alphabet 전체(≈3.4조)가 아니다. NYSE 의 `BRK.B` 도 B 주 기준으로 잡힌다. 순위 기준은 **「KIS 가 주는 클래스 단위 시총」**이라고 문서에 명시한다(회사 전체 시총과 다르다).

### 6.2 규칙

```
입력: tomv, shar, last  (각각 null 허용)
if tomv == null:
    cap_used = null ; cap_flag = 'tomv_null' ; cap_alt = (shar>0 && last>0) ? shar*last : null      → 제외(승인 정책), cap_alt 와 건수 기록
elif shar == null || last == null || shar <= 0 || last <= 0:
    cap_used = tomv ; cap_source='tomv' ; cap_flag='unverified'                                      → 사용(검증 불가 표시)
else:
    r = tomv / (shar * last)
    if |r - 1| <= 0.005                : cap_used = tomv        ; 'tomv'          ; 'consistent'
    elif 0.90 <= r <= 1.10             : cap_used = tomv        ; 'tomv'          ; 'minor_mismatch'   (주수 갱신 지연 등 — KIS 값 유지)
    elif ∃k∈{±3,±6}: |r/10^k - 1| ≤ 0.05 : cap_used = shar*last ; 'shares_x_last' ; 'unit_mismatch'  (천·백만 단위 오류)
    else                               : cap_used = shar*last   ; 'shares_x_last' ; 'basis_mismatch'  (기준 주수가 다름 — 관측 규약인 클래스 단위로 통일)
cap_ratio = r (소수 6자리) 저장
```

- 임계 0.5%: 관측값이 소수 6자리까지 정확히 1 이라 참값은 1 이고, 0.5% 는 표시 반올림(`last` 2자리·`shar` 반올림)만 흡수한다. 10% 밴드는 「같은 기준인데 한쪽이 며칠 늦은」 경우를 `tomv` 로 둔다. 그 밖은 사용자 지시대로 `shar × last`.
- `curr !== 'USD'` → `excluded 'currency'`(NYSE 는 전부 USD 여야 한다 — 방어).
- 상한 2×10^13 USD(20조)·하한 0 → `implausible` 제외(단위 오류가 두 겹으로 겹친 경우 방어).

## 8. 변경 제안 생성 규칙

### 8.1 원칙

- **제안은 수동 목록 종목에만 만든다.** 제안의 세 행동(빼기·넣기·코드 바꾸기)이 수동 목록을 바꾸기 때문이다(`applyProposalToManual` [확실]). 자동 목록 종목의 거래소 이동·상장폐지는 **다음 산출이 자동으로 반영**하고, 보유·즐겨찾기 전용 종목은 각자 원래 화면이 주인이다(가이드 §0.3) → 둘은 제안이 아니라 **알림 본문의 정보 줄**(§9).
- **자동 목록 변동(added/removed)은 제안이 아니다.** 사용자가 승인한 것이 「자동화」이고, 제안으로 만들면 승인 전까지 자동 목록이 바뀌지 않아 자동이 아니게 된다. 변동은 run 에 기록하고 알림에 싣는다(L-A1).
- 제안을 만들기 전에 **목표 상태가 이미 반영돼 있으면 만들지 않는다**(예: 수동 목록에 `NAS:WMT` 가 있고 `NYS:WMT` 가 없으면 recode 제안 없음).
- 같은 지문의 행이 있으면 **`INSERT IGNORE`**(어떤 상태든 — `done`·`ignored` 포함). 멱등.

### 8.2 월간 산출(listing·kis) 이 만드는 제안 — 수동 목록의 각 종목 `EXC:TKR` 에 대해

```
sec_rows_by_ticker = SEC 파일에서 ticker == toSecTicker(symbol)
sec_rows_by_cik    = SEC 파일에서 cik == symbol_cik_map[symbol].cik   (매핑이 있을 때만)
kis_ok             = (스캔 대상이었으면 후보 status) 또는 (아니면 최근 3거래일 us_fundamentals_snapshot 행 존재 여부)

A. sec_rows_by_ticker 1건 && exchange ∈ {Nasdaq→NAS, NYSE→NYS} && 매핑 거래소 ≠ EXC
     → kind exchange_move, action recode, next_symbol = <새EXC>:<TKR>, basis 'SEC 상장 목록: exchange=<값>'
B. sec_rows_by_ticker 1건 && exchange ∈ {OTC, TXSE, CBOE, null}
     → kind otc_move, action remove, basis 'SEC 상장 목록: exchange=<값> — KIS 미지원 거래소'
C. sec_rows_by_ticker 0건 && sec_rows_by_cik 에 같은 회사가 다른 티커로 1건(exchange 가 NAS|NYS 로 매핑됨)
     → kind ticker_change, action recode, next_symbol = <EXC'>:<TKR'>, basis 'SEC: CIK <n> 티커 <TKR> → <TKR\'>'
D. sec_rows_by_ticker 0건 && (sec_rows_by_cik 0건 || 매핑 없음) && kis_ok == false
     → kind delisting, action remove, basis 'SEC 상장 목록 없음 + KIS 조회 실패'
E. sec_rows_by_ticker 1건(거래소 일치) && kis_ok == false
     → kind kis_unavailable, action remove, recommendation '표기 확인(클래스주 . 표기 등) 또는 빼기', basis 'KIS 현재가상세 판정 불가 N일'
F. 그 밖 → 제안 없음 (SEC 없음 + KIS 정상 = 파일 지연일 수 있음 → counts 에만)
```

- 지금 운영 목록에 적용하면 **`NYS:WMT` → A(recode `NAS:WMT`)**, **`NYS:BRK.B` → E(kis_unavailable)** 두 건이 나온다 [확실 — SEC 파일·스냅샷 로그로 손으로 계산]. 이 둘이 1회차 시험 데이터다.
- 보유 중인 종목이 B·D·E(remove)에 해당해도 **제안을 그대로 만든다**. 화면·시트·알림이 「빼도 분석은 계속」을 말한다(가이드 §2.4.2). **이 잡은 시그널·주문을 만들지 않는다** — 상장폐지 의심 보유 종목은 알림 수준을 `warning` 으로 올려 사람이 결정하게 한다(안전장치 경로 `createSignal→submitOrder` 밖에서 매도를 만들지 않는다). analyst 역할의 「즉시 매도 시그널」 규정은 사람(분석가)의 보고 의무로 남기고 자동화하지 않는다.

### 8.3 제안 행 필드 채우기

| 필드 | 값 |
|---|---|
| `symbol` | 내부 전체 코드 |
| `kind` / `action_type` / `next_symbol` | §8.2 표 |
| `basis_text` | 위 basis 문장 + `(SEC 파일 sha 앞 8자)`, 255자 안 |
| `basis_source` | `'listing'` |
| `basis_fingerprint` | §8.4 |
| `collected_at` | run 의 `sec_fetched_at`(E 는 마지막 KIS 실패 시각) |
| `recommendation` | A·C `코드 바꾸기 X → Y` 는 NULL(화면이 label 을 쓴다) · B·D `목록에서 빼기` NULL · E 위 문장 |
| `state` | `'open'` · `created_at` now · `notified_at` NULL |

### 8.4 멱등 키(지문) — 「같은 사실은 한 번만」

```
fingerprint = `${source}|${symbol}|${kind}|${observed}`     (≤190자, ASCII)
  A exchange_move  : listing|NYS:WMT|exchange_move|sec_exchange=Nasdaq
  B otc_move       : listing|NYS:X|otc_move|sec_exchange=OTC
  C ticker_change  : listing|NAS:FB|ticker_change|cik=1326801;new=META
  D delisting      : listing|NYS:X|delisting|sec_missing;kis_missing
  E kis_unavailable: listing|NYS:BRK.B|kis_unavailable|kis_missing
```

- **월·일자·run_id 를 넣지 않는다.** 같은 관측 사실이면 다음 달에도 같은 지문 → `INSERT IGNORE` → 재제안 없음(무시 문구 「같은 근거로는 다시 제안하지 않습니다」 보장). 사실이 바뀌면(`Nasdaq`→`OTC`) 지문이 바뀌어 새 제안이 뜬다(보류 문구 「공시가 갱신되면 다시 올라옵니다」와 같은 뜻).
- 한계: 상태가 「실패 → 복구 → 다시 실패」로 되돌아오면 같은 지문이라 두 번째는 뜨지 않는다. 월 1회 산출에서 받아들인다(문서에 적어 둔다).
- 일간 공시 기반(참고 §8.6)은 `us_filings|<symbol>|<kind>|<accession>` — 접수번호가 다르면(8-K/A) 다시 뜬다.

### 8.5 자동 목록 종목·보유·즐겨찾기 전용 종목의 상장 상태 변화

제안을 만들지 않고 알림 정보 줄로만:
- 자동 목록에서 **빠진 종목이 `kis_missing`/`otc`/SEC 소실** 이면 「상장 상태 변화로 빠짐」으로 분류해 적는다(단순 순위 하락과 구분).
- 보유·즐겨찾기 전용 종목이 B·D·E 조건이면 `⚠ 보유/즐겨찾기 <symbol>: <사유>` 줄. `holdings-premarket`(T-119) 가 공시 쪽을 이미 알린다 [확실].

### 8.6 참고 — 일간 「변경 확인」(WP-B D5) 의 공시 규칙에 필요한 사실 [확실]

- `us_filings` 에 적재되는 양식은 `KEPT_FORMS` = 8-K(/A)·10-Q(/A)·10-K(/A)·20-F·40-F·6-K 뿐(`parse.ts:55~58`). 운영 분포 8-K 4,382 · 10-Q 1,115 · 10-K 359 · 8-K/A 83 · 10-K/A 11 · 10-Q/A 4. **Form 25·15-12B·SC 14D9·S-4·DEFM14A 는 들어오지 않는다.** 상장폐지·합병을 공시로 잡으려면 `KEPT_FORMS` 확장(`src/lib/data/us-edgar/parse.ts`)이 필요하다 — 이건 WP-A 범위 밖이지만 D5 설계 전에 알아야 한다.
- 지금 자료로 가능한 고정밀 규칙: 8-K `items` 에 **3.01**(상장폐지 통지·계속상장 요건 미달) → `delisting` · **5.01**(지배권 변동) → `acquisition` · 1.01/2.01 은 범용이라 쓰지 않는다(소음).
- `edgar-sync` 는 `loadUsTargetSymbols` 대상만 동기화한다 [확실] → B0 가 DB 를 읽기 시작하면 자동 50 도 다음 날 07:00 부터 동기화된다(예산 100초, 신규 50종목 × 2호출 × 0.25초 ≈ 25초 — 하루 안에 따라잡는다 [가능성 높음]).

## 9. 알림 (D2·D3, 가이드 §7)

### 9.1 조건 — 「새 제안 ≥1 또는 자동 목록 변동 ≥1」일 때 **1회**

- 월간 산출 `complete` 직후 1회. 제안 0 · 변동 0 이면 **보내지 않는다**(T-125 재발 방지 — 「변동 없음」 메시지 금지).
- `notified_at IS NULL AND state='open'` 인 제안만 싣고, 성공 응답 뒤 `notified_at` 을 채운다. 자동 변동은 `run.notified_at`.
- 설정 › 알람의 토글(가이드 §7.3, 키 예 `notify_universe_change`)이 꺼져 있으면 텔레그램만 생략한다. 홈 「확인 필요」 줄은 제안 행 존재로 독립 동작한다 [확실 — `readOpenProposalBrief`].
- 수준: 제안 중 **보유 종목 remove** 가 있으면 `warning`, 그 밖 `info`. `critical` 은 쓰지 않는다(주문·안전장치 알림의 자리).
- **L-A1 (Leader 결정)**: 제안 0 이고 자동 변동만 있을 때도 보낼지. 권고 **보낸다**(월 1회, 변동이 있을 때만 — 분석 대상이 바뀐 사실을 사용자가 모르면 안 된다). D2 의 「제안이 생겼을 때만」을 「변경이 생겼을 때만」으로 넓히는 셈이라 Leader 가 적어 둔다.
