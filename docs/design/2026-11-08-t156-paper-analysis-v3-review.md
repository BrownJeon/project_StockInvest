# T-156 모의분석 v3 검토 제안

상태: 사용자 검토 전 제안. 승인된 구현 가이드가 아니다. 앱 소스·운영·DB·게이트·기존 v2는 변경하지 않았다.
데모: `mockups/T-156-paper-analysis-v3.html` (T-156-v3).

## 레이아웃 설계

- 목표: 수집 자료 → 적용 규칙·판단 → 모의 매매 → 성과를 모바일에서 확인한다.
- 위계: 기존 분석 띠·3분류 → 상세 제목 → 모의 전용 안내·선택 실행 정책 → 고정 4탭 → 활성 목록·페이지.
- 영역: 오늘 분석·검증/성과·데이터 상태 및 하단 홈/거래/분석/비서/설정 구성 유지. 오늘 분석의 입구·상세 제목만 `모의분석`; M40은 정책명으로 남긴다.
- 컴포넌트: 기존 globals/ops 토큰·Section/row/StatusChip 패턴, BottomTabs CSS·NavIcons SVG 스냅샷 재사용. 기존 v2 불변.
- 상태: 정상·빈·로딩·조회 오류·접근 제한. 오류·403에서는 이전 결과·정책 표시를 제거한다. 별도 재조회 예시는 합성 응답만 복원한다.
- 행동: 조회·탭·필터·이전/다음 페이지·근거 펼치기만. 주문·수집·분석 실행·정책 활성화 버튼 없음.
- 반응형: 360/412px부터 4칸 한 줄, 각 44px 이상. 900px 이상 본문 폭 복원. 단일 활성 패널 권장안을 데모로 제시하며 사용자 검토 대상이다.

## 현재와 제안의 범위

기존 실제 앱은 2×2 링크와 4영역 동시 노출, 페이지 없음이다. v3는 `수집상태 / 종목판단 / 모의시그널 / 모의성과` 한 줄 탭과 단일 활성 패널, 목록별 10개 페이지를 제안한다. 검토 도구의 `현재 이름 비교`는 입구·제목의 변경 전 이름만 비교한다. 기존 전체 화면의 인터랙션 재현은 아니다.

sticky 위치는 실제 띠 높이 + 3분류 높이로 측정한다. 두 영역의 ResizeObserver와 창 resize가 갱신한다. 탭에는 tablist/tab/tabpanel, 방향키/Home/End, 활성 탭 하나의 tabIndex 0을 적용했다. 페이지 이동은 같은 방향의 활성 버튼 또는 패널로 포커스를 복귀시키며 목록 시작을 고정 탭 아래로 스크롤한다. 필터는 해당 목록 첫 페이지로, 건수/초기화는 모든 목록 첫 페이지로 돌아간다. 탭 전환은 각 목록 페이지를 보존한다.

## 정책 의미

현재 코드: M40 기본 규칙이 모의 매매를 결정하며, 에이전트 결과는 참고 기록이다. 에이전트 호출만 켜서는 매매에 반영되지 않는다. 기본 시나리오는 `현재 연결상태: M40 기본 · 에이전트 참고 전용 / 미호출`이다.

사용자 목표: M40 + 에이전트가 검증된 규칙/정책을 선택한 뒤 모의 의도·모의 결과로 이어지는 설계. 별도 `설계예시 · 거래연결 미구현` 시나리오로만 표현한다. 가상 적용 개정·기본 규칙·에이전트 실행·판단 반영과 종목별 최종 이유를 보여준다. 실제 선택 실행의 정책/개정/반영 상태를 제공할 DTO가 필요하며 현재 응답만으로 확정 표시할 수 없다.

부모의 2026-11-08 읽기 전용 운영 검산은 최신 회차가 리허설, 4단계 모두 미호출, 에이전트 비활성임을 확인했다. 데모 값은 이 운영 기록을 복제하지 않은 합성값이다. 모의 전용 주문 차단은 전역 DRY_RUN과 별개이나 현재 예약 전진 실행은 DRY_RUN=true도 요구한다. 실거래를 켜도 자동 모의분석이 계속된다고 표시하지 않는다.

## 결정 필요: 후속 구현 범위

A. 조회 화면 + 저장된 정책 상태 정확 표시. 현재 기본 매매·참고 판단 연결은 유지한다.
B. 사용자 목표인 모의 전용 M40 + 에이전트 규칙 선택/매매 반영 연결까지 별도 설계·검증 후 포함한다. 구체 선택 엔진은 아직 확정하지 않았으며 기존 T-156 검증 기준 대조와 블라인드 백테스트가 필요하다. 새 임계값·규칙을 이 데모에서 발명하거나 확정하지 않는다.

위 두 범위는 데모 정책 카드의 `결정 필요`에도 함께 표시했다. 화면 v3 승인과 연결 구현 범위 선택은 구별한다. 현재 환경변수로 과거 실행의 정책을 소급 추정하지 않으며 선택한 저장 회차에 정책 ID/개정·기본 규칙·에이전트 실행 결과·판단 반영 여부·근거를 저장하고 읽는 계약이 필요하다. 운영/API 실행 활성화는 이 제안으로 승인되지 않는다.

## 목록과 서버 API 요구사항

| 영역 | 데모 | 실제 구현 전 요구사항 |
|---|---|---|
| 수집상태 | 기본 출처 4개, stress 23개; 10개 페이지 | 출처 집계와 이슈 목록 각각 실제 목록인지 구분. 건수 증가 시 각 목록을 독립 페이지 처리 |
| 종목판단 | 23개, 종목/판단 필터, 독립 페이지 | 현재 회차 후보·적격·결정 합집합의 필터 후 count, 안정 정렬 및 페이지 범위 |
| 모의시그널 | 합성 23개 중 페이지 | 현재 API 기본 20/max100은 최근 조회분이다. 전체 이력에는 서버 count + cursor/offset·정렬·필터 계약이 필요. 로드한 일부를 전체라 부르지 않음 |
| 모의성과 | 관측점만 10개; 요약 지표 고정 | 현재 1000점 cap/truncated 유지. 지표는 페이지가 아닌 완전 시리즈 또는 서버 집계로 계산. 잘림은 전체 지표 미확인. 페이지 API와 성과 집계 기준·범위 분리 |

모든 서버 페이지는 로그인과 명시적 viewer 권한을 먼저 확인하고 account/owner 범위를 조회·count·summary 모두에 적용해야 한다. 첫 요청의 runId/snapshotVersion + query/filter/sort를 cursor에 결속하고 정렬의 동률 tie-breaker는 id로 고정한다. pageSize=10, totalCount, hasNext/nextCursor 및 부족/잘림 상태를 반환한다. snapshot 만료나 정책 변경 시 새 스냅샷의 page1로 재시작한다. 새 기록 삽입 중 페이지 중복/누락을 막고 403에서는 기존 DTO를 폐기한다.

정책/모델/프롬프트 개정과 판단 반영 상태는 현재 runtime/env나 mutable account.revision이 아닌 선택 run에 영속 저장된 값을 쓴다. 현재 DTO에는 해당 run 정책판 필드가 없으므로 누락 시 미확인으로 표시한다. 데모의 정책 rev.1/rev.2는 가상 정책 개정이며 실제 account.revision과 무관하다.

요약 수치·정책·기준 시각은 페이지 처리하지 않는다. 0–1 관측점 수익률/MDD 없음, CAGR은 365일 이상 완전 이력 필요, 실현/미실현 분리 미지원, 초기 리허설과 전진성과 분리를 유지한다. 합성 관측점의 수익률은 최초/최종 합성값으로 계산하며 페이지 전환에 영향받지 않는다.

## 자체 점검 및 검증 범위

디자인 스킬: page-layout-designer · ui-component-builder · project-ui-system(부분/모바일) · ui-design-reviewer · ui-accessibility-reviewer.
정적 자체 점검: P0 0 · P1 0 · P2 1; a11y Critical 0 · Major 0 · Minor 1. P2/Minor는 실제 브라우저·스크린리더/기기에서 포커스 노출과 명암·sticky 배치를 아직 확인하지 않았다는 검증 제한이다. 발견된 기능 결함이 없다는 뜻과 기기 검증 완료를 구별한다.

- demo lint: `DEMO_LINT_PASSED` (T-156-v3).
- JS VM 합성 렌더: 4목록 × 0/1/10/11/23건 경계, 페이지 범위 clamp·행 10개 이하, 마지막 페이지, 로딩/오류/403 비공개 기록·정책 미표시, 성과 지표 페이지 독립 확인.
- 브라우저: 부모가 담당한다. 이 에이전트는 CUA를 사용하지 않았다. 360/412/1280px 실제 렌더·scroll/resize·키보드 포커스·명암은 부모의 실측 후 확정한다.
- 네트워크 호출·CDN·외부 자산·실제 계좌/이메일·운영 원본 데이터 없음. 새 HTML과 이 제안서 두 파일만 작성.

사용자 검토 이후에만 승인 버전을 특정한 구현 가이드와 구현 범위를 확정한다. 이 문서는 정책 변경·서버 변경·배포 승인으로 사용할 수 없다.

## 등록 전 CUA 지적 수정

부모의 실측에서 합성 23종목이 상위 5종목 제한을 넘겨 선정 표시되는 결함을 발견해 등록 전에 수정했다. 양수 후보만 연속 순위를 매기고 적격 상위 5종목만 선정한다. 음수 후보는 순위 없음, 양수라도 6위 이하는 상위 5종목 밖으로 미선정·매매 없음이다. 설계예시도 기본 적격·상위 5종목 제한을 완화하지 않는다. current/target 모두 선정 5건, 선정 후보 양수·순위 5이하, 양수 순위 연속, 음수 순위 없음, 선정 필터 5건을 JS VM으로 검증했다. 23개 시그널은 서로 다른 가상 회차의 이력이며 23개 동시 신규 매수가 아님을 명시했다.

추가 정합성 수정: 수집 요약의 참조/적격/양수/음수 수는 판단 탭의 같은 합성 후보군 건수와 맞췄다(기본 23/23/16/7). 출처 그룹 수 4개와 종목 수는 구별한다. 시그널은 행마다 다른 가상 회차를 명시하고 고정 기준/예정 세션 예시를 제거했다.

빈 상태 추가 수정: 저장된 분석 응답 자체가 없으면 모든 탭을 기록 없음으로 표시하고 선택 회차·정책 개정·집계·성과 수치를 미확인으로 처리한다. 정상 상태의 건수 0은 알려진 0개 원장으로서 별도 취급한다.
