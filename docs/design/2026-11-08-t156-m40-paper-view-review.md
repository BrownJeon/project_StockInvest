# T-156 M40 모의분석 화면 검토 v2

사용자 요청: 분석 탭에서 수집 상태·종목별 판단/제외·매수/매도 모의 시그널·모의 성과를 확인한다. 기존 화면 구성과 실거래 비활성을 유지한다. 사용자 v2 승인은 완료됐으며, 승인 도구 지원 보완과 증거 연결 검증 뒤 이 구성을 구현한다.

## 준비한 화면

- 기존 하단 홈/거래/분석/비서/설정과 분석 상단 오늘 분석/검증·성과/데이터 상태를 유지한다.
- 오늘 분석의 종목별 영역에 **M40 모의분석** 입구 한 줄을 추가한다. 상세는 같은 오늘 분석 분류의 `?tab=m40`로 제안한다.
- 네 영역은 수집 상태·종목 판단·모의시그널·모의성과다. 실거래·승인·주문·수집 실행 버튼을 넣지 않는다. 새로고침은 저장 자료 재조회만 한다.
- 적격 종목과 최종 상위 선정을 구분하고, 상위 선정과 실제 모의 매수 여부도 분리한다. 가용 현금·보유·교체일 때문에 선정돼도 매수가 없을 수 있다.
- 리허설은 기록/미체결로 표시한다. 전진 성과는 전진 평가액만 사용하며 0~1점은 아직 없음, 365일 미만 CAGR은 아직 없음이다. 실현/미실현 손익 분리는 현 원장에서 미지원으로 표시한다.
- 모든 데모 수치·종목·시각은 합성이다. 실계좌 복사본의 금액·보유는 데모에 사용하지 않았다.

정본 데모: `mockups/T-156-m40-paper-analysis-v2.html`. v1은 내부 초안 이력으로 보존한다. v2 SHA `9d1197c42d99fc3d64bd20d3b6d267702174ea1f637ea0fdf9bc4b569db6cb07`. 기존 globals/ops/BottomTabs CSS와 NavIcons를 사용했다. 화면 소스는 승인 전에 수정하지 않았다.

## 독립적으로 준비한 읽기 API

`GET /api/research/t156/paper`의 신규 reader·DTO·권한 표 SQL·시험을 준비한다. API는 서명 로그인 → 명시적 viewer와 users 존재 확인 → 읽기 전용 일관 스냅샷 순서로만 비공개 자료를 조회한다. viewer가 없으면 상세 조회를 거부한다. 조회에서 거래/수집/판단 에이전트를 새로 실행하지 않는다.

| 영역 | 자료와 표시 계약 |
|---|---|
| 수집 | 해당 회차의 eligibility와 SHA 검증된 provenance blob에서 출처별 관측·세션·실제 수신/가용 시각 집계. 원문 공개 시각 미확인은 미확인으로 유지 |
| 종목 | 같은 계좌 회차의 sourceRunId에 연결된 후보·순위·선정·최종 판단/제외 이유. 다른 연구·합성 run을 섞지 않음 |
| 시그널 | 전용 paper 표만 조회. 리허설/모형 체결/만료·이유·예정 세션·기록 시각을 구분. 일반 signals와 shadow 초안 합산 안 함 |
| 성과 | 전진 기록만의 최초 평가액 기준 변화·관측 최대낙폭·조건 충족 시 연환산. 리허설과 섞인 returnSinceClone/peak를 전진 지표로 사용하지 않음 |

최신 회차가 blocked면 먼저 이를 표시하고, 직전 정상 결과는 **이전 저장분**과 날짜를 함께 표시한다. 저장 기준 시각을 마지막 수집·실행 성공 시각으로 단정하지 않는다. 결측을 0수익으로 채우지 않는다. 원문 clone/input/자격증명/임의 JSON은 응답하지 않고 `Cache-Control: private, no-store`를 사용한다.

신규 권한 표 `t156_paper_viewer`는 계좌당 한 명의 명시적 사용자 ID만 허용하도록 준비한다. 사용자가 제공한 로그인 이메일을 확인해 기존 회원 한 명에만 조회 권한을 연결했다. 최초 사용자/최소 ID/모든 로그인 회원을 소유자로 추정하지 않는다. **전용 viewer 표·권한 연결과 실제 reader 검산은 완료했으며, 화면 구현·배포는 아직 하지 않았다.**

## 다음 단계

사용자의 데모 v2 승인과 로그인 이메일 확인은 완료됐다. 자동 게이트가 질문 응답/작업 경로의 승인 증거를 연결하지 못해, 사용자가 ‘승인 도구 지원부터 보완’을 선택해 공통 도구의 질문 응답·등록 worktree 지원을 격리 사본에서 수정·독립검증하고 있다. 동일 v2 승인을 다시 요청하지 않는다. 이메일은 저장소·데모·공개 검증 파일에 넣지 않는다. 명시적 대상 계정 검증 후 전용 조회 권한을 연결하고, 독립 리뷰·격리 QA·승인본 대조·운영 조회를 검증한다. 기존 실계좌·전략·주문·DRY_RUN 값은 변경하지 않는다.

데모 게이트는 현재 관리 worktree 밖 경로를 기본값으로 거부했다. 도구가 문서화한 `DEMO_GATE_WORKSPACE`를 해당 worktree의 부모로, state는 기존 공통 경로로 지정해 실제 task에 `review_requested/v2`를 등록했다. 승인 상태·증거를 수동 생성하지 않았으며, 실제 승인 발화는 확인했으나 도구 증거 검증은 거부됐다. 승인 상태를 임의 변경하지 않고 화면 소스는 아직 수정하지 않았다.
