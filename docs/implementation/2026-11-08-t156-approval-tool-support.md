# T-156 승인 도구 질문 응답·worktree 지원

사용자는 기록 예외 대신 **승인 도구 지원부터 보완**을 선택했다. 실제 v2 승인은 새로 요청하지 않았다. 공유 도구 14개 파일을 원본 해시가 보존된 격리 사본에서 보완하고 독립 감사·QA 후 사전 해시 대조와 백업을 거쳐 반영했다. 운영 DB·거래 설정·훅 정의·신뢰·게이트 강제 모드는 변경하지 않았다.

| 항목 | 확인 결과 |
|---|---|
| 질문 응답 | 원래 비동기 질문 ID·선택 항목·메시지 ID·사용자 메타데이터·완료 이벤트를 원본 세션에서 대조 |
| 작업 경로 | Git commondir·등록된 worktree·역방향 gitdir 대조, 실제 task와 데모 및 active task를 같은 checkout에 고정 |
| 승인 의미 | 같은 버전이 명시된 제한적 긍정 답변만 허용. 질문 문구·이웃 답변·거부·미승인·철회는 제외 |
| 복구 | 질문은 검토 등록보다13.141초 먼저, 실제 답변은 등록 이후. 명시적 복구에만60초 등록 허용창·유일한 대상·중간 등록 없음 적용 |
| 재사용 방지 | 같은 세션/턴 claim, 실제 작업 루트·질문·메시지·버전·데모 SHA에 고정. 다른 checkout/세션/작업과 중복·손상·변경 증거 차단 |
| 회귀검사 | 독립 QA193/193, 독립 Reviewer193/193, 공유 원본 반영 후193/193 통과. 기존96개 포함 |
| 실제 처리 | `approve-codex-native` 성공(source=`codex_native_transcript`), `check` 및 `activate`에서 `DEMO_GATE_PASSED` |

원래 승인 발화 시각은 `2026-11-08T06:06:12.888Z`, 도구 기록 시각은 `2026-11-08T15:57:06+09:00`다. 과거 UserPromptSubmit 실행이나 새 사용자 승인을 주장하지 않는다. 승인된 v2 SHA는 `9d1197c42d99fc3d64bd20d3b6d267702174ea1f637ea0fdf9bc4b569db6cb07`이며 변경하지 않았다.

공유 소스는 Git 저장소 밖이므로 전체 변경 파일·원본 백업·patch·해시 목록·독립 보고서·검사 로그·최소 실제 승인 영수증을 `t156-approval-support-evidence-20261108.tar.gz`로 보존한다. 152,175bytes, SHA `d0b66dc1d6f8cc5f2b8300b5edc0ad3c0f8518a1849a79e9ac04f88ee25cfa7c`. 원본 대화·이메일·금융 데이터는 포함하지 않는다. manifest SHA `985d1bd6b3145fe25dad1bc39b94f40fbd98bde372556959bdf34f206a3393f6`.

남은 한계: 로컬 파일은 암호학적 사용자 인증이 아니다. 질문에서 task/hash를 직접 기재하지 않은 경우 유일한 검토 대상이라는 문맥을 확인한다. 같은 프로젝트/세션에서 다른 checkout의 검토가 함께 열려 있으면 보수적으로 차단한다. native 검증에는 원본 세션 대화 파일이 계속 필요하며, 알 수 없는 외부 경로나 쉘 쓰기는 기존 훅의 최선 노력 범위다. 자동 native UserPromptSubmit 수집의 신규 실제 E2E를 수행했다고 주장하지 않는다. 추가 인접 Jev 검사 시도는 격리 사본의 TheKaiwa 폴더 부재로45개 통과·시험 파일 로드 실패1건으로 별도 기록했으며 필수193개와 섞지 않는다.

이후 작업은 승인된 v2 M40 조회 화면 구현·독립 검토·화면/권한/안전 검증이다. 실거래는 계속 OFF다.
