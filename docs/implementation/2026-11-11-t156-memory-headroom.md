# T-156 메모리 사용량 보완 — 512MiB 유지

현재 단계: 0.6.0 구현·독립 검토·격리 검증 완료, 운영 배포/사후 검증 준비.

## 승인 범위와 유지 조건

사용자는 기존 512MiB와 안전 조건을 유지한 최적화를 우선 승인했고, 가능한 개선으로 해결되지 않는 경우에만 768MiB 증설을 허용했다. 이번 검증에서는 기존 기준 안의 처리 경로를 확인했으므로 증설하지 않는다. 실거래 OFF, 웹 PM2 536,870,912 bytes·cron 134,217,728 bytes, 편도 수수료 0.25%, 예측 경로 2,000개 및 같은 seed를 유지한다. 전역 DB 설정·앱 권한·보호 트리거·T0·기존 계좌와 예측 원장의 내용도 보존한다.

## 검토하고 반영한 방법

| 방법 | 반영 내용 | 보존하는 검사 |
|---|---|---|
| 마스터 처리 할당 축소 | 같은 base64를 버퍼 하나로 디코딩하고 모든 NYSE 행의 제5열부터 검사한 뒤 BRK 일치 행만 24열 생성 | 전체 마스터 SHA, fatal EUC-KR, 전체 행 탐색·중복·24열·각 필드 |
| 검증 전용 매핑 | 실제 분석용 출력은 그대로 생성하고, 상태/준비/발행/커밋 검증에는 종목 가격 출력 배열을 만들지 않음. 필요한 지수 바는 유지 | 원문 SHA·CSV/행 일치·계약/URL·OHLCV·공개 시각·종가 확정·BRK 공시/사건/가격 증거를 같은 순서로 재검증 |
| 큰 원천 객체의 수명 분리 | 준비 helper의 범위에서 압축 해제 버퍼·원문 묶음을 처리하고 독립 수치 입력과 작은 증거만 엔진에 반환 | 임대 취득 전후 처리·실패 정리·동일 분석 묶음·최신 원천·계좌 revision·발행 TX 원천 재읽기/입력 SHA·두 시점 공개시간 검사 |

마스터만 고친 첫 안은 실자료 3회 재생에서 RSS 감소가 일관되지 않아 충분한 해법으로 채택하지 않았다. 전역 검증 캐시, 강제 GC, Node 메모리 옵션 변경, 예측 경로 축소, 검증 삭제를 사용하지 않는다.

## 검증 근거와 범위

- 최종 동결: 49개 파일, 직전 3f66 대비 변경 11개(제품 6·시험 3·버전 2). manifest SHA `53cd702124235ce6986bd61e79e29778cec4f96759ff7fa5a5b8b1ca6f8a0ca1`, product digest `278455de4759f0b5cb10a226c586838724435d1fd2b45c587a09e662449e60a5`.
- 개발자 및 독립 QA의 집중 회귀 7 suites / 152 tests 통과, TypeScript 및 후보 production Next build 통과. 독립 Reviewer가 정확한 11파일 범위를 검토했다. 공식 C1·C2 Jev 결과는 별도 원문을 보존한다.
- 같은 보호 실자료의 고정 시각·동일 seed 순수 재생에서 full-map 출력·준비 입력·전체 엔진 결과 SHA가 같다. 이 근사 하네스는 원문을 계속 보유하므로 준비 helper 수명 효과나 실제 웹을 보증하지 않는다.
- 독립 QA는 외부 네트워크가 없는 컨테이너 안에 실제 저장 일봉·계좌·캘린더·원천/분석 원장을 복사한 MariaDB와 production Next를 띄웠다. 생산 DB와 실제 주문 인증정보는 사용하지 않았다. 형식·권한 검사용 합성 프로필을 사용했으며 실제 API 인증 성공으로 간주하지 않는다.

최악 여유는 24,457,216 bytes(약23.32MiB)다. 각 회차 250ms 간격의 관측으로 순간 최대/다른 동시부하/향후 전 거래일을 보장하지 않는다. 격리 Next는 PM2를 포함하지 않는다. 실제 운영의 0.5 첫 발행 peak 541,564,928 bytes/31 of 240와 이번 격리 기준 563,347,456 bytes를 혼동하지 않는다.

각 회차 최초 발행 1건·4기간 pending/actual=null, 중복 요청 추가 발행 0·미인증 401·동일 PID를 확인했다. 4기간 수치 전체 JSON SHA와 seed·경로수는 기준/수정본이 같다. 발행 시각·입력 메타데이터 SHA·코드 manifest는 새 시각과 새 코드를 기록하므로 발행 원장 전체 결과 SHA가 같아야 한다고 요구하지 않는다. 별도 손상 원천 DB는 503으로 차단되고 신규 예측 0을 유지했다.

## 운영 반영과 복구 계획

모의 계좌에 fresh before/경제 bridge/guard를 생성하고 status만 paused로 변경한다. 기존 core·proof·process 해시는 유지하고 새 49파일 동결본/전체 릴리스 영수증/구 프로세스 종료·환경·프로필을 확인한 뒤 재개한다. Reviewer 요구대로 실제 실행 중 PM2 제한을 재개 직전·직후 별도 읽기 검증한다. 단 한 번 push하여 정본 webhook blue/green으로 배포하고 중복 deploy 실행은 하지 않는다. DDL 마이그레이션과 APK 변경은 없다. 상태 검사 실패는 코드만 0.5로 자동 복구하고 모의 계좌는 확인 전 paused를 유지한다.

운영에는 이미 11/10 분석과 4기간 예측이 있으므로 같은 거래일의 정상 재실행은 기존 결과를 반환해야 한다. 중복 방지를 지우거나 원장 삭제·새 계좌 생성으로 새 발행을 만들지 않는다. 배포 후 수집/분석 멱등성과 기존 2run/8기간·대기 비교·원본 SHA/모의계좌·안전 조건, 추가 자동 재시작 및 메모리 사용량을 실제로 검증한다. 실제 다음 마감분의 신규 수집→분석→예측 발행은 다음 자료와 시간 관문이 충족될 때의 별도 확인 항목이다.

전체 T-156은 계속 진행 중이다. 84일/신규 왕복100건/에이전트 변경20일·확률 보정·과거 전체 구성/뉴스 공백은 이번 메모리 수정으로 검증된 항목이 아니다.
