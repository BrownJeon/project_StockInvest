# 전체 화면·기능 지도

> StockInvest 웹앱 전체 화면·기능의 단일 진실 문서(Source of Truth).
> 모든 UI 구현은 이 문서를 참조하고, 변경이 필요하면 문서를 먼저 고친 뒤 코드를 맞춘다.

주 사용 환경: **갤럭시 S25+ + 크롬 모바일** (폭 ~412px). 모바일 우선 원칙은 [`.claude/agents/developer.md`](../.claude/agents/developer.md) "화면 디자인 워크플로우" 참조.

> **T-108 메뉴·홈 개편 반영(2026-10-30, 승인 데모 [`mockups/T-108-menu-home-v3.html`](../mockups/T-108-menu-home-v3.html) v3)** — 이 문서의 §1~§4 는 개편 뒤 구조다. **구현·배포 전까지 운영 화면은 이전 구조**(하단 탭 대시보드·즐겨찾기·추천·분석·설정)다. 구현 사양 정본: [`design/2026-10-30-t108-implementation-guide.md`](./design/2026-10-30-t108-implementation-guide.md).
>
> 화면 용어(모든 화면 공통): 시그널(옛 「카드」) · 건수 적음 · N건 (30건 미만)(옛 「표본 부족」) · 장마감 전 손절(옛 「EOD 손절」「장마감 손실 차단」) · AI 매수 판단 · **실거래여부(ON = 실거래 가능 — 내부 `safety_dry_run` 과 방향 반대)** · 모든거래차단(옛 「킬스위치」) · 손실한도 손절(옛 「하드손절」) · 가상 주문·가상 청산(옛 「DRY_RUN 주문·청산」). 내부 키·테이블·로그는 그대로.

## 1. 네비게이션 구조

### 하단 4-탭 고정 바 (T-108 — 비서는 T-113 대화 소유권 배포 뒤 4번째에 추가해 5탭)

| 탭 | 경로 | 아이콘(Lucide 원본 경로 인라인) | 활성 경로 | 주 진입점 |
|----|------|--------|-----------|-----------|
| 홈 | `/` | `stone` | `/` | 안전 상태 띠 · 확인 필요 · 운용현황 · 청산 로직 · 오늘의 분석 · 최근 활동 |
| 거래 | `/recommend` | `handshake` | `/recommend*` · `/strategy*` · `/order` | 운용 현황 · 보유·주문 · 운영 기록 (`?tab=now\|hold\|log`) |
| 분석 | `/analytics` | `scan-search` | `/analytics*` · `/favorites*` | 오늘 분석 · 검증·성과 · 데이터 상태 (`?tab=today\|verify\|data`) |
| (비서) | `/ai` | `brain` | — | **T-113 전 숨김** — 라우트는 그대로, 탭 없음 |
| 설정 | `/settings` | `settings` | `/settings*` · `/profile` | 안전장치·리스크 정책(표시 전용)·입출금 기록·자동매매 자금·거래소 계정·알림·LLM·앱 |

- 하단 바 높이 `--nav-h`(60px) + safe-bottom. 라벨 11px(이전 10px), 아이콘 22px, 현재 탭 = `--accent` 색 + 위쪽 2px 막대 + `aria-current="page"`. 900px 이상은 가운데 720px.
- `HIDDEN_PATHS`(로그인·가입 등 탭 숨김)는 그대로.
- **안전 상태 띠**(홈·거래 맨 위, sticky): 단계(관찰·중지·혼합·실거래·확인 실패) · 실거래여부 · 모든거래차단 · 검증 통과 n/전체 · 청산 엔진 · 손실한도 손절. 분석은 짧은 머리 띠(단계 배지 → 홈). 단계는 스위치 조합에서 서버가 계산한다(`GET /api/ops/safety-state`).
- 정정(2026-10-30): 이 절의 이전 표(대시보드·추천·채팅·분석·설정)는 실제 코드와 달랐다 — 실제 하단 바는 대시보드·즐겨찾기·추천·분석·설정이었고 `/ai` 는 탭에 없었다.

## 2. 투자 워크플로우

```
전략 엔진 → 시그널 생성 (pending_approval)
  ↓ 거래 › 운용 현황: 사용자 검토 (승인·거절은 시그널 상세 /recommend/[id])
  ├─ [승인] → approved_pending_entry → entry-watcher (2~5분 주기)
  │             → 진입 구간 도달 → 주문 체결 → 포지션 → exit-engine → 청산
  ├─ [거절] → rejected (놓친 기회 탭에 기록)
  └─ TTL 만료 → expired
```

## 3. 탭별 화면 카탈로그

### 홈 (`/`) — T-108

**주 화면**: 자동매매 운용현황 중심. 순서 고정 — ① 안전 상태 띠(sticky) ② **확인 필요**(조치가 필요한 것만, 줄마다 이동할 곳 — 모든거래차단 ON · 청산 실주문 · 신규 매수 차단 · 승인 대기 · 주문 거부 · 손실한도 손절 OFF 한도 도달 · 가상 청산 · 데이터 이상 · 분석 실패 여부 모름) ③ **운용현황** 2×2 지표(칸 안 국내·해외 두 줄, 시장별 세션일 — 해외는 ET) — 관찰 단계: 분석 완료 종목 · 분석 후보 종목 · 사후 결과 추적 · 데이터 이상·분석 실패 / 실거래·혼합 단계: 진입 감시 · 운용 포지션 · 오늘 실체결 · 운용액(배정) · 자동매매 손익 · 신규 매수 가능 ④ **청산 로직** 3줄(가동 · 판정 · 청산 — 0 이어도 항상) ⑤ **오늘의 분석·판단**(장마감 AI 분석만, 국내·해외 두 열 표) ⑥ **최근 활동** 4건.
- 「0」 은 조회 성공 + 0 일 때만. 미수집 `◌`, 조회 실패 `!`, 오래됨(회색 + 기준 시각), 건수 적음, 차단 `⊘`, 장외, 준비 중을 글자+테두리 모양으로 구분.
- 관찰 기간엔 손익을 표시하지 않는다(손익 기준 = 실거래 전환일 첫 스냅샷). 홈에는 위험 CTA 없음(이동만).
- 데이터: `GET /api/ops/home`(60초) · `GET /api/ops/safety-state`(30초). 관찰 단계에서 KIS 호출 없음.
- 이전 대시보드의 보유/관심/내일 탭·종목 차트·총 평가액 머리·트레이딩 보드·운용 전략 목록·평가 깔때기는 홈에서 빠졌다(보유 → 거래 › 보유·주문, 깔때기 → 거래 › 운영 기록, 전략 → 거래 › 운용 현황 「전략 상태」, 내 결정 → 거래 › 운영 기록).

### 거래 (`/recommend`) — T-108

- 안전 상태 띠 + 3칸 세그먼트(`?tab=now|hold|log`, 기본 `now`):
  - **운용 현황**: 승인 대기(집합 = `awaiting_approval`·`pending_approval`·`pending` ∧ 미만료 — 홈과 같은 서버 COUNT) · 관측 기록(`detected`, 승인 버튼 없음 — 승인 대기 숫자에 넣지 않음) · 진입 감시(감시 중 · 주문 선점 중 · 다음 세션 예정, [감시 취소]는 확인 대화상자) · 전략 상태(켜진 전략 · 검증 통과 n/전체 → `/strategy`) · 내 시나리오 만들기
  - **보유·주문**: 보유(계좌 전체 · 자동/수동 보유 구분 · 청산 임계 대비 상태와 손익률) · 미체결 주문 · `포지션 추적 ›`(`?tab=hold&detail=trailing`)
  - **운영 기록**: 장중 룰 평가 깔때기(국내/해외 세그먼트, 세션일 기준) · 주문 기록(오늘, 필터 전체·체결·가상·차단·거부, `전체 ›` = `?tab=log&detail=orders` 거래 이력) · 내 결정 · `투자일지 ›`(`?tab=log&detail=notes`)
- 시그널 상세·승인·거절은 기존 `/recommend/[id]`(ScenarioDetail) — 결과 표시(처리 중·성공·실패·차단·연결 끊김·거절)만 추가, API·확인 단계 그대로.

### 🏠 대시보드 (`/`) — T-108 이전 구조 (배포 전 운영 화면, 기록용)

**주 화면**: 사용자 개입형 투자 관리 중심 구성.

- 상단 요약: 총 자산 KRW / 24h 변동 / 현금 비중 / 마지막 업데이트 / 새로고침 (자동 30초 새로고침)
- **투자 현황 카드 (4-grid)**:
  - 승인 대기 N건
  - 진입 감시 중 N건
  - 오늘 체결 N건
  - 포트폴리오 오늘 (`today_change_pct` / `today_change_krw`. 데이터 없으면 "준비 중")
- **승인 대기 배너**: `pending_approval > 0` 시 amber 배너 → `/recommend` 링크
- **트레이딩 보드**: "승인 대기 → 진입 감시 → 포지션" 3단계 시각화
- **최근 주문**: 최근 주문 10건을 **날짜(1차) → 종목(2차)** 2단 그룹으로 표시
  - 날짜 구분 라벨: 오늘 / 어제 / `M. D.`
  - 종목 그룹 헤더(`<button aria-expanded>`, 최소 높이 44px): `국기 + 종목명(코드)` + `N건 · HH:MM~HH:MM`
    (1건이거나 시각이 같으면 범위 대신 단일 시각 `1건 · 10:05`)
  - 기본 **접힘**. 1건짜리 종목도 예외 없이 그룹으로 표시
  - 펼치면 기존 주문 행(매수/매도 뱃지 + 금액 + 상태 + 시각) 노출
  - 그룹 요약은 **"최근 10건" 범위 안에서의** 건수·시각범위다(그날 전체가 아님).
    그날 전체는 "전체 보기 →" → 분석 탭 거래 이력에서 확인
  - 이 범위 제한을 문서 없이도 알 수 있게 섹션 헤더에 **`· 최근 N건`** 보조 표기를 둔다.
    표기의 N은 표시 상수(`RECENT_LIMIT`)를 참조하므로 건수를 바꿔도 어긋나지 않는다
  - 종목명 표기는 `useSymbolMeta()`(`displaySymbol`/`marketFlag`)로 거래 이력과 통일
  - 헤더 "전체 보기 →" → `/analytics?tab=orders`
- 보유/관심 탭 + 리스트
- 차트 섹션: 심볼 chip 스와이프 + 인터벌 토글 + 캔들 차트 + 24h 고/저/거래량 KPI
- safety 토글 (접힘 기본)
- **내 결정**(맨 아래 — 차트 다음, 기본 접힘, T-049): 요약 줄 승인·거절·만료 개수 + ⚠ 확인 필요 n건 · 펼치면 기간 1일/7일/30일·필터·카드 7건+페이저 · executing 은 주문 기록 상태로 표시(접수됨·부분체결·체결됨·취소됨·테스트, 그 밖·번호 없이 10분 초과는 "주문 여부 확인 필요" + 안내 줄) · 대시보드 30초 새로고침에 맞춰 재조회 · `GET /api/signals?…&includeExpired=1&withOrder=1`

**서브 화면**: 없음. 진입은 전부 다른 탭으로.

### A. 서버 연결 실패 화면 — `public/app-shell/index.html`

- APK 안에 들어 있는 **독립 HTML 1장**이다. 외부 자원 0(글꼴·스크립트·이미지 요청 없음), 다크 한 벌. 색은 `globals.css` 의 같은 이름 토큰을 hex 로 복사했고 머리 주석에 원본 sha256 앞 12자를 적는다(색을 바꾸면 함께 맞춘다).
- **이 파일을 바꾸면 네이티브 변경이다** — 웹 배포로는 반영되지 않는다. APK 재빌드 + `versionCode` 증가 + 사용자 재설치(→ `deploy-order.md` 「앱(APK) 배포」 절).
- 구성: 앱 이름 "주식캐기" · `h1`(휴대폰 오프라인 "인터넷에 연결되어 있지 않습니다" / 서버 무응답 "서버에 연결하지 못했습니다" — `navigator.onLine` 으로 나눔) · 본문 · `aria-live="polite"` 상태 줄 · [다시 시도] · 서버 무응답 때만 진단 힌트 · 맺음 문장 "이 화면은 앱 안에 들어 있는 안내 화면입니다. 주문·승인은 서버에 연결된 뒤에만 할 수 있습니다."("매매는 안전합니다" 류 안심 문구 금지 — 시험이 막는다).
- [다시 시도] = 운영 주소로 `location.replace`, 약 8초 잠금. 다시 온라인이 되면(`online` 이벤트) 한 번만 자동 시도, 주기적 자동 재시도 없음.

### B. 업데이트 띠 — `src/components/app/AppUpdateBanner.tsx`

- **문서 흐름 안**에 놓여 화면을 덮지 않는다(`fixed`·`sticky`·`z-index` 없음 — 시험 고정). 스크롤하면 지나가고 아래 화면(승인 버튼·DRY_RUN/KILL_SWITCH 표시)은 그대로 보이고 눌린다. 띠가 페이지 맨 위 요소라 `padding-top: var(--safe-top)` 을 띠가 가진다.
- **그리지 않는 경우**: 웹 브라우저(요청도 안 함) · 인증 전 화면(`BottomTabs` 의 `HIDDEN_PATHS` 와 같은 목록 — `/login`·`/signup`·`/signup/request`·`/oauth/invite`) · 조회 실패·401(조용히 숨김) · 등록된 배포본 없음 · 최신 · 설치 버전을 모름 · 오늘 ✕ 로 닫음.
- 판정은 versionCode **정수만** 비교: 내 코드 < `minSupported` = 필수, < 최신 코드 = 새 버전.
- 두 상태(둘 다 `role="status"` — 화면 이동마다 alert 반복 낭독 방지):

| 상태 | 문구 | 버튼 |
|---|---|---|
| 새 버전 | "주식캐기 v{최신}" / "새 버전이 나왔습니다 · 눌러서 설치 방법 보기" | 글자 → `/settings#app` · [받기] → 시스템 브라우저로 APK(같은 출처 `/app/download/` 주소일 때만 보임) · ✕(`aria-label="오늘은 그만 보기"`) |
| 필수 | "⚠ 앱 업데이트가 필요합니다" / "이 버전(v{설치})은 더 이상 지원하지 않습니다. 화면은 계속 쓸 수 있지만 앱 기능 일부가 멈출 수 있습니다."(말줄임 없이 줄바꿈) | [업데이트] → `/settings#app`. **닫기 없음** |

- ✕ = 오늘(KST) 하루 숨김. `localStorage` 키 `stockinvest.appUpdate.dismiss` 에 `{code, day}` 를 저장하고, **더 새 versionCode 가 나오면 같은 날이라도 다시 보인다.** 저장소가 막히면 이번 실행 동안 메모리에만 둔다.
- 닫은 뒤 포커스: 첫 `h1` → `h2` → `main` 순으로 옮기고 셋 다 없으면 옮기지 않는다(`focusAfterDismiss`, 시험 고정).
- 재조회: 첫 마운트 1회 + 앱이 앞으로 돌아올 때(`visibilitychange`) 마지막 확인이 **6시간을 넘었을 때만**. 주기적 폴링 없음. 띠와 C 는 같은 스토어(`useAppUpdate.ts`)를 쓰고 동시 요청은 하나로 합친다.
- API: `GET /api/app/version`(로그인 필요) — `latest`(versionCode·versionName·크기·sha256·notes·minSupported·downloadUrl) 또는 `latest:null`, 테이블 없음은 503 `not_migrated`.

### C. 설정 › 앱 (안드로이드) — `src/app/settings/AppSection.tsx`

- 설정 맨 아래 안내 상자 바로 위 섹션 1개(새 라우트·공개 안내 페이지 없음). 머리글은 섹션이 직접 그리고 `id="app"` 을 단다(띠의 이동 목표 — `/settings#app` 으로 들어오면 섹션이 마운트된 뒤 그 자리로 스크롤). 자체 조회라 설정 페이지의 저장 바와 섞이지 않는다.
- **웹**: 최신 버전 · 크기(1000 단위, 안드로이드 "내 파일"과 같은 숫자) · 파일 확인값 sha256 **앞 8자** · [APK 내려받기] · 설치 3단계(① 내려받기 — Chrome 이 **"유해할 수 있는 파일입니다"** 라고 물으면 [다운로드], 플레이스토어 밖 앱이라 매번 뜨는 확인 ② 설치 허용 — "출처를 알 수 없는 앱 설치"에서 Chrome 허용(처음 한 번) ③ 설치 후 Google 또는 이메일·비밀번호 로그인 — Google 은 Chrome 창이 잠깐 열렸다가 앱으로 돌아온다(T-088)) · 접힌 "받은 파일이 맞는지 확인하려면"(파일 이름·크기·전체 sha256). 안드로이드가 아닌 기기(UA 판별)에는 휴대폰에서 받으라는 한 줄을 더한다.
- **앱**: 설치된 버전(versionName·versionCode) · 최신 버전 + 상태 · [업데이트 받기 (크기)](새 버전·필수일 때) · 바뀐 점(`notes` 줄 목록) · "마지막 확인 … [다시 확인]" · 접힌 "업데이트 설치 방법".
- 상태 목록:

| 화면 | 상태 |
|---|---|
| 웹 | 로딩 · 오류("앱 정보를 불러오지 못했습니다" + [다시 시도]) · 올라온 앱 없음("아직 올라온 앱이 없습니다" — 503 `not_migrated` 포함) · 정상 |
| 앱 | 확인 중 · ✓ 최신 · ◆ 새 버전 · ⚠ 업데이트 필요(빨간 안내 상자) · ! 확인 실패(설치 버전은 계속 표시) · — 등록 없음 · — 비교할 수 없음(설치 버전을 못 읽음) |

- 상태는 기호+글자로 함께 표시한다. 버튼 44px·내려받기 48px 이상, 900px 이상은 왼쪽(버전·버튼)/오른쪽(설치 3단계) 두 칸.

### D. 로그인 — 웹·앱 한 화면 (T-088, 승인 데모 v2)

> 근거: 승인 데모 [`mockups/T-088-app-login-v2.html`](../mockups/T-088-app-login-v2.html)(v2, 사용자 승인 2026-10-25 23:49 · 결정 D1~D5 모두 권고 A). T-084 의 "앱에서는 OAuth 버튼을 그리지 않는다"(v1.0.0)는 이 절로 **대체**됐다.

- **화면은 하나다.** 웹·앱이 같은 `src/app/login/page.tsx` + 같은 `OAuthButtons`(Google 전용 — GitHub 버튼·아이콘 삭제) + "또는 이메일로" 구분선 + 이메일 폼을 쓴다. 앱 전용 분리 컴포넌트는 없다. 서버가 Google 을 "설정됨"으로 알려 줄 때만 버튼·구분선을 그리고(웹·앱 같음, 로딩 중·빈 목록은 아무것도 안 그림), 앱 판별은 마운트 뒤에만 본다(첫 렌더는 웹과 같다).
- **앱만 다른 것은 두 가지다.** ① Google 클릭 — 웹은 같은 창에서 `/api/auth/google` 로 이동, 앱은 PKCE 준비 후 **Chrome 창(Custom Tab)** 으로 연다(Google 이 WebView 안 로그인을 `disallowed_useragent` 로 막으므로 WebView 안 이동 폴백은 없다). ② 그 뒤의 상태 — 모두 Google 버튼 **바로 아래** 한 자리: 여는 중("Chrome 창을 여는 중…"·버튼 잠김) · 대기 카드(제목·본문·힌트·[Chrome 창 다시 열기] 48px·[취소] 44px, 이메일 폼은 계속 사용 가능) · 창 닫힘(창이 닫히고 1.5초 안에 결과가 안 오면) · 10분 지남(로그인 시작 후 10분 — 서버 state 유효시간과 같다) · 취소 · 열기 실패(안내 한 줄: 기호 i/! + 글자). 마무리 중은 화면 전체 덮개("로그인 마무리 중…", 본문 `inert`+`aria-hidden`, 이동할 때까지 유지).
- **딥링크 수신**은 `AppDeepLink`(화면 요소는 덮개뿐)가 맡는다: `stockinvest://auth/callback?code=` → 검증값을 꺼내 `POST /api/auth/app-exchange` → 성공이면 `location.replace(착지 경로)`, 실패 `app_code_invalid`, 검증값 없음(앱이 다시 시작됨·10분 지남) `app_verifier_lost`(서버에 묻지 않음) / `?error=<고정 코드>` → `/login?oauth_error=<코드>`. 코드·검증값은 화면·콘솔·주소 어디에도 그리지 않는다. 대기 카드를 푸는 `OAuthButtons` 에는 값 없는 신호(`appLoginSignal`)만 보낸다.
- **오류 안내 상자**(`OAuthErrorNote` — 웹·앱 같은 상자·문구, `role="alert"` `tabIndex=-1`, 로그인 화면 간격 `0 0 16px`): `app_code_invalid`·`app_verifier_lost`(앱 전용, "아래 Google로 계속하기를 다시 눌러 주세요") · `signup_requires_web`(앱 전용 — 굵은 첫 줄 + 앱에서는 새로 가입할 수 없다는 안내 + 앱일 때만 [Chrome에서 가입 화면 열기] 44px: Chrome 창으로 `/signup`) · `email_unverified`(빨강 막대, "Google/GitHub" → "Google") · `cancelled`·`failed`·`invalid_state`·`not_configured`(기존 문구 그대로, 모르는 코드는 `failed`). 앱에서 오류가 있으면 이메일 칸 대신 오류 상자로 포커스를 옮긴다(웹은 이메일 칸 자동 포커스 그대로).
- **이메일 로그인 `oauth_account`**(소셜로 가입된 계정): T-084 의 앱 전용 문구는 삭제 — 웹·앱 공통 "Google로 가입된 계정입니다. 위의 Google로 계속하기를 눌러 로그인하세요."(서버 문구의 "아래"는 실제로는 위쪽 버튼을 가리켜 화면이 "위의"로 조립, 결정 D5 A). 서버 응답·`login/route.ts` 는 그대로.
- **`/signup`**: 웹은 그대로. 앱은 Google 버튼 숨김 유지(결정 D1 A — 앱 Google 로그인은 기존 계정만 들어오므로 가입 화면에 두면 새 사람에게 막다른 길). 가입 페이지 코드는 바뀌지 않았고 `OAuthButtons` 의 기본값(`appLogin=false`)이 앱에서 아무것도 그리지 않는다.
- **웹에서 글자가 바뀌는 곳**: ① `email_unverified` 안내 "Google/GitHub" → "Google" ② `oauth_account` "아래" → "위의" ③ 설정 › 앱 설치 3단계 ③ 문구. 안내 상자·가입 화면 안내 상자는 360px 에서 낱말이 끊기지 않게 `word-break: keep-all` 을 받는다(표시 개선).
- **옛 앱 업데이트 안내(T-091, 승인 데모 [`mockups/T-091-app-version-gate-v1.html`](../mockups/T-091-app-version-gate-v1.html) v1 대안 B)**: 앱이고 설치 build 가 Google 로그인 최소 build(`APP_FEATURE_MIN_BUILD.googleLogin` = 2) 미만이면 로그인 화면 맨 위(카드 위)에 필수 업데이트 띠 모양 "앱 업데이트가 필요합니다 / 이 버전(v…)에서는 Google 로그인을 쓸 수 없습니다. [업데이트]"(→ `/app/download/latest.apk`)를 두고 Google 버튼은 같은 자리에서 비활성 "Google로 계속하기 (업데이트 후)". 이메일 폼·구분선·첫 포커스는 그대로, 웹·build 2 이상·버전 모름·버전 읽는 중·서버 Google 설정 없음은 띠 없음, `/signup` 그대로.
- 미확인(실기기): Chrome 창 닫힘 신호(`browserFinished`)가 오는 기기·Custom Tab 구현 · `Browser.close()` 가 안드로이드에서 창을 닫는지(플러그인 문서는 Web·iOS 전용으로 적었다) · 구형 WebView 의 `inert` · `getLaunchUrl()` 이 같은 프로세스에서 새 딥링크로 바뀌는지.

### E. 아이콘·스플래시

- **확정: ② 지층형 + 금덩이**(사용자 결정 2026-10-25 18:08) — 가로 광맥층 + 솟는 캔들 3개 + 정점 금덩이. 소스는 시안 파일의 ② 레이어(background·foreground·monochrome·알림 아이콘). Designer 가 짚은 한계(48px 에서 금덩이가 작은 점, 알림 아이콘에는 금덩이 없음)는 사용자가 알고 고른 것이다.

## 6. 미해결·후속 결정

- **알림 채널**: 푸시(웹 Push API) vs 이메일 vs 슬랙 — 어느 것부터 구현?

- **놓친 기회 가격 추적**: 현재 1h 후 가격. 4h / 24h 추적 추가 여부
