# 소급 독립 검토 요청 — T-134 청산 평가: 보유 종목 상태 조회 실패의 종목 단위 격리 (이미 운영 중)

## 배경
StockInvest 의 청산 평가 엔진(`src/lib/strategy/engine.ts` 의 `runExitEngine`)은 시장 틱마다 보유 종목을 순회하며 손절·익절을 평가한다. 지금은 `DRY_RUN=true` 지만 실거래 전에 정확해야 한다. 이 변경은 10-31 에 운영 반영됐고 내부 Reviewer·QA 는 통과했다 — 당신은 **추가의 독립 적대적 검토**다.

## 결함과 수정
루프 안에서 이웃 호출(`getTicker`, `upsertPositionState`)은 try/catch 로 종목 단위 격리되는데 **`loadPositionState`(DB 조회 1회)만 격리가 없어**, 조회가 한 번 실패하면 예외가 루프 밖으로 나가 그 틱에서 아직 평가하지 않은 종목의 손절·익절 평가가 건너뛰어졌다. 수정: 이웃과 같은 모양의 try/catch — 실패 종목은 `console.warn` + `rec.error('exit_state_load_failed')` + `noteExitJudgment(exitJudg, 'error', 'exit_state_load_failed', …)` 후 `continue`. 새 게이트 ID 를 `src/lib/strategy/eval-funnel-labels.ts` FUNNEL_GATES(단계 23)와 홈 「데이터 이상」 집계 `src/lib/ops/metrics/exit-lines.ts` `DATA_ERROR_GATES` 에 추가. 시험 18개 신규 + 배선 시험 갱신 + 기존 시험 2개의 「마지막 게이트」 단언 갱신.

## 불변 조건
- 정상 경로(조회 성공)의 호출 순서·`await` 개수·분기 순서·반환값은 한 바이트도 달라지면 안 된다.
- 실패 종목은 **평가하지 않고** 시그널·쿨다운·`position_state` 쓰기·경보를 만들지 않는다(진입가를 대체하는 새 청산 경로 금지). 같은 틱의 다른 종목은 계속 평가된다.

## 수용된 설계
실패 시 크론 500 으로 터지던 것이 이제 HTTP 200 으로 끝나 `job_run_log` 에 failed 로 안 남는다(흔적은 eval_funnel 단계 23 error·홈 데이터 이상 건수·`exit_judgment` error 행·경고 로그). 반복 실패 전용 경보 없음.

## 답해 줄 질문
(a) 새 try/catch 가 정상 경로의 동작·타이밍·예외 전파를 바꾸는 경우. (b) 실패 후 `state` 변수나 이전 반복의 값이 다음 반복으로 새는 경우(TypeScript 제어 흐름, `let` 선언 위치). (c) catch 가 삼키면 안 되는 예외(프로그래밍 오류, `AbortError` 등)를 삼켜 진짜 장애를 숨기는가. (d) 새 게이트 ID 를 나열해야 하는 곳을 빠뜨렸는가(`FUNNEL_GATES`, `GATE_STAGE`, 한국어 라벨, `DATA_ERROR_GATES`, 배선 시험, `exit_judgment` 의 decision_code 길이 48). (e) 기존 시험 2개의 단언 수정이 단언 약화인가. (f) 같은 루프에 격리 없이 남은 다른 호출이 있는가(이번 변경 범위 밖이어도 보고).
읽기 전용으로 `git diff`, grep, 작은 `node -e` 로 직접 검증해도 좋다. 파일은 수정하지 말 것.
