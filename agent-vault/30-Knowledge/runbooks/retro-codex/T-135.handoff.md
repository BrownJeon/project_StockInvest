# 소급 독립 검토 요청 — T-135 기록기 풀 연결 점유 상한 + 크론 러너 임시 파일 보호 (이미 운영 중)

## 배경
StockInvest 는 Next.js + MariaDB 주식 자동매매 앱이고, 크론 러너(`scripts/cron-runner.sh`, bash)가 pm2 로 상시 실행되며 **모든 크론 잡의 HTTP 호출이 이 러너의 `call()` 을 거친다**. 이 변경은 10-31 에 운영 반영됐고 내부 Reviewer·QA 는 통과했다 — 당신은 **추가의 독립 적대적 검토**다.

## 변경 (이 diff 전체)
**A. 기록기 풀 점유.** 기록기(`src/lib/strategy/records/judgment-recorder.ts`, `job-run-log.ts`)의 DB 쓰기가 매달려도 풀(`connectionLimit 10`, 주문 승인·UI 와 공유)의 연결이 안 묶이도록, 신규 `src/lib/strategy/records/bounded-conn.ts` 가 기록 1회에 풀 연결 **하나**를 받아 모든 문장을 그 연결로 보내고 상한(4000/2500ms)에서 연결을 `destroy()`, 상한 **뒤** 늦게 받은 연결은 쓰기 없이 `release()`, 연결은 **한 번만** 끝낸다. 반환 status·집계·SQL 문장·경고 문구·상한 값은 변경 전과 같아야 한다. 카드 조회 SELECT 는 일부러 일반 풀에 둔다(조회 실패가 판단 기록을 막으면 안 됨).
**B. 러너 임시 파일.** `call()` 의 응답 본문 파일을 `/tmp/cron-runner-<pid>.out`(644) 에서 전용 0700 디렉터리 `~/.node-local/stockinvest/call-tmp` 의 `mktemp`(0600)로. 러너 시작 시 **죽은 러너 pid 의 파일만** 정리(살아 있는 pid 의 파일 보존). 비-200 응답 로그 `body=` 는 금액 키 마스킹 후 앞 200바이트. `mktemp` 실패 시 `/tmp` 폴백. umask 077 은 함수 안에서만, 러너 전체 umask 불변, 서브셸 금지(셸 변수 보존).

## 불변 조건
- `call()` 의 반환값·`CALL_LAST_CODE`·로그 줄 형식(`[ts] <label> OK` / `HTTP=<code> body=…`)·`curl` 인자·`jrl_hook` 호출 위치는 변경 전과 같다(전 잡 영향).
- 기록 실패·지연이 분석·잡 동작에 영향을 주지 않는다. 정리 로직이 살아 있는 러너(배포 겹침 구간 포함)의 파일을 지우면 안 된다.

## 수용된 한계
폴백 경로(mktemp 까지 실패)의 파일 이름은 예측 가능(변경 전과 같음) · 시작 정리의 생존 판정은 같은 PID 네임스페이스 가정 · `detail` 키는 모든 라벨의 비-200 로그에서 지워짐 · 배포 순간 옛 러너가 `/tmp` 에 644 파일을 하나 남길 수 있음.

## 답해 줄 질문
(a) `bounded-conn.ts` 수명주기: 이중 해제·누수·상한 경쟁(연결 대기 중/첫 문장 중/문장 사이/성공 직전), `release`·`destroy` 가 던질 때, `getConnection` reject, 동기 예외. (b) 문장마다 다른 연결 → 한 연결 순차로 바뀐 의미 차이: 세션 상태(autocommit, `lock_wait_timeout`, 트랜잭션), 엔진의 트랜잭션 연결과 섞이는 경우. (c) 시작 정리의 `rm`: 살아 있는 러너 파일 삭제, pid 재사용, **변수가 비었을 때 엉뚱한 경로 삭제**, 공백·글롭 문자가 든 이름, 심볼릭 링크 추종, `set -u/-e` 와 `HOME` 미설정. (d) umask 저장·복원 누수(`return`·오류 경로), `local` 변수 충돌, `$$` 의미. (e) 마스킹 후 `head -c 200` 이 멀티바이트 문자를 자르는지, 파이프 실패·빈 본문. (f) 시험이 불변을 **실제로** 고정하는가(약한 단언, 목(mock)이 실제 mysql2 와 다른 가정을 하는 곳).
읽기 전용으로 `git diff`, grep, 작은 셸/`node -e` 스니펫(임시 디렉터리)으로 직접 검증해도 좋다. 저장소 파일은 수정하지 말 것.
