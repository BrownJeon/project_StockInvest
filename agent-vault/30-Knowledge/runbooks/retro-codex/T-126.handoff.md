# 소급 독립 검토 요청 — T-126 `exit_judgment` 청산 판단 영구 기록 (이미 운영 중)

## 배경
StockInvest 는 KIS OpenAPI 로 주식을 분석·자동매매하는 Next.js + MariaDB 앱이다. 지금은 `DRY_RUN=true`(실주문 차단)이지만 시그널 생성과 **청산 평가 엔진(손절·익절)** 은 가동 중이며, 실거래로 가기 전에 정확해야 한다. 이 변경은 10-31 에 이미 운영에 반영됐고 기록 스위치도 켜져 있다(표는 비어 있음). 내부 Reviewer·QA 는 통과했다 — 당신은 **추가의 독립 적대적 검토**다.

## 변경 (이 diff 전체)
청산 평가 루프(`src/lib/strategy/engine.ts` 의 `runExitEngine`)가 보유 종목마다 내린 결론 하나를 새 표 `exit_judgment` 에 남긴다.
- 수집·기록: `src/lib/strategy/records/exit-judgment.ts` (행 빌더, 메모리 수집기, 분리 INSERT)
- 스위치: `src/lib/strategy/records/record-switch.ts` (`exit_judgment_record_enabled`)
- DDL: `scripts/migrations/T-126-exit-judgment.sql`
- 엔진에는 수집 호출만 추가됨(+51/−0): `openExitJudgment`·`noteExitJudgment`·`flushExitJudgment` 래퍼 3개와 결론 지점 호출 약 15줄.

## 반드시 지켜져야 하는 불변 조건 (깨지면 심각)
1. 기록은 청산 평가·시그널 생성·쿨다운·`position_state` 쓰기·경보에 **어떤 영향도** 주면 안 된다 (반환값·호출 순서·`await` 개수 불변, 평가 경로에 새 DB 읽기 0).
2. 기록의 실패·지연·무한 대기가 틱을 막거나 예외를 던지면 안 된다. 설계: 수집은 메모리 push 만, INSERT 는 분리 실행(다음 마이크로태스크), 전체 4초 상한, 상한에서 풀 연결 `destroy()`.
3. 스위치 `system_config.exit_judgment_record_enabled`: 키 없음 = 꺼짐, 정확히 JSON `true` 만 켜짐, 읽기 오류·2초 초과 = 꺼짐, 30초 캐시.
4. 열 값은 DDL 과 일치해야 한다: ENUM 값, DECIMAL 범위, VARCHAR 길이, NULL 규칙, `threshold_pct` 부호(손절 음수·익절 양수·트레일링/시나리오 NULL), `currency` 규칙(국내 'KRW', 해외는 어댑터가 원화 환산해 'KRW', 단위 검사 [0.3,3.0] 밖이면 NULL).

## 수용된 설계 (근거 없이 버그로 보고하지 말 것)
`run_id` 가 분 단위라 UNIQUE 를 일부러 안 걸었다(같은 분 2틱 중복 허용) · 외래키 없음 · 틱당 100행 상한 · 잔고 미확인 틱은 행 없음 · 시세·평단이 둘 다 달러 값(1배)이면 'KRW' 로 잘못 남는 알려진 한계.

## 답해 줄 질문
(a) 위 불변 조건을 깨는 경로가 있는가? 특히 `engine.ts` 의 수집 호출과 래퍼 3개가 예외·`await`·실행 순서를 바꾸는가. (b) `exit-judgment.ts` 의 행 빌더가 DDL 을 위반하거나 틀린 값을 **조용히** 저장하는 경우(범위·길이·ENUM·부호·NaN/Infinity·문자열 절단 경계). (c) 연결 수명주기(`getConnection`, `destroy`/`release`, 상한과 연결 대기 경쟁)에서 연결 누수·이중 해제·늦은 쓰기. (d) 값 바인딩/이스케이프 문제 — 종목명 등 외부 유래 문자열이 SQL 로 들어가는 방식. (e) 두 시장 틱이 겹칠 때 수집기 상태 공유(전역 변수) 가능성. (f) DDL 의 CHECK·인덱스가 정상 INSERT 를 불필요하게 실패시키는가.
