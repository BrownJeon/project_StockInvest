# 소급 독립 검토 요청 — T-128 서버·읽기 계층 후속 정리 (이미 운영 중)

## 배경
StockInvest 는 KIS OpenAPI 기반 주식 자동매매 웹앱이다(Next.js + MariaDB). 지금은 `DRY_RUN=true`. 이 변경은 10-31 에 운영 반영됐고 내부 Reviewer·QA 는 통과했다 — 당신은 **추가의 독립 적대적 검토**다. 변경은 27개 파일(+899/−149)이지만 서로 독립인 5개 작업(A1~A5)이다.

## 변경 (이 diff 전체)
- **A1** 설정 화면 초기 `Promise.all` 의 요청별 `.catch(() => null)` — `/api/settings/strategies` 한 요청이 실패해도 안전 값이 상태에 잘못 들어가지 않고 unhandled rejection 이 나지 않게. 안전 값(DRY_RUN·킬스위치)을 못 읽으면 토글 잠금 + 「값을 읽지 못했습니다」를 유지.
- **A2** 사유 코드의 한국어 사전을 한 출처로(`src/lib/ops/reason-dictionary.ts`; 이전엔 서버 `activity.ts` 와 화면 `reason-copy.ts` 두 벌) + 서버가 내는 사유 코드마다 문구가 있거나 `KNOWN_UNMAPPED` 허용 목록에 있어야 한다는 키 일치 시험.
- **A3** `broker_ledger` 표 없음(errno 1146)을 지표 계약대로 `prep` 으로 분류(이전엔 `error(not_migrated)`), 안전 읽기 레인이 허용하는 SQL 목록을 상수로 export 하고 시험이 고정, `order_rejected` 줄 사유가 비면 「사유 기록 없음」.
- **A4** 저장된 청산 사유 앞머리 `[하드 손절]`·`[EOD 손절]` 을 **표시 시점에만** `[손실한도 손절]`·`[장마감 전 손절]` 로 바꾸는 별칭 맵(`src/lib/signals/exit-reason-display.ts`). 신호 생성 경로·DB 텍스트·`exit-engine` 의 `reasonHead` 는 불변.
- **A5** 경보 문구 6건의 「킬스위치」→「모든거래차단」 용어 정정(`volatility-guard.ts`, `portfolio-snapshot/route.ts`) + 문구 울타리 시험. 발송 조건·임계 불변.

## 불변 조건
신호 생성·주문·경보 **발송 조건과 임계는 불변**. DB 에 저장된 값은 불변(표시만 변환). 안전 값(DRY_RUN·킬스위치)을 읽지 못하면 항상 **안전한 쪽(잠금)** 으로 동작. 화면의 안전 값 표시가 실제 값과 어긋나면 안 된다.

## 답해 줄 질문
(a) A1: 안전 값을 읽기 실패했는데 false(꺼짐)로 표시하거나 토글이 의도치 않게 열리는 경로, 요청 한 건 실패 시 다른 값이 오염되는 경로. (b) A4: 별칭 변환이 원문을 비교하는 코드(문자열 일치로 사유를 판별하는 곳)를 깨뜨리는지, 옛·새 앞머리가 섞여 들어올 때 이중 변환. (c) A3: `prep` 분류 변경이 홈 지표를 잘못 0 이나 정상으로 보이게 만드는지. (d) A5: 경보 조건·임계·중복 억제 로직이 정말 불변인지. (e) A2: 사전 병합 중 키 누락·덮어쓰기·순서 의존.
읽기 전용으로 `git diff`, grep, 작은 `node -e` 로 직접 검증해도 좋다. 파일은 수정하지 말 것.
