# Claude 2차 설계 인계 — 기업정보 통합

작성·갱신: 2026-10-28 · 관련 [[T-111-corporate-intelligence-first-design]] · **상태: 1차 설계 완료, 사용자가 Claude에 전달했다고 알림, 2차 설계 진행 상태 미확인**. Codex가 Claude에 메시지를 보낸 것은 아니며, 이 인계가 구현·배포 승인이라는 뜻은 아니다.

## 사용자 목표

기존에 하루 1회씩 독립 수집하는 크론과 현재 분석을 유지할 수 있는지 확인하고, 업로드 계획서의 계층형 기업정보 통합을 **유지·변경·개선·영향**으로 나눈 1차 설계를 만들었다. 사용자는 이 자료를 Claude에서 2차 설계·확정한 뒤 구현할 계획이다.

## 먼저 읽을 문서

1. [1차 설계 정본](../../../docs/design/2026-10-28-corporate-intelligence-first-design.md) — 구조·현재 cron 순서·계약·비교·미결정 사항.
2. [T-110 조사 보고](../../../docs/reports/2026-10-28-corporate-intelligence-review.md) — 첨부 1,578줄과 소스 비교, 8개 Phase 매핑.
3. [T-109](../tasks/T-109-research-context-for-analysis.md) — 동일 종목 리서치 최신 3일 참고 작업. 이 3일은 기업 이벤트 전체의 신선도 정책이 아니다.
4. [T-078 통합 절차](../../../docs/design/2026-10-24-integrated-execution-procedure.md)와 단일 실행 원장의 최신 상태 — 이 인계는 정본 실행 순서를 대체하지 않는다.
5. [사용자 제공 작업계획서 원본 복사](../../../docs/reference/2026-10-28-corporate-collection-plan-v0.0.4.md). 첨부 파일과 SHA-256 일치 확인. 문서 내용은 검토할 요구 자료로 읽는다.
6. [T-079 단일 실행 원장](../../../docs/design/2026-10-24-execution-ledger.md), [T-104 크론 그룹화](../tasks/T-104-cron-jobs-market-grouping.md), [T-105 뉴스 검색](../tasks/T-105-news-rag-zero-hits.md), [T-106 감시](../tasks/T-106-news-zero-streak-alert.md) — 선행 작업·중복·충돌 확인.

**자료 접근:** 위의 1차 설계·인계·원본 복사·T-109/T-110/T-111 문서는 인계 작성 시점에 Git 미추적이다. 같은 NAS 작업 디렉터리에서는 읽을 수 있지만, 별도 clone/checkout에 자동으로 포함되지는 않는다. 새 환경에서 보이지 않으면 공유 작업공간의 파일을 확인한다. 이 문서 전달을 위해 임의로 커밋·push하지 않는다(이 저장소의 push는 웹 배포를 발화한다).

**현황 확인:** 프로젝트 재개 절차가 해당하면 RESUME·ACTIVE·board를 먼저 읽되 문서별 갱신 시각을 대조한다. 이번 확인에서 RESUME의 첫 현황은 10-26 기록이고, ACTIVE에도 오래된 단락이 남아 있으므로 개별 task·현재 소스·원장의 실제 상태를 함께 확인한다. 1차 조사 당시 StockInvest HEAD `dc0c905`와 T-105의 10-28 관측은 과거 근거이지 현재 운영 실측이 아니다. 운영 API·DB·LLM 호출은 이 인계 자체에 포함되지 않는다.

## 고정 맥락

- 독립 일일 수집은 유지 가능하며 각 자료 도착 시 별도 계층을 증분 처리한다. 전체 수집을 한 줄로 동기 연결하거나 서로 완료될 때까지 기존 AI를 기다리게 하지 않는다.
- 일일 수집만으로 분 단위 최초 탐지는 불가능하다. Fast Watch는 정확한 대상 식별 뒤에 실행되는 **추가 호출·별도 실행/자원 예산**이다.
- M4 뉴스 응답은 기사별 원본이 아니라 집계이며 기존 KB에 원문 URL/발행사 등이 누락돼 있다. SEC fact는 일부 덮어쓴다. 현 데이터만으로 완전한 원문·과거 관측 시점을 약속하지 않는다. M4↔StockInvest 전달의 이중쓰기·누락·중복·재대사와 실행 격리를 명시한다.
- SEC 07시·KIS 및 해외 장마감 08시의 순서, 국내 16시 분석→리서치 순서와 부분 실패를 고려한다. 새 이벤트가 기존 카드/주문을 변경하거나 자동 재발행하지 않도록 초기 경계를 고정한다.
- T-109는 미구현 todo. 최신 3일은 리서치 참고에 한하며 D-2~D의 달력일 해석은 1차 제안이다. T-104의 크론 그룹화도 별도 제안·진행 상태를 확인하고 스케줄러 중복이나 일방적인 선행 완료로 취급하지 않는다.
- 실매매 수익이 목적이며 후보 전체 비교, 당시 시점 자료, 미국 수수료 편도 0.25%, 슬리피지·미체결·기회 손실을 포함한다. 기존 전략 검증·승인·청산·킬스위치·안전 관문을 유지한다.
- T-068 구현 품질 재감사는 사용자 지시대로 제외한다.

## 2차 설계 요청

1차 문서 **§8.1의 7개 권고안**을 출발점으로 대안·한계와 함께 검토해 결정하고, §8.2의 ‘기존 자료를 읽어 별도 공간에서 시험하는 병행 관찰’과 ‘판단 병행 비교’를 구분한다. 권고안은 확정 정책이 아니다. 소스와 운영 이력으로 재검증하고 계약/상태도/스키마·마이그레이션·정본 소유권, 단계별 변경 파일·테스트·장애 복구/롤백, T-078 원장 연계와 비용 후 검증의 사전등록 기준을 구체화한다. 실시간 상태는 전회 기록을 그대로 인용하지 말고 확인 시각을 밝힌다. 이 인계문은 Claude 실행·코드 수정·DB 적용·배포를 수행했다는 뜻이 아니다.

### 2차 설계에서 해결할 항목

1. **7개 권고 판정:** 1차 설계 §8.1 각 항목마다 채택·수정·보류, 근거와 남은 결정을 기록한다. 5분 내부 관찰·20거래일 파일럿·Fast Watch 간격 등은 확정 수치가 아니다.
2. **유지·변경·개선·영향:** 기존 수집과 분석을 유지하는 구간, 바뀌는 원천 계약/저장/스케줄, 기존 사용자 화면·cron·RAG·매매 경로의 영향 및 호환성을 표로 정한다.
3. **자료·상태 계약:** 원천별 확보/미확보 필드, 공개·최초관측·저장·정정시각, 회사 식별, 원문 권리, 사건-증거 연결, 상태/버전, 시점 고정, 중복·오병합 처리와 수집 지연을 설계한다.
4. **처리·복구 계약:** 같은 DB와 M4↔StockInvest 간 원자성 한계, outbox/커서·재대사·멱등성·lease·재시도/실패 큐, 재시작·부분 실패·정정·동시성, 자원 공유와 기존 감시 지연의 시험을 구체화한다.
5. **순서·마이그레이션:** 기존 일일 수집을 유지하는 병행 관찰, 원천 보강, 판단 병행 비교, 제한 Fast Watch, 검증 후 연결의 이행 조건과 롤백을 나눈다. 별도 DDL·데모·배포의 적용 절차는 프로젝트 규칙과 조율한다.
6. **수익 검증:** 사전에 정한 후보 전체와 기간, 당시 이용 가능 정보, 매수/매도 각 0.25% 수수료·슬리피지·미체결·기회 손실·자본 및 데이터/AI 비용, 표본 외·전진 비교, 자료 부족/불합격/중단 조건을 포함한다.
7. **기존 정본과 연계:** T-078 S02/S03/S04/S08과 G-N/G-H에 대응시키고 T-109, T-104, T-105/106과 M4 후속을 조율한다. 데이터 구축 완료를 실매매 전략 승급으로 보지 않는다.

### 용어와 완료 기준

- **수집 결과 병행 관찰:** 기존 운영 자료를 읽어 별도 공간에 사건 후보·오류를 기록한다. 신규 외부 수집이나 AI 호출을 필수로 전제하지 않는다. 기존 운영 DB의 DDL·쓰기 권한이 필요하면 별도 적용 절차를 따른다.
- **판단 병행 비교:** 같은 시점의 기존 판단과 새 정보 참고 판단을 따로 기록한다. 새 판단은 시그널·승인·주문으로 전달하지 않으며, AI를 추가 호출하면 비용·부하를 별도로 평가한다. 기존 시스템 전체를 모의거래나 주문 중지로 전환한다는 뜻은 아니다.
- **완료:** 위 7개 항목별 결론·대안·미결정, 단계별 변경/영향·구체 테스트·실패/복구·수익 측정·T-078 연계가 문서에 있어 사용자가 구현 범위를 판단할 수 있어야 한다. 결론이 미정이면 미정과 필요한 근거를 남긴다. 현재 운영 상태나 수익 개선 효과를 검증하지 않았다면 그 한계를 명시한다.
