# Claude 인수인계 — StockInvest 개편 작업

## 1. 이번에 받은 요청과 현재 완료 범위

사용자는 인터뷰 후 개편안 작성을 요청했고, 이어서 **기존 T-064와 합친 하나의 작업절차서**를 요청했다. 이제 실행 정본은 [통합 작업절차서](../../../docs/design/2026-10-24-integrated-execution-procedure.md)다. T-064와 [T-077 개편안](../../../docs/design/2026-10-24-portfolio-restructure-plan.md)은 상세 근거/이력, [인터뷰](2026-10-23-project-direction-interview.md)는 정책 근거로 보존한다.

T-077은 개편안 작성, T-078은 통합 절차서 작성이라는 **문서 작업**이다. 이를 구현·운영 전환 완료 또는 포괄 실행 승인으로 취급하지 않는다. 코드/DB/설정/주문/알림 변경, 커밋·push·배포는 이번 문서 작성에서 하지 않았다.

## 2. 읽는 순서

1. 프로젝트 `CLAUDE.md`와 실제 적용되는 상위 지침. Codex는 `AGENTS.md`도 확인.
2. [RESUME](../../00-Context/RESUME.md) 최상단 T-078 항목 → [ACTIVE](../../00-Context/ACTIVE.md) → [board](../board.md).
3. [통합 절차서](../../../docs/design/2026-10-24-integrated-execution-procedure.md)의 §2 정책 → §4 대응표 → §5 H/N 관문 → §6 S단계 → §9 결정 목록 → §12 시작 지시문.
4. [T-078](../tasks/T-078-integrated-execution-procedure.md)의 통합/검토 범위와 judge 기록. 상세 근거가 필요할 때만 T-064/T-077의 해당 절을 읽는다.
5. 작업하는 영역의 기존 task·소스만 추가 확인. 옛 RESUME·개편안의 숫자를 현재 운영 상태로 사용하지 않는다.

## 3. 반드시 유지할 결정

- 현재 자산으로 재편하고 미국·국내의 현재 별도 자금 구획을 유지한다. 자동 자금 이동이나 새 70/30 비율을 만들지 않는다.
- 실제 기존 보유 전체와 ETF를 포함해 두 시장 합산 최대 10종목. 신규 슬롯 예약까지 공통 관리한다.
- 매수·추가매수 후보를 공동 평가·배분·예약한다. 개별 시그널이 같은 전액 예산을 반복 사용하는 구조를 없앤다.
- 보유가 새 종목/업종 한도를 넘으면 분석·점수화 후 우선순위로 점진 축소한다. 점수 방향과 구체 한도는 검증할 초안이다.
- 월 손실 5%는 재평가와 필요한 매도·축소의 계기다. 신규·추가 매수는 그때 별도 판단하며 월 손실만으로 일괄 중지하지 않는다. 모든 판단은 공통 한도와 기존 안전장치를 지킨다.
- 일반 매도는 차트·뉴스·실적·기업 전망을 함께 판단한다. 기존 exit-engine을 켜는 것만으로 새 정책을 구현했다고 하지 않는다.
- 기본 3개월 만료 시 재평가하고, 보유 연장은 근거·제안 기간으로 사용자 직접 승인을 받는다. 미응답은 보유·재알림이며 기존 위험 점검은 유지한다.
- 유료 데이터는 기존 웹검색·공식 원천 집계 결과를 먼저 확인한 후 결정한다. 서버·AI 구독료는 이번 비용 검토에서 제외한다.
- 통상 운용은 합의한 기준 안에서 자동, 기준 밖만 직접 승인하는 것이 목표다. 현재 운영 스위치를 바꿀 수 있는 포괄 승인은 아니다.

## 4. 첫 작업 — S00 대조 보고서

첫 턴에서 바로 새 자동매매를 켜지 말고 다음 결과를 만든다. 미정 숫자를 임의로 채우거나 이미 답한 인터뷰를 되풀이하지 않는다.

1. 현재 HEAD·변경 파일과 실행 중인 다른 작업의 소유권을 확인한다. T-077 시작은 `330314e545b5dbfa1c9523ea68f134cc91bb2042`, T-078 시작은 `e0aadadf1604a15b269a6c2a240eefa2b778b400`였고 다른 작업의 변경이 있다. 이를 현재 HEAD로 고정하지 않는다. `git add -A`, stash/reset/clean 등 일괄 정리는 하지 않는다.
2. 현재 소스·DB 스키마·배포 버전·안전 설정을 허용된 읽기 전용 범위에서 대조한다. 새로운 권한이 필요하면 구체 범위를 제시한다. 문서의 과거 배포 성공·테스트 수치를 현재 확인으로 대체하지 않는다.
3. 최신 보유·시장별 자금·주문 가능 금액·미체결·원가/현금 불일치를 대사한다. 인터뷰의 과거 5종목과 다른 기록의 3종목을 현재 사실로 합치지 않는다.
4. T-071 WP-2/3, T-072 후속, T-074 기준 정하기, T-076 취소 후속의 남은 실제 범위를 확인한다. 이미 구현한 기능을 새로 만들지 않는다.
5. 결과를 `확정 정책 / 현재 구현 / 차이 / 미정 값 / 단계별 작업과 완료 조건` 표로 작성한다. 민감한 계좌 상세는 기존 git 제외 로컬 보고서 위치를 사용하고 버전관리 문서에는 필요한 요약·시점·미확정 여부만 남긴다. 키·토큰·계좌번호는 기록하지 않는다.
6. 하위 작업은 기존 task를 재사용하거나 실제 새 ID를 확보해 생성하고, Judge→설계→독립 검토→QA의 적용 순서를 남긴다. 이 문서가 미래 task ID를 미리 확보하지 않는다.

S00 보고서가 나온 뒤 통합 §6의 실행 원장에 남은 작업을 연결한다. S01 장부와 S02 데이터의 독립 범위, H 기존 보유 관리와 N 신규 매수 검증을 구분하고 S03~S09의 선행/통과 조건을 따른다. 옛 Phase/A 단계는 별도 실행하지 않는다.

## 5. 재사용할 구현과 함정

- T-072 매수 검증 관문은 이미 있다. `validation-gate.ts`와 송신 전 재확인을 보존한다. 전략 귀속이 없는 시나리오 매수를 관문 제거로 뚫지 않는다.
- T-071 체결 대사의 CAS·결과 불명·부분체결 추적을 보존한다. 다만 거래 원가/통화/비용 WP-2와 공유 예약 WP-3가 끝났다는 뜻은 아니다.
- T-074 자산 원장은 실제 체결 원가 장부와 다르다. 기준 설정·현금 의미를 확인하지 않고 월 손실/순수익 정본으로 연결하지 않는다.
- 개별 현금 점검과 `(symbol,direction)` 락은 계좌 공동 예산 예약이 아니다. 금액 예약과 두 시장 공통 슬롯을 같은 원자적 경계로 보호해야 한다.
- 현금 스냅샷과 예약 반영 상태의 시점을 짝지으며 송신 전에 다시 확인한다. 매도도 여러 사유가 같은 수량을 중복 약정하지 않도록 공통 수량 선점이 필요하다. 조건부 매수 유효기간은 3개월 보유기간과 분리한다.
- 기존 holding-checker는 알림 후 deadline을 NULL로 지운다. 이 경로를 그대로 쓰면 승인 대기·재알림 상태가 사라진다.
- 기존 max10·월5% 표시 상수, 24h Kill Switch, 동일 종목 24h 발화 횟수 제한은 각각 다른 기능이다.
- 기존 SP500_TOP50은 새 Nasdaq100+자체 NYSE50 후보군과 다르다. 국내 후보군도 원천을 확인해 이름만 바꾸지 않는다.
- 과거 2% heat·3% stop·6%/10% 한도·4회 분할·8주 섀도우를 이번에 새로 승인된 숫자로 쓰지 않는다. 자동 삭제도 하지 말고 정책 대조 후 처리한다.

## 6. 검증·권한·진행 원칙

- 점수 항목·한도·월 계산 공식·기간 정책의 새 값은 초안/모의/운영 승인 상태를 구분한다. 단순 구현 선택은 담당자가 근거를 남기며 진행한다.
- 모의·읽기 작업은 미정 투자 수치 때문에 전부 멈추지 않는다. 실제 운용에 필요한 미정 값은 근거 있는 정책안으로 묶어 검토받는다.
- 테스트는 모의 KIS·격리 DB에서 수행한다. 공유 운영 DB로 테스트하거나 부팅 DDL을 유발하지 않는다. 타 세션의 현재 의존성/테스트 문제를 보존하고 기준 차이를 명시한다.
- 백테스트·전진 모의와 전략 검증 승급은 결과 증거가 필요하다. 수익률 목표·승률·분석 점수로 합격 증거를 대체하지 않는다.
- 화면은 Designer 데모 승인 후 구현한다. 412px 모바일과 900px 이상 데스크톱 기준 유지.
- 코드 변경의 독립 Reviewer·안전 훅 scope·QA를 생략하지 않는다. T-077 문서 검토는 미래 안전 코드의 커밋 승인 기록이 아니다.
- 운영 마이그레이션·새 비용·실거래 전환·push/배포는 유효한 별도 권한을 확인한다. push는 webhook 배포를 발화한다.
- 해당 문서 task의 judge 원문과 문서 검토 범위를 읽는다. 문서 R0 판정이나 Codex 내부 재귀 검토 예외를 실제 구현/Claude 환경의 자동 면제로 쓰지 않는다. Claude는 그 환경의 judge/Codex 절차를 따른다.
