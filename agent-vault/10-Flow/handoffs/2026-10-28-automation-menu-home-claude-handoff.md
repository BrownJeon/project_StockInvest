# Claude Code 인수인계 — 자동매매 중심 메뉴·홈·분석·비서 개편

> **인계 완료 — 2026-10-28:** 사용자가 이 개편안을 Claude Code에 전달했다고 확인했다. Claude 측 [[T-108-automation-menu-home-overhaul]]에 접수·최신 상태 대조·Judge 판정이 기록돼 있다. T-108은 현재 `proposed`, 데모는 `drafting`이며 지표 계약·데모 제작과 착수 순서 결정이 남아 있다. 이 문서의 아래 조사 및 작업 트리 내용은 작성 시점의 기록이다. 특히 T-101·T-102는 이후 운영 반영됐으므로 T-108과 최신 ACTIVE를 우선 확인한다.

## 1. 목적과 현재 완료 범위

사용자는 StockInvest를 종목을 찾아보는 앱에서 **자동매매의 판단·운용·결과를 확인하는 앱**으로 개편하려 한다. 종목분석 보완 이후 약 한 달간 추이를 관찰하고 실거래 여부를 판단할 계획이다.

[확실] 이 대화에서 완료한 것은 소스 조사·개편 추천·메뉴명 및 아이콘 선택·문서 작성이다. **화면 코드·메뉴·API·DB·안전 설정은 변경하지 않았고, 데모 제작·사용자 데모 승인·커밋·push·배포도 하지 않았다.** 이전에 작성한 문서는 [메뉴명·아이콘 결정](../../../docs/design/2026-10-27-navigation-icon-decisions.md)이다.

이 문서는 Claude Code가 맥락을 다시 질문하지 않고 **최신 상태 대조 → 작업 접수 → 데모 제작**부터 진행할 수 있게 하는 인계서다. 모든 추천안이 최종 승인됐다는 뜻이나 실거래·설정 변경 권한을 부여하는 문서로 해석하지 않는다.

## 2. 사용자 요구와 확정 수준

### 2.1 사용자의 핵심 발화

- 최초 요청: 현재 5개 메뉴와 구조를 파악하고, 자동매매 컨셉의 메뉴·대시보드·분석 개편을 추천해 달라. 즐겨찾기 대신 챗봇을 두는 방안을 생각 중이다.
- 메뉴명: **"AI 비서 -> 비서 , 자동매매 -> 거래"**.
- 홈: **"기본적으로는 홈화면에서 종합적인 정보가 있어야"** 하고, 투자현황은 자동매매 기준 데이터로 변경해야 할 것 같다. **"보유/관심/내일 같은 항목이나 차트는 불필요하니 제거해도 될것같아"**.
- 아이콘: **"분석은 'scan-search'로 해주고 거래는 'handshake', 비서는 'brain' , 홈은 'stone'으로 변경해줘"**.
- 이번 요청: **"현재까지 개편안에 대하여 클로드코드에서 진행할 수 있도록 인수인계서 작성해줘"**.

### 2.2 그대로 계승할 사항과 데모 검토 사항

| 구분 | 내용 | 처리 |
|---|---|---|
| 사용자 지정 | 메뉴명 `거래`·`비서` | 이전 명칭 자동매매·AI 비서로 되돌리지 않는다 |
| 사용자 지정 | 홈 `stone`, 거래 `handshake`, 분석 `scan-search`, 비서 `brain` | 지정 아이콘으로 제작한다 |
| 사용자 요구 방향 | 홈의 종합 정보 유지, 투자현황을 자동매매 기준으로 개편 | 지표 정의와 데이터 연결을 함께 설계한다 |
| 사용자 제거 의견 | 홈의 보유/관심/내일 탭과 종목 차트 제거 | 제거안을 기본으로 데모에 반영하되 필요한 상세 기능은 이전한다 |
| 기존 추천 유지 | 설정 이름과 `settings` 아이콘 | 사용자가 별도로 지정한 아이콘으로 오기록하지 않는다 |
| 제안·데모 검토 대상 | 하단 순서 `홈 / 거래 / 분석 / 비서 / 설정`, 홈 섹션·지표, 분석 3분류, 거래 하위 구조, 비서 조회 범위 | 구체 데모에서 검토받는다 |
| 아직 없음 | 전체 화면 데모 승인·데모 생략 승인 | 아이콘 선택이나 인계 요청으로 승인 상태를 만들지 않는다 |

이미 정한 이름·아이콘을 재질문하지 않는다. 미정 사항은 가능한 기본안을 데모로 구체화하고 필요한 차이만 함께 검토받는다.

## 3. Claude Code에서 처음 읽을 것

1. 적용되는 워크스페이스·프로젝트 `CLAUDE.md`와 역할 지침.
2. [RESUME](../../00-Context/RESUME.md) → [ACTIVE](../../00-Context/ACTIVE.md) → [board](../board.md). 날짜를 대조한다. 이번 확인에서는 ACTIVE 최상단이 10-27 21:50이고 RESUME 최상단은 10-26으로 더 오래됐다.
3. 이 문서와 [메뉴명·아이콘 결정](../../../docs/design/2026-10-27-navigation-icon-decisions.md).
4. [기존 개편 인계](2026-10-24-claude-restructure-handoff.md)와 [통합 실행 절차서](../../../docs/design/2026-10-24-integrated-execution-procedure.md)의 관련 정책. 이번 UI 개편은 기존 운용 정책·원장 작업을 대체하지 않는다.
5. [워크스페이스 데모 검토 절차](../../../../docs/demo-review-gate.md), 프로젝트 `docs/screens.md`, 실제 `BottomTabs.tsx`와 대상 화면. **문서와 코드가 불일치하므로 현행 구현은 코드로 대조한다.**

운영 서버의 최신 상태는 이번에 직접 조회하지 않았다. 아래 운영 관련 사실은 명시한 문서 시점의 기록이다. 이를 현재 DB 설정·실계좌 수치로 단정하지 않는다.

## 4. 확인한 현재 구조와 재사용 지점

[확실] 실제 하단 메뉴는 다음과 같다.

| 실제 메뉴 | 경로 | 현재 역할 |
|---|---|---|
| 대시보드 | `/` | 자산·투자현황·트레이딩 보드·전략·깔때기·최근 체결·보유/관심/내일·차트·내 결정 |
| 즐겨찾기 | `/favorites` | 종목 저장·메모·재무 정보·리서치 추적 대상 관리 |
| 추천 | `/recommend` | 승인 대기·승인/거절·진입 감시·직접 시나리오 |
| 분석 | `/analytics` | 리서치분석·포트폴리오·포지션 추적·주도주·투자일지·놓친 기회·거래 이력·신호 진단 |
| 설정 | `/settings` | 계좌·안전장치·승인 방식·전략·LLM·알림·앱 설정 |

- `/ai`의 채팅 화면과 채팅 API는 이미 구현돼 있으나 하단 탭에서 빠져 있다.
- `/strategy`의 전략·분석가 운영 화면도 재사용 후보다. `/order`는 독립 주문 화면이 아니라 `/strategy`로 이동한다.
- `docs/screens.md`는 대시보드/추천/채팅/분석/설정이라고 기술해 실제 하단 바와 다르다. AGENTS의 주문/전략 목록도 현행 코드와 다르다.
- `SafetyBar` 구현은 존재하지만 기존 조사에서 실제 화면 사용처는 확인되지 않았다. 현재 홈에 표시된다고 가정하지 않는다.
- 이 대화의 브라우저 확인은 로그인 화면까지만 가능했다. 로그인 후 시각 감사·실데이터 검증을 마쳤다고 쓰지 않는다.

### 4.1 메뉴와 경로 개편 제안

| 제안 메뉴 | 아이콘 | 범위 | 초기 경로 권고 |
|---|---|---|---|
| 홈 | `stone` | 운용 종합 요약 | `/` 재사용 |
| 거래 | `handshake` | 후보·승인·진입 감시·보유·주문·운영 기록 | `/recommend` 및 기존 상세 화면 재사용 검토 |
| 분석 | `scan-search` | 종목분석·추이/검증·성과 | `/analytics` 재사용 검토 |
| 비서 | `brain` | 운영 데이터 조회·비교·설명 | `/ai` 재사용 |
| 설정 | `settings` | 계좌·기본 정책·알림·앱 등 | `/settings` 재사용 |

새 `/trade` 등의 URL은 아직 결정하지 않았다. 이름 변경만을 위해 새 경로를 만들 필요는 없다. 경로를 바꾼다면 기존 URL·`/analytics?tab=orders` 등 딥링크·대시보드 링크·텔레그램/앱 링크의 호환 방식을 먼저 정한다.

로그인/가입 등에서 하단 바를 숨기는 `BottomTabs.HIDDEN_PATHS` 동작을 보존한다. 메뉴 이동을 이유로 인증 공개 경로를 추가하지 않는다.

아이콘은 Lucide 원본을 사용한다. `package.json`에는 현재 `lucide-react`가 없으므로 기존 자산 방식을 확인한 뒤 필요한 패키지 또는 공식 SVG 사용 방식을 정한다. 추천 스타일은 동일한 선 굵기·약 24px·선택 메뉴만 기존 강조색이며, 실제 수치는 데모 검토 대상이다. 임의 그림이나 이모지로 지정 아이콘을 대체하지 않는다.

## 5. 홈 개편 제안

홈의 목적은 **정상적으로 분석하는가 → 무엇을 확인해야 하는가 → 자금·거래·보유 위험은 어떤가**를 한 번에 확인하는 것이다. 개별 종목 탐색이나 상세 조작은 해당 메뉴로 연결한다.

### 5.1 기본 섹션 순서

| 순서 | 영역 | 표시 내용·이동 |
|---|---|---|
| 1 | 현재 상태 | 관찰/실거래/중지 상태, 신규 매수 허용 여부·차단 이유, 마지막 정상 분석·데이터 기준 시각 |
| 2 | 확인 필요 | 승인 대기·주문 오류·데이터 이상·보유 위험 등 조치가 필요한 항목과 해당 상세 링크 |
| 3 | 운용현황 | 운용 자금 요약과 단계에 맞는 핵심 지표 4개 |
| 4 | 오늘의 분석·판단 | 분석 완료 → 후보 → 보류/진입 감시/주문 결과, 주요 제외 이유. 깔때기는 요약하고 상세 연결 |
| 5 | 최근 활동 | 분석 완료·후보 변경·체결·오류 등 최근 3~5개. 관찰 중에도 활동이 보이게 구성 |

예시 문장은 합성 데이터로 작성한다: "분석 관찰 중 · 마지막 분석 정상 · 신규 매수 차단 · 후보 제외 사유 확인". 실제 운영 상태와 분리된 목업 샘플임을 표시한다.

### 5.2 홈에서 제거·축소할 것

| 현재 요소 | 처리 제안 |
|---|---|
| 보유/관심/내일 가로 탭과 목록 | 홈에서 제거. 보유 상세는 거래, 관심/분석 대상 관리는 분석, 유효 진입 시나리오는 거래로 이전 |
| 종목 선택·봉 주기·캔들 차트·종목 고저/거래량 | 홈에서 제거하고 종목 분석 상세에서 제공 |
| 트레이딩 보드의 긴 포지션 카드 | 홈에는 운용 포지션·미체결·위험 요약만. 상세는 거래 |
| 운용 전략 전체 목록 | 활성·검증 상태 한 줄과 거래 상세 링크로 축소 |
| 평가 깔때기 전체 | 오늘 판단 요약으로 축소하고 분석/진단 상세 연결 |
| 내 결정 | 거래의 운영 기록·매매 상세로 이전 |

홈에서 종목 목록을 제거해도 **보유 위험·미체결·승인 대기 요약과 상세 진입점은 남긴다.** "내일"이라는 고정 명칭 대신 해당 시장 세션의 유효 후보·다음 분석 예정 시각을 사용한다.

운영 단계에 따라 홈 우선순위와 지표를 바꾸되, 보기 모드 전환이 실제 거래 스위치를 바꾸는 동작으로 연결되지 않게 한다.

## 6. 투자현황 → 운용현황: 집계 의미부터 변경

### 6.1 현재 지표의 실제 의미

[확실] `Dashboard.tsx`의 `AutoTradingStatusCard`는 다음 값을 표시한다.

| 현재 라벨 | 현재 계산 | 그대로 재명명하면 생기는 문제 |
|---|---|---|
| 승인 대기 | 해당 상태 시그널 조회 결과 길이, 최대 100개 | 전체 건수와 다를 수 있음 |
| 진입 감시 중 | `approved_pending_entry` 조회 결과 길이, 최대 100개 | 전체 집계·출처 구분 필요 |
| 오늘 체결 | 최근 주문 20개 중 KST 오늘 생성, 상태 `accepted/filled/partially_filled/dry_run`인 주문 수 | 접수·모의 주문 포함, 실제 체결일 집계 아님, 최근 20건 한정 |
| 포트폴리오 오늘 | 현재 계좌 총평가액과 KST 자정 이전 최신 스냅샷의 차이 | 기존 수동 보유·현금·입출금·환율 영향 포함, 자동매매 손익 아님 |

`/api/analytics/portfolio`의 기간 수익률도 총자산 단순 증감이다. 입출금 보정 성과로 사용하지 않는다. `computeMonthlyReturn()`은 구현돼 있으나 기존 조사에서는 시험을 제외한 생산 코드 연결이 확인되지 않았다. 재확인 후 원장 완전성·월 경계 등 선결조건을 검토한다. 상세는 [[T-081-s01-ledger-cost-monthly-metric]].

### 6.2 단계별 추천 지표

| 분석 관찰 기간의 기본 지표 | 실거래 단계의 기본 지표 |
|---|---|
| 분석 완료 종목 | 진입 감시 |
| 분석 후보 종목 | 운용 포지션 |
| 사후 결과 추적 표본 | 오늘 실체결 |
| 데이터 이상·분석 실패 | 자동매매 손익 |

실거래용 자금 요약은 자동매매 운용액·신규 매수 가능 금액을 제안했다. 정확한 귀속 범위와 계산법은 아직 확정하지 않았다.

### 6.3 구현 전 Analyst/Leader가 정할 데이터 계약

각 지표별로 **대상 집합·기간/거래일·집계 단위·데이터 출처·통화·비용·기준 시각·완전성**을 표로 정한다.

- 계좌 전체와 자동매매 귀속을 구분한다. 기존 수동 보유를 자동 관리 대상으로 편입하는 정책은 별도이며 이번 UI 이동이 편입 승인이 아니다.
- 관찰 결과·가상 진입/가상 성과·실거래 성과를 명시적으로 구분한다. 관찰 중이라는 이유로 `DRY_RUN=true`나 완전한 모의 체결 엔진이 있다고 가정하지 않는다.
- 실제 체결은 체결 증거와 실제 체결 시각으로 집계한다. 접수·거부·취소·결과 불명·DRY_RUN을 성공 체결에 넣지 않는다. 부분체결의 수량·잔량·중복 집계 규칙을 정한다.
- 실현손익·평가손익·비용을 분리하고 비용 중복 차감과 원가 미상 거래의 거짓 손익을 막는다.
- 미국 주력: 미국 거래일/세션과 KST 표시 시각을 구분하고 DST를 고려한다. 국내 데이터와 합칠 때도 시장·기간 기준을 명시한다.
- USD 원금액과 KRW 환산액을 구분하며 환율 기준 시각을 표시한다. 주문 가능 금액·순예수금·총예수금·예약금은 같은 값으로 취급하지 않는다.
- `0`은 확인된 영값일 때만 표시한다. 미수집·조회 실패·오래됨·표본 부족은 각각 표시하며 마지막 정상값을 현재값처럼 보이지 않게 한다.
- 최신 N건 목록 길이로 전체 일계·상태별 건수를 만들지 않는다. 필요하면 범위가 정의된 읽기 전용 집계 API를 설계한다. 새 엔드포인트·스키마는 아직 확정하지 않았다.

## 7. 거래 메뉴 제안

현재 추천·전략·보유/주문 기능을 다음처럼 묶어 검토한다.

| 하위 구분 | 주요 내용 |

화면 개편을 이유로 주문 경로·확인 단계·D5 검증 관문을 변경하지 않는다. 실제 주문은 기존 `submitOrder()`를 경유한다.

### 8.1 즐겨찾기는 탭을 바꾸고 입력 기능을 보존

- `stock_favorites.research_enabled=1`은 리서치 추적 대상이다.
- 즐겨찾기는 `getAlwaysIncludeSymbols()`를 통해 국내·해외 전략 분석 대상에도 편입된다.
- 미국 재무데이터 수집 대상에도 포함되고, 주도주 화면의 별표 버튼도 즐겨찾기 API를 사용한다.
- 홈의 관심 종목 `watchSymbols`는 별도 저장·기능이다. 즐겨찾기와 같은 목록이라고 가정하지 않는다.

따라서 하단 즐겨찾기를 비서로 바꿔도 종목 추가/삭제·메모·추적 설정·상세 링크와 데이터 수집 입력은 보존한다. 단순 메뉴 정리에 DB 삭제나 분석 유니버스 변경을 끼워 넣지 않는다. 개인 저장·분석 추적·실거래 허용의 의미를 분리해 설계한다.

### 8.2 한 달 관찰에 필요한 추이·검증

- 당시 후보/분석과 이후 D+1·3·5·10 결과, 비용 가정과 비교 기준, 표본 수·추적 대기·가격 없음.
- 조건 충족·후보 제외·검증 차단·진입 보류 이유와 분석/데이터 실패 추이.
- 추천 당시와 현재의 분석 차이, 적용 전략 버전·분석 시각. 현재 재계산 결과를 과거 판단으로 표시하지 않는다.
- 리서치분석은 관찰용이며 실제 전략 엔진과 별도 경로다. 매매에 사용된 판단과 관찰용 통계를 구분한다.
- `paper_fills`는 가상 진입 재료이며 완전한 청산·손익 계산을 제공한다고 단정하지 않는다.
- [[T-095-postmortem-script-p1]]의 사후검증 결과를 재사용 검토한다. 스크립트의 Markdown/JSON 결과를 앱에서 이미 볼 수 있는 것으로 오인하지 않는다.
- 현재 리서치 저장은 종목·날짜별 upsert라 당일 재분석이 이전 값을 대체할 수 있다. 당시 판단 이력에 필요한 불변 기록/보존 정책은 새 설계 항목이다. DDL 필요 시 별도 검토한다.

## 9. 비서 메뉴 제안

### 9.1 재사용 가능한 것과 부족한 것

[확실] `/ai`에는 대화 목록·기록 저장·질의 정제 단계·모델 선택 기능이 있다. `context-builder.ts`는 최대 3종목의 시세와 일봉 60개에서 기술지표를 붙인다. 기존 메시지 경로는 종목 컨텍스트·최근 대화·투자 성향을 사용한다.

계좌 보유·운영 상태·시그널/주문·검증/사후 성과를 조회하는 연결은 기존 조사에서 확인되지 않았다. 메뉴 노출만으로 운영 비서가 완성되는 것은 아니다.

### 9.2 1차 범위 권고: 조회·비교·설명

| 시작 질문 | 연결할 읽기 데이터 |
|---|---|
| 오늘 왜 매수하지 않았어? | 분석 실행·후보·제외/차단 사유 |
| 이 종목 분석이 지난주보다 어떻게 바뀌었어? | 당시 분석 이력·현재 결과·전략 버전 |
| 이번 주 후보들의 이후 결과는 어때? | 후보 이력·동일 기준 사후 성과·표본 완전성 |
| 지금 확인할 문제가 있어? | 분석/데이터 갱신·주문·원장 수집 상태 |

- 답변마다 기준 시각·조회 기간·근거 데이터와 상세 화면 링크를 제공한다.
- 없는 데이터·불완전한 원장·오래된 결과를 명시하고 수치나 승률을 생성하지 않는다. 계산은 서버의 공통 지표로 하고 LLM은 설명한다.
- 종목·주문·진단 상세에서 "이 내용 질문하기"로 해당 맥락을 전달하는 안을 검토한다.
- 1차 비서는 주문 제출·승인·취소·킬스위치 해제·설정 변경 권한 없이 설계한다. 관련 요청은 필요한 기존 화면으로 안내한다.
- 계좌 정보를 붙이기 전에 대화 소유권·계좌 접근 권한·사용자별 데이터 범위를 검토한다. 현재 조사만으로 완결된 보안 판정이 내려진 것은 아니다.
- 허용된 서버 조회 도구/집계만 사용하고 임의 SQL 실행이나 전체 계좌 자료를 프롬프트에 넘기는 방식을 피한다. 외부 LLM 전송 범위도 정한다.
- 기존 가격 텍스트에 일괄 `원` 표기가 있어 미국 종목의 통화 표시를 점검한다.
- 기존 질의 정제·모델 선택 단계를 홈 이용 흐름에 그대로 강제할지는 데모에서 검토한다. 구현됐다는 이유로 기능을 삭제하거나 유지로 확정하지 않는다.

- 이전 자문 intake는 `advisory-menu-20261027`, `engine=rules`, `fallback=budget_window_closed`, `risk=R2`, `demo=full/designer`였다. 현재 구현 task의 접수·승인을 대신하는 결과는 아니다.
- Leader가 `check.mjs`로 상태를 관리하고 Designer가 `mockups/<task-id>-<slug>-v<N>.html`을 작성한다. `demo_gate`를 손으로 승인 상태로 쓰지 않는다.
- 홈의 관찰·실거래, 정상·빈·로딩·조회 실패·오래된 데이터·검증 차단 상태를 포함한다. 주문 등 위험 CTA가 있으면 기존 확인·취소·실패·차단 흐름을 모두 표현한다.
- 합성 데이터만 사용하고 운영 API 호출·실계좌 정보·비밀·외부 URL 로딩을 넣지 않는다. 실제 `globals.css` 토큰을 스냅샷으로 사용하고 360/412px 및 900px 이상 데스크톱 복원을 확인한다.
- 승인 전 화면 코드를 쓰지 않는다. 데모가 승인되면 해당 버전을 명시한 가이드와 `check` 통과를 기준으로 구현한다.

### 11.2 검증·배포 범위

- 새 작업 환경의 훅 설치/검증은 프로젝트 규약대로 수행한다. 안전 경로 목록은 `scripts/git-hooks/commit-msg`가 정본이다. 해당 파일을 커밋하려면 실제 독립 Reviewer의 일치하는 scope 판정이 필요하다. 자체 판정 작성·과거 무관 task 차용·에이전트의 `--no-verify`는 금지다.
- 테스트/화면 실행은 기존 정책을 따른 격리·합성 환경을 사용한다. 개발과 운영의 DB가 공유되므로 검증을 위해 운영 데이터를 쓰거나 부팅 DDL을 유발하지 않는다.
- 의미 있는 검증: 접수와 체결 구분, 부분체결 중복, 최근 N건 초과 집계, 거래일 경계/DST, 수동·자동 귀속, 비용/입출금/환율 구분, 실패값과 0 구분, 분석 대상 보존, 대화/계좌 권한, 딥링크 호환.
- 화면 검증: 하단 5탭·짧은 메뉴명·지정 아이콘, 360/412px 잘림, 하단 safe-area·키보드 겹침, 데스크톱 복원, 상승 빨강/하락 파랑, 지표의 기준 시각·빈/오류 상태.
- `src/**` 중심의 웹 변경이면 웹 배포 범위다. `android/**`·Capacitor 설정·앱 셸 등 네이티브를 변경해야 할 근거가 생기면 별도 APK 절차와 승인을 적용한다.
- push는 webhook 배포를 발화한다. 문서 전달만을 위해 임의 push하지 않는다. DDL·실거래/안전 설정·알림 발송·APK 공개는 이 문서로 승인되지 않았다.

## 12. 인수자가 결정할 세부 설계

아래는 사용자가 아직 고르지 않은 구현/화면 세부사항이다. 가능한 항목은 권고안으로 구체화해 데모와 지표 계약에서 함께 검토한다.

1. 경로 재사용 또는 새 URL/리다이렉트 정책 — 초기에는 기존 경로 재사용 권고.
2. 자동매매 운용 자금·기존 수동 보유·시스템 관리 포지션의 표시 귀속 — 기존 운용 정책을 계승하고 새 편입은 별도 판단.
3. 관찰/실거래 홈의 4지표와 세부 배치 — §5~6 기본안.
4. 분석 3분류 및 거래 하위 분류의 상세 이름·진입점 — §7~8 기본안.
5. 비서 첫 조회 도구·데이터 전송 범위와 권한 — 조회·비교·설명부터, 미연결 질문의 한계 표시.
6. 당시 분석·전략 버전·비용 가정·후속 결과의 보존 방식 — 기존 장부/결과와 중복하지 않게 설계.

전체 추천안을 이미 승인된 설계로 주장하거나, 반대로 결정된 아이콘·메뉴명까지 모두 처음부터 질문하지 않는다.
