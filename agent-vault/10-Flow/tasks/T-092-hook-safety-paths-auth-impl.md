## Leader 기본 방침

1. 훅 **판정 로직은 바꾸지 않는다**(`SAFETY_PATHS` 배열 항목 + 근거 주석 + 시험 + CLAUDE.md 문구만). 앱 런타임 코드(`src/**`)는 건드리지 않는다.
2. 파일 단위 정확 일치(`^…\.ts$`)를 쓰고, 디렉토리 전체는 `profile/password/` 하나만(그 아래가 라우트와 그 시험뿐이므로). 이웃 파일(예: `login-gate.ts`)이 새지 않게 한다.
3. **프로젝트 원칙 "테스트 파일은 제외하지 않는다"** 를 따른다 — 1~4번 구현의 시험 파일도 같이 넣는다(Leader 판단, 5번은 디렉토리라 시험 포함, 6번은 그 자체가 시험). 실제 시험 파일 경로는 Developer 가 `git ls-files` 로 확정하고 task 에 적는다.
4. 6곳 **밖으로 넓히지 않는다.** 훅 안에 넣을지 애매한 이웃 파일(`src/lib/mail/header-safe.ts`·`signup-request-mail.ts`·`config.ts` 등)은 목록에 넣지 말고 "후보"로 task 에 적어 사용자에게 알린다.
5. push 는 하지 않는다(승인 따로). 로컬 커밋 + main ff 병합(=이 서버 훅 활성화)까지.
6. 격리 worktree 에서 작업한다(남의 push 한 번에 미검증 코드가 배포되는 것 방지). 안전 경로 커밋이므로 Reviewer 판정 줄 필요 — worktree 에 이 task 파일 사본이 있어야 훅이 판정을 읽는다.
