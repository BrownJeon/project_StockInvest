# T-078 — T-064와 최신 개편안의 통합 작업절차서

## 목표

- 사용자 요청: T-064와 이번 개편안을 합쳐 Claude가 사용할 하나의 작업절차서를 만든다.
- 수익 경로: 기존 연구·검증 설계를 보존하면서 최신 운용 정책과 구현 의존성을 연결해 중복 개발과 정책 역행을 막는다.
- 단일 실행 정본: `docs/design/2026-10-24-integrated-execution-procedure.md`.
- 범위는 문서 통합·독립 문서 검토·진입점 연결이다. 코드·계좌·DB/설정·주문/취소·알림·커밋/push/배포는 변경하지 않는다.

## 관련 과거 이력 요약

- [[T-064-profit-engine-design]]: 일봉·PIT 유니버스·코드 스크리너·H1~H5·비용/체결 모델·과적합 통제·OOS·전진 모의 검증과 Phase 0~4 설계. 과거 운영 수치·미결 정책은 최신 인터뷰와 대조해야 한다.
- [[T-077-portfolio-restructure-handoff]]: 최신 사용자 정책·공동 예산/슬롯·점수 축소·월 재평가·3개월 승인/재알림·A0~A7·수용 기준. 문서 완료이며 구현 완료가 아니다.
- [[2026-10-23-project-direction-interview]]: 정책 요구 근거. 충돌 시 이 기록의 최신 사용자 결정이 우선한다.
- T-070/T-071/T-072/T-074/T-076 등 기존 구현/검증/운영 상태는 각 task와 최신 코드로 확인한다. 이번 세션은 읽기 전용 문서 대조만 한다.

## 역할별 지시사항

- Leader: 통합 단계·선행 조건·중단/승급 기준·결정 대조표·진입점 작성. 기존 T-064/T-077의 원문 이력은 보존하고 실행 정본 이동 표지만 추가한다.
- 이력 대조: T-064의 연구 세부·미결 D1~D20·Phase를 새 요구/절차와 비교. 읽기만 하고 파일·운영을 바꾸지 않는다.
- Judge: 문서 통합 intake/C1을 정해진 도구로 실행, 기능 수준 요약만 전송. 사용자 대화·계좌/잔고/보유·코드/로그 전송 금지. 도구 결과를 그대로 남긴다.
- 독립 문서 검토: 중요한 T-064 연구/편향/비용 계약이 유실되지 않았는지, 최신 사용자 정책과 작업 순서·게이트에 모순이 없는지 검토. 코드 감사/안전 코드 커밋 승인으로 기록하지 않는다.
- 공유 저장소의 타 작업을 보존하고 각 소유 절 외 파일을 임의 수정하지 않는다.

## 2026-10-28 — 사용자 완료 보고와 이번 작업 종료

- 사용자가 "작성한 통합한 작업절차서로 작업완료했어. 작업 마무리해줘"라고 알렸다. 이 완료 보고를 기록하고, 이번 대화의 인터뷰·개편안·통합 절차서·Claude 인수인계 작업(T-077/T-078)을 종료한다.
- 구현 작업 완료는 사용자의 확인으로 기록한다. 이번 마무리에서 실제 커밋·배포·운영·S00~S09별 검증 증거를 새로 감사하지 않았으며, 실행 원장의 단계/관문을 일괄 완료로 바꾸지 않았다. 과거 상태표와 최신 완료 보고의 시점을 구분한다.
- 추가 설계·구현을 자동 재개하지 않는다. 통합 절차서는 정책/절차 참고로 보존하고, 기존 인수인계 시작 지시문은 당시 이력으로 남긴다. 별도 후속 task와 운영 안전장치는 이번 종료 범위에서 변경하지 않는다.
- 현재 대화의 실행 중 보조 에이전트가 없음을 확인했다. 코드·DB·안전/매매 설정·주문/취소·알림·커밋/push·배포 변경 없이 종료 기록만 정리했다.
