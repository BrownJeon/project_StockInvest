WP-1 이 해외 market 도 이 취소 추론 경로에 넣으므로 노출이 늘어난다 → WP-1 에 해외 쪽 fail-closed(다음 페이지 신호면 throw → `completed_query_failed` 보류)를 포함 권고. ⑥ order-sync 는 `strategy-eval` 에서 `void syncPendingOrders()` 로 **응답과 분리돼** 돈다 — T-019 §동시성의 "cron 순차 blocking 이라 겹치지 않는다" 전제는 약하다(겹침 자체는 여전히 드묾). ⑦ 운영에 **`pending` + `exchange_order_id` NULL 주문 1건**(#2107, 해외 market 매도, 2026-05-14)이 남아 있다 — 동기화·cancel-all 대상 밖, 매도라 일일 합산 영향 없음. 정리는 사용자 결정. ⑧ `docs/db-schema.md` 의 status ENUM 에 `blocked`·`market` 컬럼이 빠져 있다(문서 드리프트).
  - **확인 못 한 것**: KIS 해외 `inquire-ccnl` 의 행 단위(주문당 누적 1행인지 체결 건별인지 — 최대값 집계라 어느 쪽이든 과대평가는 없음), 장 마감 만료 후 그 주문이 `inquire-nccs`·`inquire-ccnl` 에 어떻게 보이는지, 체결조회 페이지 크기, 해외 취소 `ORD_QTY='0'`=전량 취소 여부, 운영 해외 market `filled` 14건(전부 2026-05 매도)이 실제로 전량 체결이었는지. 전부 **실 KIS 응답 1회**가 있어야 확정된다(읽기 전용 TR 이지만 KIS 호출 금지라 미실행).
- 운영 실측(건수만): 거래소 접수된 주문 19건 = 해외 market `filled` 14(모두 5월 매도)·해외 지정가 `filled` 2·`cancelled` 1(#3137)·국내 market `filled` 1·국내 지정가 `cancelled` 1. 현재 미결(조회 대상) 0건, 최근 30일 주문 0건, `executions` 0행, 결과 불명 `rejected(kis_5xx)` 84건. 최근 30일 시그널은 전부 `limit`(국내 728·해외 561) — 해외 market 을 만드는 곳은 `exit-engine.ts:205`·`sell-proposal.ts:259`·`price-breakout.ts:29`(전부 **매도**)와 수동 주문뿐이다 → F01 의 실제 노출은 "청산 매도의 부분체결을 전량 청산으로 기록"이다(보유 수량의 진실은 KIS 잔고라 포지션 자체는 안 틀어지고, 장부와 방치된 잔량 주문이 틀어진다 — §16-1b 와 같은 결론).

**2. WP-1 (F01) 최소 수정안 — 새 상태·DDL 없음**
- 핵심 한 가지: **"브로커가 실제로 받은 주문 유형"** 함수를 둔다 — `brokerOrderType(order, market) = market==='overseas' ? 'limit' : order.type`(근거 주석: `kis-overseas.ts` `ORD_DVSN:'00'` 고정). `order-sync.ts` 의 두 분기(`settleDecision` `:700`, 미체결 판정 `:480`)가 `order.type` 대신 이 값을 본다. 국내는 값이 그대로라 **국내 동작 불변**.
- 그 결과(해외 market, NAS):
  - 0주 체결·잔량 작동 → 체결목록 없음·미체결 있음 → `accepted` 유지(정상 판정).
  - 0주 체결·장 마감 만료 → 두 목록 모두 없음 + 유예 경과 → `cancelled` (**영구 accepted 해소**, 일일 매수 합산에서도 빠져 예산이 풀린다).
  - 1/10주 체결·잔량 작동 → `partially_filled` 로 **추적 유지**(감사 F01 합격 기준).
  - 이후 추가 체결 → `partially_filled` 그대로(재UPDATE 없음), 10/10 → `filled`.
  - 1/10주 체결 후 잔량 만료 → 기존 T-019 경로 그대로: `executions` 1주 기록 → `filled` → `partial_fill_settled` 감사·매도/매수 알림.
- 같은 WP 에 넣을 작은 보강 3가지(전부 기존 규칙의 확장, 새 주문·취소 없음):
  - (a) **해외 체결가 통화**: 지금 그대로 두면 WP-1 이 해외 부분체결 종결을 더 자주 만들어 USD 단가가 `executions.price` 에 들어가고 리포트가 그것을 원화로 읽는다(F02 를 키움). WP-1 에서는 해외 행의 `price` 를 **원화로 맞춘다** — 1안: `orders.price`(송신 기준 원화가, 통화 일치·체결가와는 ±0.5%+α 차이), 2안: USD 체결가 × 그 시점 환율(`fetchUsdKrwRate`, 실패 시 1안). 어느 쪽이든 원본 USD 단가·사용 환율은 `partial_fill_settled` 감사 payload 에 남겨 WP-2 가 재계산할 수 있게 한다. **권고 2안**(Leader 결정 항목).
  - (b) **해외 체결조회 연속조회 fail-closed**: 응답 `tr_cont` 가 다음 페이지를 뜻하면 throw → `completed_query_failed` 보류. 국내는 골든 불변 원칙상 이번에는 건드리지 않고 기록만(같은 위험이 있음).
  - (c) **진행 중 체결 수량 흔적**: `partially_filled` 동안 체결 수량이 바뀌면 `trade_logs` 에 `fill_progress`(주문번호·누적수량·잔량 여부) 1행 — 컬럼이 없으니 "즉시 반영"은 감사 기록까지만 가능하다. 보유·위험은 원래 KIS 잔고 기준이라 즉시 반영된다[가능성 높음 — §16-1b]. 원장 수량을 컬럼으로 즉시 반영하는 것은 WP-2(DDL).
- 새 상태가 **꼭 필요한 부분**: 앱이 보낸 취소를 "요청됨"과 "확정됨"으로 나누는 것(`cancel_requested`)과 화면에서 "부분체결 종료"를 "체결"과 다르게 보이는 것(`partially_cancelled`) — 둘 다 WP-1 범위 밖. 앞의 것도 DDL 없이 "취소 API 성공 시 상태를 바꾸지 않고 `trade_logs.cancel_requested` 만 남긴 뒤 order-sync 가 체결/취소를 판정"으로 대체할 수 있다(별도 WP-1b 후보, 아래 §8 결정 항목). 뒤의 것은 `trade_logs.partial_fill_settled`·`executions` 로 이미 구분 가능하므로 표시용 DDL 은 WP-4 와 묶는 것을 권고.
- WP-1b 후보(Leader 판단, 범위 결정 필요): `cancel-all` 이 `result.ok` 를 검사하게 고치고 실패는 `cancel_failed` 로 남기기(약 10줄). `partially_filled` 를 대상에 넣는 것은 **취소를 더 보내는 변경**이라 task 금지 조항에 걸려 제외.

**3. 미체결 해외 market(영구 accepted) — 처리와 남는 위험**
- 처리: §2 로 NAS 종목은 만료 뒤 `cancelled` 로 닫힌다(유예 120초·5분 주기라 최대 한 회차 늦게).
- 남는 위험 ① **NYS/AMS(커버리지 밖)**: 미체결 목록 근거가 없어 `cancelled` 로 닫을 수 없고, 지금의 "조용한 영구 accepted" 대신 매 회차 `active_coverage_gap` 보류(6시간 warning, `complete=false`)가 된다 — 정직해지지만 시끄러워진다. 부분체결이면 `partial_fill_unconfirmable` 6시간 warning. 근본 해결은 거래소별 미체결 조회 확장(T-017 유량과 충돌) 또는 체결조회를 "체결+미체결 전체"(`CCLD_NCCS_DVSN='00'`)로 바꿔 주문별 `nccs_qty` 를 읽는 것 — 후자는 실응답 확인이 먼저다.
- 남는 위험 ② **자동 잔량 취소가 없으므로**: 해외 market 매도가 −0.5% 지정가에 걸리지 않으면 잔량이 장 마감까지 살아 있고 그동안 다시 시도하지 않는다(현재와 같음). 손절 매도의 경우 "보호가 일부만 걸린 채 장 마감" 가능 — 지금은 이것이 `filled` 로 가려져 있었고 WP-1 뒤에는 `partially_filled`/알림으로 **보이기만** 한다. 실제 대응(잔량 취소·재호가)은 WP-4(사용자 파라미터).
- 남는 위험 ③ 체결조회가 장기간 실패하면 해외 market 도 보류로 쌓인다 — 기존 30분 critical·2시간 구조적 전환 그대로 적용.

**5. 시험 행렬 (WP-1, 전부 mock, 새 파일)**
- 해외 NAS market 매도 10주: 체결 0·미체결 있음 → 변경 없음 / 체결 1·미체결 있음 → `partially_filled`·`executions` 0 / 체결 10·미체결 없음 → `filled`·`executions` 0 / 체결 1·미체결 없음 → `executions` 1행(수량 1, **원화 가격**) 다음 `filled` 순서·감사·매도 알림 키 / 체결 0·미체결 없음·유예 전 → `too_fresh` / 유예 후 → `cancelled`.
- 추가 체결 도착: 1주(`partially_filled`) → 4주(재UPDATE 없음, `fill_progress` 1행) → 10주·목록 소멸(`filled`).
- 조회 실패: 미체결 실패 + 체결 1/10 → `partially_filled`(종결 금지) / 체결조회 실패 → 보류 / 체결조회 다음 페이지 신호 → 보류(새 fail-closed) / 환율 조회 실패 → 1안 폴백.
- 재시작: 첫 회차 `partially_filled` 기록 뒤 추적기 초기화 후 다음 회차 → 같은 판정, `executions` 중복 없음(멱등 가드). `executions` INSERT 뒤·상태 UPDATE 전 실패 → 다음 회차 행 1개 유지.
- NYS market: 체결 0·조회 성공 → `active_coverage_gap` 보류(취소 금지) / 체결 10 → 수량 근거로 `filled`.
- 소수점: 해외 market 1.7주 = 송신 1주 → 1주 체결 시 `filled`(H-4 무회귀).
- **국내 골든 불변**: 국내 market 체결목록 있음 → 즉시 `filled`(수량 무관) / 체결목록 없음 → 변경 없음·보류 아님 — 기존 시험 그대로 통과 + 같은 입력을 해외 심볼로 바꾼 쌍둥이 시험으로 차이를 고정.
- 이미 `filled` 로 잘못 종결된 기존 주문(소급 수정 없음): **탐지 방법 제안** — 대상은 `market='overseas' AND type='market' AND status='filled'`(현재 14건). 읽기 전용 스크립트가 주문일·종목별로 KIS 체결조회(조회 TR, 주문 없음)를 불러 `ft_ord_qty`/`ft_ccld_qty` 를 주문 수량과 대조해 표로만 출력(DB 쓰기 없음). **v2-1. R-01 롤백 서술 정정 + 롤백 절차**

**v2-2. R-03 조건부 상태 쓰기 + single-flight (WP-1 포함)**
- `SET_STATUS_SQL` 을 **이번 회차가 읽은 그 상태일 때만** 쓰는 CAS 로 바꾼다: `UPDATE orders SET status='<next>' WHERE id=? AND status=?`(두 번째 값 = 이 회차 SELECT 의 `order.status`). Leader 문구의 "IN (읽은 상태들)"보다 좁게 잡은 이유: IN(비종결 3개)만으로는 두 회차가 모두 `accepted` 를 읽고 하나가 `partially_filled` 로 쓴 뒤 늦은 쪽이 `cancelled` 로 덮는 경우를 못 막는다. 정확한 이전 상태 비교는 그것까지 막는다.
- `affectedRows === 0` 이면 "다른 회차가 먼저 바꿨다" → `synced` 를 올리지 않고 `partialSettlements`·감사·알림도 남기지 않으며 `ORDER_SYNC_CAS_LOST id=… expected=… next=…` 로그 1줄(경고, 알림 없음). 이미 들어간 `executions` 행은 멱등 가드가 있어 무해하다.
- single-flight: 모듈 변수 `let inFlight: Promise<OrderSyncResult> | null`. 진행 중이면 새 호출은 **새 KIS 조회 없이 진행 중 Promise 를 그대로 돌려준다**(`ORDER_SYNC_SKIPPED_INFLIGHT` 로그 1줄). `finally` 에서 해제. 이유: 운영은 `instances: 1`(ecosystem 확인)이라 프로세스 안 중복이 주된 겹침이고, blue/green 전환 순간의 두 프로세스 겹침은 CAS 가 막는다.
- 시험 영향: 기존 시험 7곳이 `updates[0].params` 를 `[id]` 로 단언한다(`order-sync.test.ts:106,124`, `order-sync-partial-settled.test.ts:174`, `order-sync-fail-closed.test.ts:239,270,289,653`) → `[id, '<이전 상태>']` 로 **강화 갱신**(약화 아님). mock 의 UPDATE 응답 `[{}]` 는 `[{ affectedRows: 1 }]` 로 바꾼다. 운영 코드는 `affectedRows` 가 숫자가 아니면 성공으로 보지 않고 CAS 실패와 같은 경로(보수)로 처리한다.

**v2-4. R-05 해외 market 추론 취소 = 연속 2회차 부재 + `cancel_inferred`**
- 대상: `brokerOrderType` 덕에 취소 추론 경로로 새로 들어오는 **해외 market** 주문만. 국내·해외 지정가의 기존 규칙(유예 120초 뒤 1회 부재로 `cancelled`)은 그대로 둔다(기존 시험 불변, 범위 확장은 별도 판단).
- 규칙: 조회 두 축 성공 + 커버리지 안 + 유예 경과 + 두 목록 모두 없음을 **처음** 보면 모듈 메모리 맵 `absentSince: Map<orderId, {firstAt, count}>` 에 1회 기록하고 `hold(…'cancel_confirming')`(정체 시계에 올리지 않음, `complete` 를 깎지 않음 — `too_fresh` 와 같은 "의도된 대기"). 다음 회차(≥5분 뒤)에도 같은 조건이면 `cancelled`. 그 사이 한 번이라도 어느 목록에든 나타나면 맵에서 지운다. 프로세스가 재시작되면 맵이 비어 **추가 1회차를 더 기다릴 뿐**이라 안전 방향.

- `UnreconciledReason` 에 `'cancel_confirming'` 1개 추가(코드 타입이지 DB 값 아님, DDL 없음). `reportUnreconciled` 의 "too_fresh 만 있으면 침묵" 조건에 함께 넣는다.

**v2-5. R-06 부분체결 종결 나이 가드**
- `settleDecision` 의 "목록 신뢰 가능 + 활성 목록에 없음 + 체결수량 < 송신수량 → 종결(`filled`+`partial`)" 분기는 `ageMs >= graceMs` 일 때만 성립. 아니면 `partially_filled` 유지(다음 회차 교정). 전량 체결(수량 ≥ 송신수량) 판정과 활성 목록에 있는 경우의 `partially_filled` 는 나이와 무관(양성 증거). `settleDecision` 에 `ageMs`·`graceMs` 인자 추가.
- 기존 시험 영향: 부분체결 종결 시험들은 `AGED()`/오래된 `created_at` 을 쓰는지 구현 때 확인(기본값이 새 주문이면 생성 시각만 과거로 맞추는 것이지 단언은 그대로).
