# T-060 — 매도 제안 요약 발송 관측 공백 보완

## 배경 (사실, 2026-10-21 조사 — 정본 조사 기록은 [[T-055-sell-proposal-mode]] Leader 기록 10:32)

- 사용자가 T-055 매도 제안 요약이 텔레그램으로 오지 않았다고 신고했다(국내 10-21 09:04, 해외 10-20 22:31 KST 선점분 포함). 사용자는 같은 봇 대화방에서 **직접 보낸 진단 메시지(10-21 10:27)는 정상 수신**했다 → 봇·채팅 설정과 서버→텔레그램 연결은 정상.
- 엔진은 요약 단계에 도달해 `system_config` 일일 표식을 선점했다(국내 `"2026-10-21"` 09:04:12, 해외 `"2026-10-20"` 22:31:29). 그 뒤 `dispatch('info')` → 텔레그램 경로. 이 시간대 `pm2-err.log` 에 `요약 전송 실패`·`[notify] telegram 전송 실패`·`[telegram] sendMessage failed` 는 **0건**이다.
- **관측 공백**: `finishReport` 는 전달 결과(`delivered`/`failed`/`unconfigured`)를 로그로 남기지 않는다. 전달 0·실패 0 인 경우(`unconfigured` — 채널 없음/자격 증명 미설정/`notify_channel=none`)는 `'no_channel'` 로 조용히 끝나고 **표식은 선점된 채로 남아 그날 요약은 영영 안 나간다**(`sell-proposal-preview.ts` 의 마지막 반환부). 엔진은 `void preview.finish()` 로 결과를 버린다(`engine.ts:956`). 그래서 로그로는 '텔레그램이 받았다'와 '조용히 건너뛰었다'를 구분할 수 없다.
- 확정하지 못한 것: 실제 원인. (가설) 자격 증명 읽기가 DB 일시 오류로 빈 값→`NOTIFY_SKIPPED`(60초 캐시) / 전송은 됐으나 다른 이유로 안 보임 / 그 밖. 이 task 는 원인을 *추측으로 고치지 않고*, 다음 요약 때 원인이 로그로 드러나게 하고 `no_channel` 을 재시도 대상으로 만든다.

## 요구

1. **결과 로그**: `finishReport` 가 전송 시도를 마칠 때마다 1줄을 남긴다 — `[sell-proposal-preview:<market>] 요약 결과 <outcome> (거래일 <date>, channel=<채널>, delivered=[…], failed=[…], unconfigured=[…])`. 정상 `sent` 는 `console.log`, 그 밖은 `console.warn`. **토큰·채팅 ID·메시지 본문·종목 수량/평단은 로그에 넣지 않는다.**
2. **`no_channel` 처리**: 전달 0·실패 0(채널 없음/미설정)이면 지금처럼 조용히 끝내지 않는다. `console.warn` 로 사유를 남기고, **표식을 되돌려** 다음 틱에 재시도되게 한다 — 단 기존 재시도 상한(`MAX_SEND_RETRIES`)을 공유해 무한 반복하지 않는다. 상한 도달 시 `send_failed_kept` 와 같은 방식으로 그날을 포기하고 그 사실을 경고로 남긴다(`notify_channel=none` 같은 의도된 설정에서 매 틱 소음이 되지 않게).
3. 기존 결과 값(`sent` 등)·표식 의미·선점/되돌리기 조건부 UPDATE·`knownDone` 의미는 바꾸지 않는다. 새 outcome 이름이 필요하면 `SellProposalReportOutcome` 에 추가하되 기존 소비처(엔진 로그·테스트)가 깨지지 않게 한다.
4. **테스트**: ① delivered≥1 → `sent`, 표식 유지, 로그 1줄 ② failed 만 → 기존 `send_failed_released` 동작 불변 ③ 전달 0·실패 0 (unconfigured) → 경고 + 표식 되돌림 + 다음 호출에서 재시도 ④ 재시도 상한 도달 시 포기·경고 ⑤ `dispatch` 가 throw 해도 기존 동작 불변 ⑥ 로그 문자열에 토큰/본문이 없음.
