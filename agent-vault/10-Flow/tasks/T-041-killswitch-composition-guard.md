## 해결 방향 — 사용자 승인: B (+C 는 후속)

**B. 임계 초과로 발동하기 직전에, 사라진 보유 가치가 *설명되는지*, 그리고 *거래 정황이 없는 순수 소실인지* 확인한다.**

- 기준선에 있던 비현금 보유가 현재 스냅샷에 **아예 없으면** 소실(V). 0원으로 *기록된* 보유(상폐·거래정지)는 관측된 실제 손실이라 소실이 아니다.
- 설명되는 몫 = `min(V, max(0, 현금(KRW+USD) 증가 + 신규 보유 평가금액))`. **U = V - 설명되는 몫**. U 가 기준 총액의 10% 이상이면 보정 대상(`suspected`). 보정 손실 = `(현재 - (기준 - U)) / (기준 - U)`.
- **거래 정황** = max(0, 현금 증가) + 신규 보유 + **기존 종목 추가 매수**(양쪽에 있는 종목의 *수량* 증가분 × 현재 단가; 수량이 없는 구형 행은 가치 증가분으로 보수적으로 계산). 거래 정황이 소실액의 **3%** 이하일 때만 "순수 소실"(`pureDisappearance`).
- `suppressible = suspected && pureDisappearance`. **보류가 허용되는 유일한 조건**이다.
  - suppressible 이고 보정 손실이 **엄격히 임계 이내** → 발동 **보류** + critical 알림(사건별 키, 6시간 스로틀, 미설명 금액·"거래 정황은 없다"·수동 발동 안내·상장폐지 가능성 안내). 조용한 보류 금지.
  - 거래 정황이 있거나(suspected 이나 순수 소실 아님), 보정 후에도 임계 초과 → **그대로 발동**(사유에 이유를 덧붙임).
  - **검증 불가는 발동 쪽**: 구성(positions)을 읽을 수 없는 행, 보정 기준 ≤ 0, 이 단계의 예외(자체 try/catch).
- 저장 가드(`checkHoldingVanished`)는 **동작을 바꾸지 않는다**. 같은 순수 모듈의 `evaluateVanish` 로 옮겼을 뿐이다(비유한 총액 → 거부 포함, 변경 전 본문과 동치).

### 폐기된 설계 두 번 (독립 감사 C-1, C-2 — 같은 날)

1. **1차(C-1)**: "총액 감소 ≥ 소실액×70%"를 증발로 판정, 기준에서만 소실분을 뺌. 총액은 **남은 보유가 실제로 빠져도** 줄고 매도 대금(현금)·신규 보유는 현재에 남아, 정상 매도 뒤 남은 보유의 진짜 -12% 손실이 "관측 불능"으로 보류됐다. → **구성 항목의 흐름**(소실 가치가 현금/신규 보유로 설명되는가)으로 교체.
2. **2차(C-2)**: 미설명 몫 U 가 세 가지를 구분하지 못한다 — ① 관측 불능 ② 소실 종목을 낮은 가격에 청산한 *실현 손실* ③ 그 대금으로 산 보유의 이후 하락. 손절(α)·리밸런스(β)·갈아타기(γ)에서 -12% 실손실이 보류됐고, 사용자의 실제 포트폴리오 형태(SNPS/SMH → MU, MU -16%)도 보류됐다. 스냅샷만으로는 구별이 **원리상 불가능**하므로, 거래 정황이 보이면 관측 불능으로 보지 않고 **발동**하도록 보류를 순수 소실로 한정했다. 재현 입력을 회귀 테스트로 고정.

## 알려진 한계 / 하지 않은 것

- 킬스위치 해제는 하지 않았다 (사용자 결정). 현재도 `safety_kill_switch=true`.
- C(미결제 대금을 총자산에 반영)는 미착수. KIS 해외 잔고의 미결제/결제예정 필드 확인이 선행 — 라이브 호출 금지(토큰 충돌), 문서 근거만으로 판단.
- 저장 가드의 3시간 릴리스 밸브 자체는 건드리지 않았다. 밸브가 저장한 낮은 행의 다른 소비처(변동성 가드, `order_max_pct`)는 낮은 총액에 보수적으로 반응한다.
- **δ — 손실 실현 후 대금 전액 출금**은 관측 불능과 구별할 수 없어 **보류된다**(critical 알림은 나간다). 원리상 해결 불가이며 테스트로 고정했다. 같은 이유로 **상장폐지·정리매매로 종목 행 자체가 제거된 실손실**도 보류된다(M-2; 0원으로 *기록된* 경우는 발동).
- 정량(모델 추정 — **실제 빈도가 아니다**): 우리가 가정한 거래 혼합(매도·출금·추가/신규 매수·미결제·조회 누락·상폐, 하락 사건 45% 스트레스, 수량 반영) 10만 건, 시드 3개. 보류 약 6,800건 중 시장 손실 ≥10% 위반 약 175~215건(≈3%), 그중 **86%가 δ형**. 출금 없는 위반은 ≈6~14건(보류의 0.1~0.2%). 2라운드 감사 시점의 같은 모델 기준 7,373건에서 약 97% 감소.
- **정책 값 `PURE_DISAPPEARANCE_MAX_EVIDENCE_RATIO = 3%`**: 10%→3% 로 낮추면 순수 미관측 보류는 4,154→4,144(-0.2%)로 그대로이고 출금 없는 위반은 14→6건, 2% 는 추가 이득 없음. 사용자가 바꿀 수 있다(올리면 보류·우회 증가, 내리면 발동 증가).
- 수량(`qty`)이 없는 구형 `portfolio_snapshots` 행은 가치 증가를 추가 매수로 계산한다. **"보수적"이라고 쓴 앞선 서술은 부정확했다**(3라운드 감사 정정): 가격 상승은 거래 정황으로 잡혀 발동 쪽으로 기울지만, 같은 종목 안에서 매수와 하락이 상쇄되면 가치 증가가 작아 숨는다(수량 제거 퍼저에서 위반 195건 중 비-δ 64건). 운영 `portfolio-snapshot` 크론은 항상 `qty`(= free + locked)를 채우므로 영향은 작다.
- 무관한 입금은 소실을 설명하는 것으로 계산돼 *발동 쪽*으로 기운다(보수적). 일부 매도(수량 감소) 후 대금 미관측은 보정 대상이 아니라 남은 보유의 가치 하락으로 보여 *발동*한다(보수적 오발동 가능).
- 보류 상태를 사람이 확인(ack)할 때까지 재알림하는 장치는 없다. 알림 키는 사건(소실 종목 조합)별이라 이론 상한이 일 24건(크론 시간당 1회 × 최대 1건)이다.
- 변이 생존으로 남긴 것(동치): 감사가 지적한 `!(share<MIN)`↔`share>=MIN`(share 가 NaN 일 때만 차이, 입력은 유한값만 도달), `evaluateVanish` 의 `prev≤0` 가드(호출처에도 같은 가드), 알림 키의 `.sort()`(종목 순서 정규화).
- **3라운드 감사가 수용 가능한 잔여 위험으로 분류한 것(차단 사유 아님)**: ① 일반 출금이 매도 대금을 소진한 경우(정보상 δ 와 동일) ② 매수한 종목 자체가 상폐 정리·조회 누락으로 행에서 사라진 경우 ③ 3% 허용치 안에 숨은 먼지 ④ 역분할 + 같은 가치 추가 매수로 수량 순증이 0 인 경우 ⑤ 매수한 종목이 -97% 이상 빠져 3%×V 아래로 숨는 경우. 퍼저에서 **거래 없이 미관측 사건만 있는 보류 약 3.6천 건의 위반은 0건**(8시드)이고, 위반은 전부 "대금이 보이지 않게 된 거래"에서만 났다.
- **고칠 수 있으나 이번에 고치지 않은 것(3라운드 Medium, 비차단 권고)** — 코드를 고치면 감사를 다시 받아야 해서 사용자 판단으로 남긴다:
  - **M-1**: 0원으로 *기록된* 종목(운영자가 `snapshot_zero_price_symbols` 로 허용한 심볼)에 대한 신규·추가 매수는 `curHoldings` 가 값>0 만 담아 거래 정황으로 안 잡혀 보류될 수 있다. 입력 예: [A 5M, B 5M] 에서 A 를 팔아 신규 C 를 샀는데 C 가 `qty 50, price 0, value 0` 이면 총 -50% 인데 보류. 0원 행은 운영자가 이미 개입한 상황이라 사람이 인지한다. 권고: 현재 행이 `qty>0` 인데 값이 0 이면 그 자체를 거래 정황으로 본다.
  - **M-2**: 거래 정황의 현금 항목이 *순증감*이라 통화 간 증가·감소가 상쇄된다. 입력 예: 미국주 A 를 팔아 USD 현금 2.8M 이 보이는데 같은 날 KRW 2.8M 을 출금하면 순증감 0 → 실현 손실 -12% 보류. 권고: 통화 행별 양(+) 증가의 합을 증거로 쓴다. 희귀하다.
  - **Low**: 보류 알림 본문이 "거래 정황은 없다(200,000원)" 처럼 금액이 0이 아닌데 "없다"고 쓴다 → "미미하다(허용치 이내 N원)" 정도로. 허용치를 `min(3%×V, 기준 총액의 1%)` 이중 상한으로 조이는 안은 미검증 제안이다.
- 확인하지 못한 것(감사 포함): KIS 잔고가 당일 체결 매수를 보유 수량에 즉시 반영하는지(라이브 호출 금지 — 반영이 늦으면 10-03 형태와 같이 보류되고 알림은 간다), 운영 DB `positions` 의 실제 분포(수량 필드 누락·한 심볼 다중 행), 퍼저가 가정한 거래 혼합의 현실성, 분할·병합·배당 재투자·환전·증거금 조합.
- 현금 부족(8만 원 < 시그널 1건 10만 원)은 별건.
