# T-056 — 해외 USD 예수금 스냅샷 수집

## 배경

[[T-055-sell-proposal-mode]] §1.3 의 P: **해외 매도 대금(USD)이 스냅샷 총자산에 잡히지 않는다.** 10-03 SNPS 매도 뒤 총자산이 23.5M → 6.53M 으로 보였고 10-05 재매수 때 복귀했다. 같은 이유로 10-03 04:16 킬스위치 오발동이 있었고 [[T-041-killswitch-composition-guard]] 가 "순수 소실 → 발동 보류 + critical" 가드를 넣었다. 매도 제안(T-055) 2단계가 켜져 MU(포트폴리오의 약 64%)를 팔면 같은 현상이 재현돼 화면 총자산·1회/일일 한도(평가액 비례)·킬스위치 판단이 -64% 를 본다.

## 사용자 결정

2026-10-19 밤 T-055 §6 Q7 → **(a) 2단계 전에 먼저** (권고안 수락). 이 task 는 그 별건이다.

## 요구와 제약

1. 해외 USD 예수금(주문가능 현금)을 스냅샷 `positions` 에 `currency:'USD'` 현금 행으로 함께 수집한다.
2. **조회 실패를 삼키지 않는다.** 예수금 조회가 일시 실패해 행이 빠지면 그 자체가 총자산 급감으로 읽혀 킬스위치가 오발동할 수 있다([[T-014]] 근본 원인 — 잔고 부분 실패를 `.catch(()=>[])` 로 삼킨 것 — 과 같은 부류). 실패 시 스냅샷 저장 보류 + critical 경보로 닫는다. 어떤 경로로도 "예수금 행 없음 = 예수금 0" 으로 해석되면 안 된다.
3. [[T-041-killswitch-composition-guard]] 의 구성 변화 가드와의 상호작용을 **먼저 읽기 전용으로 분석**한다: 현금 행 신설이 첫 스냅샷에서 "구성 변화"로 읽혀 가드가 오작동하거나, 반대로 가드를 무력화하지 않는가. 환율(USD/KRW) 변동이 총자산에 섞이는 방식(이중 계상·시차)도 확인한다.
4. 총자산을 읽는 모든 소비자(킬스위치, 1회/일일 한도의 평가액 비례, 대시보드 총자산·손익, 리포트)를 전수 조사해 현금 행이 새로 더해질 때 **값이 어떻게 달라지는지** 표로 보인다. 숫자가 갑자기 커 보이는 것(과거 스냅샷과의 불연속)도 영향으로 적는다.
5. 해외 현금이 0 이거나 계좌에 해외 현금이 없는 정상 상태와, 조회 불가 상태를 구별한다(0 은 행을 만들거나 0 으로 기록, 불가는 보류).
