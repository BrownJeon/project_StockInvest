# T-080 — 킬스위치 24h 손실 판정의 USD 행 오집계 방지

> **연결:** 통합 절차 S05(안전 경계) 공통 — H/N 어느 쪽에도 선행 조건이 없다. 정책 버전: U01~U16 확정(2026-10-23), C01·C05 제안 v1. 정본 원장 [execution-ledger](../../../docs/design/2026-10-24-execution-ledger.md), 근거 [S00 보고서 §0-2·§2.4](../../../docs/design/2026-10-24-s00-baseline-report.md).
> **수익·위험 경로(제1원칙):** 킬스위치는 매수·매도를 구분하지 않고 막는다(`dry-run.ts`). 오집계로 발동하면 청산 주문도 막혀 손실 보유를 정리할 수 없다. 이번 10-23 발동 −12.1% 중 약 76% 가 환전한 달러의 집계 누락이었다(기준선의 가려진 USD 까지 양쪽에 대칭 반영하면 실제 약 −2.8%, 임계 −10% 미달). 같은 부류의 오발동이 10-03(T-041, 미정산 대금)에 이어 2회째다.

## 사실 (S00 실측, 2026-10-24~25)
- [확실] `system_config.safety_kill_switch=true`, 갱신 2026-10-23 22:42:37 KST(자동 발동). DB 값이 env 보다 우선(`kill-switch.ts`).
- [확실] 기준선 스냅샷(#5428)과 발동 시점(#5443) 모두 USD 행이 있고 값(`qty`)이 0 → "전환 규칙 E"(`kill-switch.ts` `applyUsdSymmetricRemoval`: **한쪽에만** USD 행이 있을 때 대칭 제거, `baseHas === curHas` 면 그대로 통과)가 적용되지 않음. 총자산 차이 −12.06% 가 로그 금액과 1원 단위로 일치.
- [확실: KIS 응답, 2026-10-25 일요일 10:3x] KIS API 는 USD 예수금·출금가능·주문가능을 모두 스냅샷 값과 같게 돌려주고 증거금·미체결은 0 이다. 즉 USD 가 "없어지는" 것이 아니라 **평일 저녁 스냅샷에서만 0 으로 읽히는 문제**다. 평일 16:40~06:30 사이 읽기 전용 조회 1회가 있으면 원인(응답값 자체가 0 인지, 조회/파싱 문제인지)을 분리할 수 있다 — 설계 후보 (b)·(c) 선택의 근거.
- [확실: 관측] 10-22 06:29 스냅샷에 USD 가 보이다가 16:38 에 0 이 됐고 10-23 07:13 에 환전분과 합쳐 다시 보인다. [가능성 높음: 해석] 따라서 기준선(10-22 22:59) 시점에도 야간에 가려진 USD(총자산의 약 2%)가 있었다. 현재 쪽에만 USD 를 더한 "−0.7%" 는 비대칭 보정이라 쓰지 않는다 — 대칭 반영 시 약 −2.8%.
- [확실] USD 행은 평일 16:37~48 경에 0 으로 가려졌다가 05:19~07:18 경(요일에 따라 06:29 이전) 다시 보이고, 토요일 10:01 이후 일요일 00:16 까지 계속 보인다. 원인은 미확정(T-074 "달러 자동투자 상품" 가설 대기).
- [가능성 높음] **두 가지 메커니즘이 있다.** (i) 이번 사건 — 기준선과 현재 모두 USD 가 가려진 상태에서 KRW→USD 환전이 일어나 환전분이 사라져 보임. (ii) 시간대 비대칭 — 현재는 가려진 시간대인데 24시간 전(±60분)은 보이던 시간대이면 USD 비중(현재 총자산의 약 11.5%)만큼 거짓 손실이 생김. 해제 후 (ii) 의 대표 구간은 **주말·휴일 다음 첫 평일 16:30 ~ 다음날 06:30 경(약 14시간)**이고 시세가 +1.5% 이상 오르면 발동하지 않을 수 있다. 일요일 가시성은 미관측.

## 범위
- **하는 것:** (1) 격리 시험에서 발동 사례를 합성 재현(실제 금액·종목 없이 비율로 만든 fixture) (2) USD 행 부재·한쪽 0·양쪽 0·양쪽 양수 4조합의 처리 규칙 설계 (3) 규칙 보강과 회귀 시험 (4) 해제 판단에 쓸 근거 요약(해제 자체는 사용자).
- **설계 후보(C1 전 검토, 확정 아님):** (a) `qty=0` 인 USD 행을 '불명'으로 보고 **직전 양수 값을 이월**한다 — 유효기간은 가려진 구간(약 16:40~06:30, 평일 야간)을 덮을 만큼(약 18시간 이상) 필요하고, 실제 출금·환전이 일어난 뒤에는 낡은 값을 쓰는 위험이 있다. 이것이 이번 사건(양쪽 USD 행이 이미 0)을 잡는 후보다. 단순히 "USD 행을 양쪽에서 제외"하는 것은 이번 사건에 효과가 없고(총액이 그대로), 규칙 E 의 "한쪽에만 있을 때" 조건을 넓히는 것만으로도 못 잡는다. (b) 근본 해결: 스냅샷의 USD 조회 안정화 — 원인 확정(A03)과 연결되며 T-081 소유 가능. (c) 판정에 KIS 주문가능 조회값 사용 — KIS 호출이 필요하므로 별도 권한. (d) 보조 후보 — T-041 구성 판정에 '현금 감소 + 보유 수량 불변 + USD 증가 미관측 = 환전/이동 의심 → 발동 보류(알림)' 추가. 이번 사건은 국내 매도로 KRW 가 순증하고 보유 수량도 바뀌었으므로 이 조건에 해당하지 않는다 — 다른 유형의 보조 규칙으로만 평가한다.
- **하지 않는 것:** 킬스위치 DB 값 변경(해제), 임계(−10%) 변경, 주문 송신 경로 변경, 운영 설정·알림, 커밋·push·배포.

## 소유 파일 / 비대상
- 소유: `src/lib/safety/kill-switch.ts`, `src/lib/safety/portfolio-total.ts` 및 해당 시험. **모두 SAFETY_PATHS 대상 → Reviewer 판정(scope 포함) 없이는 커밋 불가.**
- 비대상: `order-sync.ts`·`order-limits.ts`(T-081 소유), `dry-run.ts` 의 차단 의미(매수·매도 모두 차단은 기존 안전 규칙으로 유지).

## 설계 v1 (Leader, 2026-10-25 — Judge C1 전, 사용자 D-1 "권고대로": 킬스위치는 유지한 채 이 task 먼저)
**Phase 1 (지금)** — 발동 후보일 때만 작동하는 보류 규칙. 정상 경로·임계·DB 우선·매수/매도 동시 차단 의미는 바꾸지 않는다.
1. 기존대로 기준선(24h±60분)·현재 스냅샷·규칙 E 를 거친 손실률이 임계 이하(발동 후보)일 때만 새 단계를 탄다. 후보가 아니면 아무 것도 하지 않는다.
2. 기준선·현재 각각의 USD 행 수량이 0(또는 행 부재)이고, 그 스냅샷 시각 기준 **직전 20시간 이내**에 USD 수량이 양수인 스냅샷이 있으면 "가려짐"으로 보고 그 양수 값(수량)을 이월한다(환율은 그 스냅샷 자신의 USD 행 가격, 없으면 직전 양수 행의 가격). 최근 N=48개 스냅샷을 읽어 JS 에서 계산한다.
3. 이월 후 **보정 손실률**을 계산한다. 보정 손실률이 **임계의 절반보다 얕으면**(예: 임계 −10% → 보정 > −5%) 발동하지 않고 **critical 알림으로 보류**한다 — 원인(어느 쪽이 가려졌는지), 원시 손실률과 보정 손실률, 마지막으로 보인 시각, "실제 손실이면 설정 > 안전장치에서 수동으로 켜세요" 를 담는다. 알림은 사건 키로 스로틀(12h).
4. 보정 손실률이 −5% ~ −10% (모호 구간)이거나 임계를 넘으면 **기존대로 발동**한다(사유에 보정 정보 병기). 이월할 양수 값이 없으면 보정 불가 → 기존대로 발동.
5. 어떤 단계든 예외·파싱 실패·읽기 실패 → **발동**(검증 불가는 발동 쪽 — T-041 원칙 유지). 이 단계가 보류하는 유일한 경우는 3번이다.
6. 순수 함수(`assessHiddenUsdCarry`)로 분리해 시험한다: 입력 = (기준선 행, 현재 행, 직전 스냅샷 목록, 임계) → 출력 = {carried 여부, 보정 손실률, 보류 가능}. DB 호출 없음.
7. 근거: 10-23 사건 재현(기준선·현재 모두 가려짐 → 원시 −12.06%, 보정 −2.8% → 보류), 시간대 비대칭(현재만 가려짐, 시세 보합 → 원시 약 −11.5%, 보정 약 0% → 보류), 진짜 폭락(미국 보유 −12% 단독 → 보정 후에도 −10% 근처 → 발동).
**Phase 2 (월요일 평일 저녁 읽기 전용 조회 1회 뒤)** — KIS 가 가려진 시간대에 USD 를 어떻게 돌려주는지(응답값 자체가 0 인지, 다른 필드/TR 에 값이 있는지) 확인한 뒤 스냅샷 USD 조회를 근본적으로 고칠지(T-081 A03) 결정한다. 그때까지 Phase 1 이 안전망이다.
**알려진 한계(수용):** 가려진 구간에 실제로 USD 가 출금·소진되면 이월값이 낡아 보정 손실률이 얕게 나올 수 있다 — 그래서 절반 마진(−5%)과 모호 구간 발동으로 상쇄하고, 보류는 항상 critical 알림으로 사람에게 알린다.

## 수용 기준
1. 합성 재현: 현 로직은 발동하고 수정 후에는 발동하지 않는다(환전분 오집계 사례).
2. 실제 큰 하락(예: 미국 시세 단독 −10% 초과)은 수정 후에도 발동한다.
   - 모호 구간(보정 −5% ~ −10%)은 발동한다. 보류는 보정 손실률이 임계의 절반보다 얕을 때만.
   - 보류 시 critical 알림이 나가고 알림 실패가 판정을 바꾸지 않는다. 이월할 양수 값이 없으면 기존대로 발동한다.
3. USD 행 4조합(부재/한쪽 0/양쪽 0/양쪽 양수)과 기준선 ±60분 경계를 시험한다.
4. 수정이 매수·매도 동시 차단 의미와 DB>env 우선순위를 바꾸지 않는다.
5. 독립 Reviewer PASS(scope: 위 소유 파일) → Judge C2 → QA(격리 사본, `git archive HEAD` + 변경분) 순환. 과거 T-041·T-056 판정을 차용하지 않는다.
6. 배포는 별도 사용자 승인(push 가 배포 발화).
