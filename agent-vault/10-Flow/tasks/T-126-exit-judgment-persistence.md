### D1. 무엇을 남기나 — 1행 = (청산 평가 틱, 보유 종목)
`runExitEngine` 의 종목 루프(`engine.ts` 818~969행)가 종목마다 내리는 **결론 하나**를 남긴다. 루프의 `continue` 지점이 많아서(약 12곳) 각 지점의 기존 `rec.pass/skip/error` 호출 바로 뒤에 같은 결론을 수집기에 한 줄 더 넣는 **가산 방식**으로 한다(기존 줄 삭제·이동·들여쓰기 변경 금지 — diff 가 읽혀야 한다).

| 결론 `decision` | 해당 게이트(`decision_code` = 게이트 ID 그대로) |
|---|---|
| `no_fire` | `exit_no_fire` (정상 0) |
| `skip_policy` | `exit_engine_disabled`(마스터 OFF — 소급 이력의 핵심)·`exit_hard_stop_disabled`·stage 11 정책 스킵(`quantity_below_min`·`duplicate_active_signal`·`symbol_blacklisted` … `createSignalGuarded` 가 돌려주는 `recordedGate`) |
| `skip_cooldown` | `cooldown_exit` |
| `fired` | `signal_created` (+ `signal_id`) |
| `error` | `exit_avg_price_missing`·`exit_ticker_error`·`exit_price_invalid`·`exit_state_upsert_failed`·`exit_state_missing`·`exit_unit_mismatch`·`exit_create_failed` |

**기록하지 않는 것**: `balances_unknown` 틱(보유 목록을 모르면 종목 행이 없다 — `eval_funnel`·`job_run_log` 가 증거)·보유 0종목 틱·`ENGINE` 이 아닌 진입(매수) 판단. 한계로 문서에 적는다.

### D2. 표 `exit_judgment` — 가산 전용, 외래키 없음, 앱 부팅 때 만들지 않음
열(타입은 `position_state`·`signals`·T-112 규약과 맞춘다; 최종 타입은 일회용 MariaDB 시험으로 확정):
- `judgment_id BIGINT UNSIGNED AUTO_INCREMENT PK`
- `run_id VARCHAR(40) NOT NULL` — `buildRunId`(`market-YYYYMMDDHHMM`, **분 단위**). ⚠ 같은 분에 틱이 두 번 돌면 값이 겹친다 → **`(run_id, symbol)` UNIQUE 를 걸지 않는다**(걸면 두 번째 틱 기록이 조용히 사라진다). 중복 방지가 필요하면 `evaluated_at`(초 단위)와 함께 본다.
- `evaluated_at DATETIME NOT NULL`(KST 벽시계, 앱이 `toKstDatetime` 문자열로 바인딩) · `session_date_kst DATE NOT NULL` · `session_date_et DATE NULL`(해외만)
- `market ENUM('domestic','overseas') NOT NULL` · `symbol VARCHAR(32) NOT NULL`(`signals.symbol`·`position_state.symbol` 과 같은 형식)
- `position_qty DECIMAL(36,18) NULL` · `entry_price`·`peak_price`·`price DECIMAL(36,8) NULL` · `currency CHAR(3) NULL`(KRW/USD, 시장에서 도출) · `pnl_pct DECIMAL(10,4) NULL`
- `trigger_kind ENUM('eod_loss_cut','hard_stop','target_profit','trailing_stop','none') NOT NULL DEFAULT 'none'` · `threshold_pct DECIMAL(10,4) NULL`(적용 임계 — 값을 얻을 수 없으면 NULL, 추측해 채우지 않는다)
- `decision ENUM('fired','skip_policy','skip_cooldown','error','no_fire') NOT NULL` · `decision_code VARCHAR(48) NOT NULL`
- `exit_engine_enabled TINYINT(1) NULL` · `exit_hard_stop_enabled TINYINT(1) NULL` · `dry_run TINYINT(1) NULL`(그 틱에 판독한 값; 못 읽으면 NULL — 0/1 로 단정하지 않는다)
- `signal_id BIGINT NULL`(`signals.id` 는 부호 있는 BIGINT) — 주문은 `signals.consumed_order_id` 로 이어지므로 `order_id` 열을 두지 않는다(쓰는 시점에 주문이 아직 없다)
- `engine_release VARCHAR(48) NULL`(T-112 `engineReleaseFromCwd` 재사용)
- 인덱스: `(evaluated_at, market)`·`(symbol, evaluated_at)`. CHECK: `decision`↔`decision_code` 길이·`pnl_pct` 범위만 최소로(과한 CHECK 는 기록 실패를 부른다 — 기록이 던지지 않아도 행이 사라진다).
- 하루 상한: 보유 5종목 × 2시장 × 약 80틱 ≈ 수백 행. 보존 기간 삭제는 이번 범위 밖(삭제는 별도 승인 사안).

### D3. 쓰기 방식 — 청산 평가를 막지 않는다 (가장 중요)
1. 수집은 **메모리 push 만**(동기·throw 불가·await 없음). 수집기 메서드 전부가 내부 try/catch 로 모든 예외를 삼킨다.
2. 틱 끝에서 **분리 실행**(`void …catch`)으로 한 번 INSERT(다중 행) — `recordJudgmentDetached` 와 같은 모양. 타임아웃(4초)·행 수 상한(예 100)·실패 시 `console.warn` 한 줄(원인 분류어만, 금액·종목 없음). 던지지 않고 기다리지 않는다.
3. 스위치 `system_config.exit_judgment_record_enabled` — **키 없음 = 꺼짐**, 정확히 JSON `true` 만 켜짐, DB 오류·테이블 없음(errno 1146)·2초 초과 = 꺼짐. `record-switch.ts` 의 `RECORD_SWITCH_KEYS` 에 키를 추가해 같은 판정·30초 캐시를 쓴다. 스위치 읽기는 **분리 실행 안에서**만 한다(평가 경로에서 추가 DB 읽기 0). 이 스위치는 기록 스위치이지 안전 스위치가 아니다 — 거래 동작에 영향이 없다.
4. 청산 엔진의 반환값·`created`·`blocked`·`rec.*` 호출·쿨다운·`position_state` 쓰기·`sendAlertThrottled` 는 **바이트 단위로 같아야 한다.** 수집기 호출 줄만 늘어난다. 시험으로 고정한다: (a) 수집기가 매번 throw 해도 결과 동일 (b) 분리 INSERT 가 실패·지연해도 틱 소요 시간·결과 동일 (c) 스위치 꺼짐일 때 INSERT 0회.

### D4. DDL 절차 (사용자 승인 범위 — 위 진행 기록 10-31 06:50 해석 참고)
`scripts/migrations/T-126-exit-judgment.sql` — T-112 SQL 과 같은 머리 주석(앱 부팅 때 실행 안 됨·적용 명령·적용 전후 확인·되돌리기 DROP 주석·`SET SESSION lock_wait_timeout = 5`)·`CREATE TABLE IF NOT EXISTS`. 일회용 MariaDB 10.11 시험(strict / NO_BACKSLASH_ESCAPES 두 sql_mode)으로 DDL 과 삽입·CHECK 위반·경계값을 검증하고 결과를 task 에 남긴다. 적용은 **QA PASS 뒤, 웹 배포보다 먼저, 장외 창**에서 Leader 가 한다(적용 전 `SHOW TABLES LIKE 'exit_judgment'` 빈 결과·`@@GLOBAL.sql_mode` 기록, 적용 후 `SHOW CREATE TABLE` 기록). 적용만으로는 아무것도 쓰이지 않는다(스위치 꺼짐). 스위치 켜기는 별도 승인.
