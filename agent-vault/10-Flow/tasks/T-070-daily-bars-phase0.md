## 범위
1. **DDL**: T-064 §5.2 의 `daily_bars` (가산 전용 `CREATE TABLE IF NOT EXISTS`, 되돌리기는 이 테이블 삭제 한 줄). 마이그레이션 파일 위치·적용 방식은 T-059 선례(스크립트 `--with-migrate` 거부 정책, 수동 적용)를 따른다. **개발자는 운영 DB 에 적용하지 않는다**(Leader 가 한다).
2. **수집기 라이브러리** `src/lib/profit-engine/` (신규 네임스페이스, **주문·safety·exchanges 어댑터를 import 하지 않는다**; 기존 `src/lib/research/` 와 분리):
   - KIS 해외 일봉 **연속조회(페이지네이션)** + **USD 원값**(KRW 환산 금지) + 수정주가 모드 기록(`adj_mode`). 국내 일봉은 보유 2종목 점검용으로 같은 방식(호출당 행수는 실측해서 기록).
   - **`src/lib/exchanges/` 는 수정하지 않는다**(안전 경로). 토큰·스로틀은 앱의 기존 모듈(`kis-auth`·`kis-throttle` bulk 레인)을 **읽기 호출로만** 사용. 새 토큰을 발급하는 코드 금지(T-059 `kis-fundamentals-snapshot` 선례 참고).
   - 품질 게이트(T-064 §5.4): 통화·단위 필수, 결측·중복·역순·거래량 0 검출, 전일 대비 [0.70,1.43] 밖은 **제외가 아니라 `flags='corp_action_suspect'` 로 표시**(분할 종목을 빼는 편향 방지), 확정 봉만 `is_final=1`, **조정 기준 변경 감지**(중첩 재조회 구간 종가 불일치 → 해당 종목 전체 재수집 대상으로 표시).
3. **수동 호출 라우트** `POST /api/cron/daily-bars` (T-059 `kis-fundamentals-snapshot` 방식, `checkCronAuth`, **cron-runner 에 등록하지 않음** — 정기 증분은 Phase 1). 본문 `{symbols?, years?, maxCalls?}`; 호출당 예산(예: 100초·maxCalls 상한)으로 청크 실행·재개 가능·**멱등 upsert**. 기본 대상: 보유 5종목(최우선) → 최근 90일 시그널 종목(≤300). 장중 봉은 `is_final=0`.
4. **과거 시그널 사후검증(읽기 전용)** `scripts/profit-engine/signal-postmortem.mjs` + 리포트 `agent-vault/10-Flow/reports/T-070-signal-postmortem-<YYYYMMDD>.md`:
   - 대상: 최근 90일 만료·스킵 시그널(시장·전략별, 특히 `rsi-oversold-v1`). 같은 종목 반복 발화는 **에피소드(종목별 N일 내 최초 발화) 단위**로 센다.
   - 계산: D+1 갭·`would_fill`(진입구간 도달)·D+1/3/5/10 수익·MAE, 추세 조건(MA60·20일 수익률 5분위)별 분할, 만료 시점 상태 분해, **H-G 구조적 비실행**(시그널 금액 < 1주 가격, 시장·가격대별 분해), 비용 반영 가상 기대값(미국 왕복 0.65%·손절 0.75%, 국내 0.33%/0.43% — T-064 §6.4).
   - 환율: 시그널 가격(KRW)과 일봉(USD) 비교는 "일봉 종가 대비 시그널 가격 비율"로 역산(환율 이력 없음, T-064 §5.3).
   - 출력 끝에 **H-A~H-G 판정 표**(어느 병목이 지배적인가, 근거 수치, 확신 수준)와 `rsi-oversold` 유지/비활성 권고.
5. 분석가(Fable) 읽기 전용 자문 1회: 리포트 수치 해석·권고 검토(데이터가 쌓인 뒤 Leader 가 호출).
