# T-064 — 수익 엔진 설계

> **불변 원칙 (사용자, 2026-10-22)**: 이 프로젝트는 **수익을 내기 위해 존재**하고, 모든 것은 이에 맞춰 존재해야 한다. 이 원칙은 절대 변하거나 왜곡되어서는 안 된다. 이 문서의 모든 설계는 "비용을 뺀 실제 수익과 손실 통제"를 목적함수로 삼고, 승률·시그널 수·분석 건수·노트 품질 같은 대리 지표를 목적으로 삼지 않는다. 이 원칙을 바꾸는 것은 사용자의 명시 지시로만 가능하다.
>
> 상태: **설계안 v3 — 독립 검토(reviewer) CONDITIONAL_PASS 반영(10-22 18:4x).** 합격 기준(D4)·유니버스 정의는 R-02 반영본(§5.5·§6.6)으로만 확정한다. 이 문서는 *설계*이고 구현·DB 변경은 없다. 설계 1·2(일봉 저장소·스크리너·백테스트)의 **구현(Phase 0~)은 사용자 승인(D15)과 DB 테이블 추가 허용(D2) 뒤에** 시작한다. 이미 구현·배포된 것: 리스크 정책 화면(T-066). 구현 중: 현금 하한 정보화·분할 4회 정렬·손절가 도달 텔레그램 알림(T-068).
> 근거 표기: [확실] = 이번 세션에서 DB·코드로 직접 확인 · [가능성 높음] · [추측] · [자문] = analyst(Fable) 읽기 전용 자문의 주장(코드·문서를 직접 읽은 것만 [확실]로 승격).
>
> **사용자 확정 입력 (2026-10-22)**
> 1. 현재 자산 약 2,000만원, **미국 70% · 국내 30%**라고 함 — 스냅샷은 미국 82%·국내 15%라 차이가 있다(§7.3, 결정 D9).
> 2. **한 번에 감내할 손실 = 총자산의 2%** — 포트폴리오 동시 손실의 상한(열)으로 해석(§7.1, 결정 D11). **설정 화면의 안전장치 항목 안에 표시**하고 **손절폭·손절 합 한도를 리스크 정책에서 한 번에 설정**하면 보유 종목별 **예상 손절가가 실시간 표시**되게 같은 task 에서 함께 만든다(사용자 지시; v2 의 종목별 수동 입력은 오해여서 폐기) → [[T-066-risk-policy-settings]].
> 3. **시장 우선순위: 미국 → 국내.** 유니버스·비용·거래 시간·이벤트 데이터가 미국 기준으로 바뀐다(§5·§6.4·§7.1·§8).
> 4. **미국 매매 수수료는 매수·매도 각 0.25%**(사용자 확인). **환전은 사용자가 직접** 한다 — 거래마다 환전하지 않으므로 환전 스프레드는 매매 비용에서 뺀다(§6.4).
> 5. **미국주식 쪽에 약 200만원을 추가할 예정**(용도 확인 필요, §7.5·D12). 사용자 답변 중 "2."(손실 2% 해석)는 비어 있어 D11 은 미확인으로 둔다.

## 5. 설계 1 — 일봉 저장소

### 5.1 유니버스 (사용자 확정: 미국 우선 → 국내 후순위)
- **데이터 계층은 시장 무관**(스키마에 `market`·`currency`). 채우는 순서만 정한다.
- **Phase 0**: 현 보유 5종목 — 미국 3(MU·SMH·ORCL)+국내 2(삼성전자·SK하이닉스). 국내 2종목은 *보유 점검에만* 쓴다.
- **Phase 1 (미국)**: 기존 T-057 정적 유니버스 50 + 즐겨찾기 + 보유(≈54종목)로 파이프라인을 먼저 검증한다(**시험용** — 이 정적 50종목 `SP500_TOP50` 은 현재 시점 대형주를 하드코딩한 목록이라 합격 판정 유니버스로 쓰지 않는다, §5.5). 이 종목들은 SEC 공시·재무·실적 일정(T-059)이 이미 DB 에 있어 이벤트 트리거(§8)와 실적 블랙아웃을 바로 쓸 수 있다. **Phase 2 검증 전에 ≥150종목으로 확장**한다(합격 기준의 "기여 종목 ≥30"과 사용자의 "넓은 표본" 요구). 확장 후보 출처 두 가지 — ① 미국 상장 보통주 중 시총 상위 → 20일 평균 거래대금(ADTV) 상위 N(시총 출처 필요: T-059 `us_fundamentals_snapshot.market_cap` 은 단위 미확정) ② 대표 지수 구성 목록(공개 목록의 이용·갱신 방법 **확인 필요**). 어느 쪽이든 월 첫 거래일 스냅샷을 `universe_snapshots` 에 적립(PIT).
- 제외: ETF·ETN·레버리지/인버스 상품(SMH 같은 ETF 는 보유 점검 대상이지만 개별 종목 전략 대상은 아님; 지수 ETF 는 §13-1 코어 후보), 우선주·SPAC, 상장 1년 미만, 주가 하한 미만, **주가 상한 초과(슬롯 ÷ 7주, §7.1)**.
- **Phase 1b (국내, 후순위)**: 코스닥 보통주 시총 상위 300 → ADTV 상위 100, 매월 첫 거래일 스냅샷, 관리종목·투자주의환기·거래정지·불성실공시 제외(호가단위·주가 하한 **확인 필요**). 정의만 보존하고 미국 결과가 나온 뒤 착수한다.

### 5.2 스키마 (가산 전용·`CREATE TABLE IF NOT EXISTS`, 적용은 사용자 승인 — T-059 와 같은 방식)

```sql
CREATE TABLE IF NOT EXISTS daily_bars (
  market      VARCHAR(8)   NOT NULL,            -- 'KR' | 'US'
  symbol      VARCHAR(32)  NOT NULL,            -- 앱 심볼 ('005930', 'NAS:MU')
  trade_date  DATE         NOT NULL,            -- 거래소 현지 거래일(KR=KST, US=ET)
  open  DECIMAL(18,4) NULL, high DECIMAL(18,4) NULL, low DECIMAL(18,4) NULL,
  close DECIMAL(18,4) NOT NULL,
  volume      BIGINT       NOT NULL,
  turnover    DECIMAL(24,2) NULL,               -- 거래대금(제공될 때)
  currency    CHAR(3)      NOT NULL,            -- 'KRW' | 'USD' — 통화 혼합 방지
  adj_mode    VARCHAR(12)  NOT NULL,            -- 'adjusted' | 'raw' (KIS 수정주가 여부 기록)
  is_final    TINYINT(1)   NOT NULL DEFAULT 1,  -- 장중 봉은 0, 확정 후 갱신
  flags       VARCHAR(64)  NULL,                -- 'corp_action_suspect' 등 품질 게이트 결과
  source      VARCHAR(32)  NOT NULL,

  PRIMARY KEY (market, symbol, trade_date), KEY idx_date (trade_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS universe_snapshots (   -- 오늘부터 진짜 PIT 로 쌓는다(생존 편향 검증용)
  asof DATE NOT NULL, symbol VARCHAR(32) NOT NULL, rank_adtv INT NOT NULL,
  adtv20 DECIMAL(24,2) NULL, mcap DECIMAL(24,2) NULL, status_flags VARCHAR(64) NULL,
  PRIMARY KEY (asof, symbol)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS bar_fetch_state (      -- 증분 상태(T-059 symbol_cik_map 패턴)
  symbol VARCHAR(32) PRIMARY KEY, last_trade_date DATE NULL,
  last_attempt_at DATETIME NULL, last_error VARCHAR(255) NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
연구 결과(`research_runs`·`research_trades`)는 Phase 2 에서 같은 방식으로 추가한다. 되돌리기는 `DROP TABLE` 한 줄씩(데이터 함께 삭제).

### 5.3 수집
- **앱 안 cron 라우트**(T-059 `kis-fundamentals-snapshot` 방식)로 만들어 앱의 KIS 스로틀·토큰 캐시를 그대로 쓴다(앱 밖 스크립트는 스로틀을 공유하지 못한다). 이 세션의 빌더는 토큰을 새로 발급하지 않고 캐시만 읽었지만 상시 수집은 앱 안이 맞다.
- 미국은 정규장 마감 뒤(서머타임 중 05:00 KST, 11-01 종료 후 06:00 KST) **07:00 KST 이후**(프로젝트 선례: 해외 분석 08:00 "데이터 반영 대기", 리서치·EDGAR 07:00 — 겨울에는 06:30 이 마감 30분 뒤라 비확정 봉이 `bar_fetch_state` 를 지나쳐 전진할 위험)에 **증분** 1회(종목당 약 1호출, 최근 5거래일 중첩 재조회로 확정 봉만 인정), 국내(후순위)는 15:40 이후. 백필은 3~5년을 청크로 나눠 재개 가능하게(`bar_fetch_state`) **cron-runner 밖 일회성 수동 호출**로 한다(cron-runner 는 직렬 bash 루프라 길어지면 진입 감시가 지연되고, 스로틀 bulk 레인 용량(640)을 넘기면 실패한다). 백테스트는 앱 프로세스(pm2 단일 인스턴스·512MB)가 아니라 **오프라인 러너**로 돌린다(D19). 호출 한도는 초당 5건 공유라 낮은 우선순위 레인이 필요하다(레인이 없으면 추가 — 스로틀 코드 확인 필요).
- 용량(**미국 일봉은 호출당 100행 실측**, 국내는 확인 필요): 3년(≈756봉) = 종목당 8호출 → 54종목 432호출(0.8초 간격 약 6분), 150~200종목 1,200~1,600호출(약 16~21분). 일일 증분은 종목당 1호출. **LLM 토큰 0.**
- **신규 개발 범위(검토자 R-12)**: 현 KIS 일봉 어댑터는 연속조회가 없고 가격을 현재 환율로 KRW 환산해 돌려준다. **USD 원값 일봉 수집기와 페이지네이션은 신규 개발**이며 환율 이력(`fx_rates` 1행)이 없으므로 시그널 가격(KRW)과 일봉(USD)의 비교는 "일봉 종가 대비 시그널 가격 비율"로 환율을 역산한다.

### 5.4 데이터 품질 게이트 (코드)
1. **통화·단위**: `currency` 필수, KRW↔USD 혼합 금지(10-21 `price_change_pct_24h` 가 +262% 같은 값을 낸 사고의 교훈 — 평균 변화율이 비현실적이면 적재를 막는 이상치 검사).
2. **수정주가**: KIS 국내 일봉의 수정주가 옵션 **확인 필요**. 코스닥은 무상증자·액면분할이 잦다. 전일 대비 종가 비율이 **[0.70, 1.43] 밖**(가격제한폭 밖)이면 기업행위 의심으로 격리해 확인 전까지 백테스트에서 제외.
3. 결측·중복·역순·거래량 0 일자 검출, 종목 커버리지 ≥95%.
4. **확정봉만 신호에 사용**: 장중 봉(`is_final=0`)은 신호 계산에 쓰지 않는다.
5. KIS 수정주가는 과거 일자 종가가 웹 종가보다 낮게 보일 수 있다(이번 세션 MU 대조: -0.02~-0.17%, 배당 반영으로 보임). 같은 소스로 일관되게 쓴다.
6. **조정 기준 변경 감지(검토자 R-10)**: KIS 수정주가는 호출 시점 기준으로 과거를 재조정하므로 분할·배당 뒤에는 저장된 과거 행이 낡는다. 최근 N일 중첩 재조회에서 겹치는 구간의 종가가 달라지면 해당 종목을 전체 재수집한다. 위 2번의 ±30% 격리는 분할한 종목(대개 승자)을 백테스트에서 빼는 편향이 되므로, 격리 종목은 *재수집·조정 확인 뒤 복귀*시키고 제외 건수를 리포트한다. 가격 수준 필터($150)·달러 ADTV 는 같은 조정 기준으로 계산한다.

### 5.5 생존 편향 — 정직한 한계
KIS 종목마스터는 현재 상장 종목만 준다 [가능성 높음]. 따라서 과거 3~5년 백필 구간의 유니버스는 *생존 편향이 있는 상한값*이다. 완화: ① 오늘부터 월별 스냅샷을 진짜 PIT 로 적립 ② 백필 구간은 "현재 상장 종목 중 당시 ADTV 상위"로 구성 ③ KRX 정보데이터시스템·DART 로 과거 관리종목·상폐 이력 보강(이용약관 **확인 필요**). 합격 판정은 백필 IS 결과가 아니라 **표본 외(OOS)와 전진 페이퍼**를 근거로 한다.

**[독립 검토 R-02] 현재 시점 목록 편향 — 위 한계에 더해 한 가지가 더 있다**: Phase 1 의 54종목(`SP500_TOP50`)은 현재 시점 대형주를 하드코딩한 목록이고 확장 방식("시총 상위 → ADTV 상위")도 *현재* 시총을 쓰므로 승자 선택 편향이 있다. OOS(최근 40%)도 같은 목록으로 나누기 때문에 종목 선택에 OOS 구간 정보가 이미 들어 있다. 절대 기준(+0.40%·샤프 1.0·MDD 12%)은 이 편향을 그대로 합격률로 옮긴다. 규칙:
1. 유니버스는 IS/OOS **분할일 시점에 알 수 있던 정보**(분할일 이전 봉으로 계산한 ADTV 순위)로 고정한다. 정적 50종목 목록은 파이프라인 시험에만 쓴다.
2. IS 합격 조건에 *벤치마크 상대 조건*과 *생존편향 할인*(54종목 동일가중 보유가 지수 ETF 보유 대비 앞선 만큼)을 넣는다(§6.6).
3. 최종 근거는 전진 페이퍼로 둔다. 이 규칙이 반영되기 전에는 합격 기준(D4)을 확정하지 않는다.

## 6. 설계 2 — 코드 스크리너 + 백테스트

### 6.1 원칙: 백테스트 = 라이브 동일 코드
신호 함수는 `bars[0..D]`(D 일 종가까지)만 입력받는 **순수 함수**로 한 번만 작성하고 백테스트와 라이브가 같이 쓴다. 라이브-백테스트 괴리의 가장 흔한 원인(코드가 둘)을 구조로 없앤다.

### 6.2 구성 (`src/lib/profit-engine/`, 신규 — 기존 `src/lib/research/` 와 분리)
`indicators`(기존 지표 순수 함수 재사용) · `signals/<전략>` · `fill-model`(§6.3) · `portfolio-sim`(이벤트 기반, 슬롯·사이징·비용, 일별 평가손익 기반 MDD·샤프) · `metrics`(순기대값·PF·샤프(√252)·MDD·**날짜(주/월) 군집 블록 부트스트랩** CI — 같은 날·같은 레짐 거래는 독립이 아니며 거래 수는 에피소드 단위로 센다) · `report`(JSON+마크다운) · `registry`(전략 사전 등록·상태 REJECTED/PASSED).
기존 `backtest.ts` 는 포트폴리오 검증에 쓸 수 없다: 단일 종목 전액 올인, `STYLE_PRESETS.neutral`(undefined) 참조 [확실], 자문 코드 해석상 MDD 가 청산 시점에만 갱신되고 샤프를 거래별 수익률로 √365 연율화 [자문]. **새로 작성**하고 기존 파일은 구현 단계에서 처리(삭제 여부는 그때 결정). 기존 `src/lib/research/`(T-032~034: Yahoo 일봉·랠리 사이클·전조 규칙 lift)는 헤더 계약상 실매매와 분리된 *탐색용*이고 위 6.1 의 "라이브와 같은 신호 함수" 원칙과 맞지 않으므로 새 코드는 별도 네임스페이스에 둔다. 그 모듈의 lift·적중률은 아이디어 발굴로만 쓰고 합격은 Phase 2 검증만 인정한다. 이 모듈의 Yahoo 일봉(5년 수정주가)은 KIS 일봉의 오프라인 교차검증용으로 쓸 수 있는지 사용자 결정에 올린다(D19).

### 6.3 체결 모델 (백테스트 = 라이브 동일 규칙, [자문] 초기 제안값)

| 단계 | 규칙 |
|---|---|
| 신호 | D 일 종가 확정 후 평가 |
| 주문 | 지정가 `close_D × 1.005`(기존 `limitChasePct 0.005` 재사용), 유효기간 D+1 당일 |
| 체결 | `low_{D+1} < 지정가 - 1틱`이면 체결, 체결가 = `min(open_{D+1}, 지정가)` (닿기만 한 것은 미체결) |
| 추격 방지 | `open_{D+1} > close_D × 1.02` → 발주 안 함(로그). 갭 하락 `< ×0.97` → 발주 안 함(뉴스 리스크). 취소 종목 3거래일 쿨다운. `close_D × 1.005` 초과가는 어떤 경우에도 매수 금지 |
| 손절 | 시장가. `open_D < stop` 이면 `open × (1 - slip)`, 아니면 `low_D ≤ stop` 일 때 `stop × (1 - slip)` |
| 거래 크기 | 주문금액 ≤ ADTV20 × 0.1% 이면 전량 체결 가정, 초과하면 거래 금지 |
| 기록 | 모든 신호(체결 여부 무관)에 지정가·체결 여부·D+1/3/5/10 수익·가상 손익을 남겨 **미체결의 기회비용**을 측정 |
| 같은 날 선후(감사 보완 3) | 같은 날 진입·손절·익절 가격이 모두 닿으면 일봉만으로 순서를 모르므로 **손절 먼저**(보수)로 가정하고 *익절 먼저* 민감도를 함께 보고한다. 진입 당일 `low ≤ stop` 은 손절로 본다. 장중 신호는 D+1 DAY 지정가로만 취급 |
| 라이브와의 차이(검토자 R-10) | 라이브 체결 경로는 entry-watcher 1분 폴링이고 미국 주문은 $1 이상 정수 달러로 반올림해 송신한다(`roundToTickOverseas`). 위 모델의 "1틱"($0.01 전제)과 장 시작 전 사전 주문 가정(`min(open, 지정가)`)은 라이브와 다르므로 *민감도로 보고*하거나 라이브 규칙에 맞춘다. "백테스트=라이브 동일 규칙"(6.1)은 신호 함수에만 성립하고 체결 모델에는 성립하지 않는다 |

D+1 시초 갭 분포(유니버스 중앙값·90분위, 미국은 현지 정규장 시가 기준)를 일봉으로 먼저 실측한다([추측] 중앙값 0.5~0.8%, 90분위 2% 안팎이면 체결률 50~70%). 갭이 구간 폭을 크게 넘으면 변형 B(마감 직전 평가 → 종가 근처 매수; 해외 마감 경매 주문 지원 여부 **확인 필요**)를 같은 틀로 비교한다.

**환전 스프레드는 매매 비용에서 제외한다**: 사용자가 직접 환전하고 거래마다 환전하지 않기 때문이다. 다만 환율은 비용이 아니라 *리스크 측정과 손익 표시*에 영향을 준다(§7.5): 환전 스프레드는 돈을 넣고 뺄 때 한 번 내는 자본 이동 비용이라 전략 평가에는 넣지 않고, 환율로 인한 평가 변동은 가격 손익과 분리해서 보여 준다.

## 7. 리스크·포지션 규칙 (제약 2·3 의 수치화, 사용자 확정 대상)

### 7.1 사이징 산식 — 사용자 확정 "한 번에 감내할 손실 2%"를 열 상한으로 쓴다
- **사용자 확정(2026-10-22): 한 번에 감내할 손실 = 총자산의 2%.** 포트폴리오 전체가 *동시에* 잃을 수 있는 최대 손실(열린 포지션의 손절폭 합, "열")의 상한으로 해석한다. 총자산 2,108만원 기준 **약 421,545원**. *단일 거래*의 손실 한도 2%로 읽으면 손절 3%에서 포지션이 총자산의 67%가 되어 원칙 2("한 번에 많은 양을 매수하지 않는다")와 충돌해 채택하지 않았다. 다르게 의도했다면 정정해 주세요(D11).
- 슬롯 10을 채우는 거래당 리스크 = 2% ÷ 10 = **0.2%**(약 42,155원). 포지션 크기 = 거래당 리스크 ÷ 손절폭: 손절 3% → 약 140만원(총자산의 6.7%), 손절 2% → 약 211만원(상한 10% 적용). 손절폭이 넓을수록 포지션은 작아진다. **실행 상한과의 정합(검토자 R-03)**: 사이징 슬롯은 `min(산식, 시장 1회 상한)` 이어야 한다 — 슬롯 140만원(총자산의 6.7%)은 미국 1회 상한(해외 평가액의 6%, 약 104~119만원)보다 약 1.3배 커서 단일 주문으로는 못 내고 분할이 필요하다.
- 가용 슬롯 = `min(10, 열 상한 ÷ 거래당 리스크, 가용 현금 ÷ 슬롯 금액)`. 지금은 가용 현금이 약 57만원이라 **0~1**.
- **미국주식 주가 상한**: 수량 반올림 오차를 15% 이내로 두려면 슬롯 금액이 ≥7주 가격이어야 한다. 슬롯 140만원(약 $1,060, 환율 1,325원 가정)이면 **주가 ≤ 약 $150**. MU($900대)처럼 1주가 슬롯의 대부분인 종목은 분할·정밀 사이징이 안 되므로 전략 대상에서 제외하거나 소수점 거래(지원 여부 **확인 필요**)를 써야 한다. 이 필터는 백테스트에도 같은 구간으로 적용한다.
- 환율 위험은 손실 한도가 보는 *가격 위험*과 분리해 표시한다(원화 평가 총자산에는 포함).
- 이 값은 **설정 화면의 안전장치 항목 안**에서 읽기 전용으로 보여 주고, **손절폭 %와 손절 합 한도 %를 같은 화면(리스크 정책)에서 설정**하면 보유 종목별 예상 손절가·손절 합이 자동 계산돼 실시간 표시된다(T-066, 데모 승인 후). 이 값은 위험 계산·표시에만 쓰고 자동 매도·알림과는 연결하지 않는다. 집행은 T-064 Phase 4.

- **손절 합 계산(T-066 반영)**: 평균단가 기준 예상 손절가 = 평균단가 × (1 − 손절폭), 손절 합 = Σ(평균단가 − 예상 손절가) × 수량 = 손절폭 × 취득원가 합. 현재 보유(취득원가 합 약 2,570만원)에 손절폭 3%이면 약 77만원(총자산의 3.7%)으로 **한도 2%를 넘는다**. 한도 2%를 지키는 손절폭 상한은 약 **1.6%**이고, 이 화면은 이 역산값을 보여 준다.

### 7.2 분할·현금·한도
- **분할 매수는 최대 4회**(사용자 확정 2026-10-22). 시나리오 빌더는 이미 1~4분할을 제공한다. **집행(코드 확인 결과)**: `maxPositionsPerSymbol`(5→4, T-068 WP-B)은 *국내* 룰 엔진 경로에서 최근 24시간 동일 종목 매수 *주문* 건수만 세므로(`portfolio-stability.ts`: `market !== 'domestic'` 이면 통과, 호출자는 `engine.ts` 한 곳) 미국·시나리오 확정 경로의 분할은 막지 못한다. 그래서 T-068 WP-B 에 **확정 요청당 분할(슬라이스) 최대 4개**를 서버에서 거부하는 검증(`scenario-confirm-fields.ts`)을 추가한다. *같은 종목을 여러 날·여러 요청으로 나눠 사는 누적 분할 횟수*를 시장 무관하게 세는 게이트는 아직 없다 → 사용자 결정 D17. 분할은 가격 구간을 같은 폭으로 나눈다(`calcSplitSlices` 는 구간 폭만 나누고 확정 경로는 화면에서 넣은 구간별 수량 `manualSlices` 를 그대로 쓰므로 "구간마다 같은 금액"은 사실이 아니다). 분석가 자문은 '2트랜치'를 권했지만(분할 횟수가 많을수록 손절선과 가까운 구간에 사게 됨) 사용자 결정을 따르되 안전 규칙을 둔다: **모든 분할 구간은 예상 손절가보다 위**여야 하고 **손절선 아래 추가 매수 금지**, 한 종목의 *전체 계획 금액*으로 손절 합(2%)과 1회·일일 상한을 계산한다.
- 현금 하한은 두지 않는다(사용자 결정 — 정보 표시). 섹터(또는 60일 수익률 상관 >0.7) 집중 ≤40%·섹터당 ≤3종목, 심볼당 ≤15%(문서 30% 하향 제안).
- 주간 손익(월요일 시가 대비 실현+평가): -1.5% 신규 일 1건·1차 트랜치만 / -2.25% 신규 정지 / -3.0% 주간 정지+다음 주 노출 50% 상한+원인 분석 리포트 필수 / 월 -5% 신규 전면 정지·재검증(기존 포지션 강제 청산은 하지 않는다 — 아래 규칙과 일치시킴, Kill Switch 연동 여부는 D4) / 일 -2% 다음 날 신규 정지. **기준 자산(주·월 손실의 분모)은 정책 시작 시점의 총자산으로 명시한다** — 현재 계좌는 이미 이 한도를 넘은 상태라 기준일을 정하지 않으면 시작과 동시에 정지가 된다(검토자 R-08).
- 기존 포지션 강제 청산은 **하지 않는다**(각 포지션의 손절·사용자 결정이 담당).

### 7.4 10종목 설계의 현실 (계좌 구간별)
총자산 기준으로는 2,108만원에서 슬롯 8~10·슬롯당 140~176만원이 산식상 가능하다. 그러나 *실행 가능 슬롯은 현금이 결정*하므로 지금은 0~1이다. 월 기대 수익은 보수적으로 **월 +1~2%(순)·MDD -10%** 안팎이 일봉 스윙의 현실적 범위라는 *설명용 추측*(근거 문헌 미확인, 합격 기준으로 쓰지 않는다 — 감사 보완 6)이고 문서의 "월 +5~10%"는 이 설계로 달성하기 어렵다 [추측, 문서 §1 수정은 사용자 결정]. 2,108만원 기준 월 +1%는 약 21만원이다. **현실적 기여 규모(검토자 R-06)**: 자유 현금이 0~1슬롯이면 합격선을 넘는 전략도 월 약 1.7% × 투입 현금(수만 원 단위)이라 지금 계좌 손익은 보유 집중이 지배한다(§0-8).

### 7.5 추가 자금 약 200만원과 환율의 영향 (사용자 입력, 2026-10-22)

> **사용자 결정(2026-10-22): 현금 하한은 규칙으로 두지 않는다**(권고대로 — 현금 비중은 정보로만 표시). 따라서 아래 '현금 하한 10% → 투자 가능 약 26만원' 계산은 *정책을 새로 집행한다고 가정한 시나리오*였고 채택되지 않았다. 실제 제약은 §7.6 의 1회·일일 상한과 실시간 잔고다.

**추가 자금**: 입금 후 총자산 약 2,308만원, 현금(원화+USD 환산)은 약 57만원 → **약 257만원(11.1%)**. 문서 정책의 현금 하한 10%(약 231만원)를 지키면 **신규 매수에 쓸 수 있는 돈은 약 26만원뿐**이다 — 200만원은 *현금 완충을 복원*할 뿐 신규 포지션 재원이 되지 못한다.

| 현금 하한 | **없음(사용자 결정 2026-10-22).** 문서(`trading-strategy.md` §5)에만 있던 10% 는 폐기하고 현금 비중은 정보로만 표시한다 | **확정** |
|---|---|---|
| 10% (문서 정책) | 약 231만원 | 약 26만원 |
| 7.5% | 약 173만원 | 약 84만원 |
| 5% | 약 115만원 | 약 141만원 (슬롯 140만원 1개분) |

따라서 *200만원을 새 전략의 재원으로 쓰려면* 현금 하한을 낮추는 사용자 결정이 필요하다(D12). 200만원을 기존 보유 종목 추가 매수에 쓸 계획이면 집중(§7.3)이 더 커질 수 있어 용도를 먼저 알려 달라. 이 자금이 들어와도 초기 가용 슬롯은 0~1이다.

**환율이 설계에 미치는 영향 (질문: "환전은 내가 직접 하는데 영향이 있나?")**

| 영역 | 영향 | 설계 반영 |
|---|---|---|
| 매매 비용 | **없음** — 거래마다 환전하지 않는다 | §6.4 에서 제외 |
| 매수 가능 금액 | **있음** — 미국 주식은 **USD 예수금**으로만 산다. 원화로 넣어 두면 시스템이 쓸 수 없다(T-058 게이트가 USD 기준) | 가용 재원 = USD 예수금. 원화 예수금은 "환전 필요"로 표시. 환전 시점·금액은 사용자가 정한다 |
| 손실 한도 측정 | **있음** — 미국 보유 평가액 약 1,730만원 × 환율 1% = 약 17.3만원 ≈ 2% 한도(약 42만원)의 **41%**. 가격이 그대로여도 환율만으로 한도의 절반 가까이 움직인다 | 2% 한도는 **USD 가격 위험**(손절폭 합)에 적용하고, 환차손익은 따로 표시한다 |

| 전략 검증 | 없음 — 백테스트는 USD 가격으로 한다 | — |

### 7.6 매수 시그널 생성 흐름 (사용자 정의, 2026-10-22)

> 사용자 설명: "종목 매수 시그널을 만들 때 현재 계좌 잔고를 기준으로 설정의 한 번에 투자할 수 있는 상한선을 확인해 분할 여부를 판단하고, 분할하면 분할 금액에 따라 시그널을 생성한다. 예: AAPL 매수 시그널을 만들 때 현재 잔고를 확인하고 매수 상한선이 잔고에 만족하면 분석가가 판단 에이전트와 분할 매수 여부를 검토해 매수 시그널을 생성한다."

| 단계 | 현재 코드(2026-10-22 확인) | 상태 |
|---|---|---|
| ① 현재 잔고 확인 | T-058 시그널 현금 게이트 — 시그널 생성 시점의 실시간 현금(미국은 USD 예수금) | **있음(집행 중)** |

| 현금 하한 | **문서(`trading-strategy.md` §5)에만 있고 코드로 집행하지 않는다.** 사용자 흐름에도 없다 | 사용자 결정(D12) |

| 층 | 주기 | 역할 |

- **기존 코드 결함 2건(구현 때 고친다)**: (a) `exit-engine` 기본값에서 목표 익절 2.5%가 트레일링 활성 2.5%와 같고 우선순위상 먼저 평가되어 트레일링이 사실상 작동하지 않는다 [자문 해석 — 기본값 2.5/2.5 는 [확실], 우선순위는 구현 때 재검증]. (b) 문서(스윙 손절 -3%·익절 +6%) 와 코드(손절 1.5%·목표 2.5%)가 다르다 [자문, 문서 §2 재확인 필요].
- `position_state` 는 평균가·고점·수량만 있어 트랜치별 진입가·진입일 귀속이 안 된다 → 트랜치 기록 필요(후속).
